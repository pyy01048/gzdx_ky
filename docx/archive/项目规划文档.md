## 1. 项目概述

### 1.1 定位
面向个人考研备考的**一站式本地离线学习平台**，覆盖目标管理、任务打卡、刷题、错题本、记忆卡片、番茄钟、课表、学习笔记、AI 助手、网盘联动、文档知识库（RAG）等全流程功能。前端 + 后端 + 数据库单机自洽，零外部服务依赖即可运行。

### 1.2 核心诉求（设计约束）
| 诉求 | 落地方案 |
| --- | --- |
| 本地离线优先 | 全部业务数据存于本地 SQLite（`backend-main-fastapi/data/kaoyan.db`），页面与 API 由单端口 8000 提供 |
| 本地 GPU 推理 | AI 层预留统一服务商封装，支持接入本地推理端点（详见 §9 演进规划） |
| 数据不出网 | 知识库（442 文档 / 5164 分块 / 845 知识点 / 4670 SFT 样例）完全本地存储与检索 |
| 真实数据不虚假 | 业务数据以 FastAPI 数据库为准，前端挂载时后端优先回填，杜绝"演示假数据" |

### 1.3 总体规模
- 后端 API：**60+ 个**（routers/ 下 12 个路由模块）
- 数据库表：**18 张**，当前已入库 442 篇文档、5164 条知识分块、4670 条 SFT 样例、845 条知识点
- 前端页面：**12 个**（懒加载路由），已构建到 `dist/` 并复制进后端 `static/`

┌──────────────────────────────▼──────────────────────────────┐

│  ├─ static/  前端构建产物（index.html + assets/）              │
│  ├─ routers/ 12 个 API 路由模块（业务接口）                    │
│  ├─ services/ AI 统一封装 / RAG / 文档解析 / OCR / 网盘 / 调度  │
│  ├─ models.py + database.py  ORM 与 SQLite 会话               │

                               │ SQLite

### 2.2 技术栈
| 层级 | 技术 | 说明 |
| --- | --- | --- |

## 6. 数据流

### 6.1 常规业务数据流
```
前端页面 → src/api/client.js（/api 代理）→ FastAPI routers → services → SQLite
前端状态：Zustand store ← 挂载时 hydrate() 从后端拉取真实数据回填（后端优先）
写操作：页面 action 调用 client → 后端落库（fire-and-forget）
```

### 6.2 AI + RAG 数据流（防瞎编）
```
用户提问
  → /api/ai/chat/stream（SSE）
  → ai_service.chat_stream：优先本地 RAG 检索
       ├─ knowledge_chunks（5164 分块，学科可过滤）
       ├─ knowledge_points（845 知识点）
       └─ documents（文档段落）
  → 命中片段拼入上下文 → 调 AI 服务商 → 流式回传前端
  → 答案基于本地知识库，标注来源，避免幻觉
```

### 6.3 文档入库流（脚本一次性导入）
```
训练产物（kb_chunks 5164 / processed 442 txt / sft 4670）
  → scripts/import_kb_data.py（8 学科分类）
  → SQLite：documents + knowledge_chunks + sft_examples
  → scripts/fill_knowledge_points.py → knowledge_points（845）
```

## 8. 本地部署与一键启动

### 8.1 环境要求
- Python 3.10+（依赖：fastapi / uvicorn / sqlalchemy / pydantic / httpx / python-docx / python-pptx / pypdf / pdfplumber / rapidocr-onnxruntime / onnxruntime / APScheduler / python-dotenv 等，见 `backend-main-fastapi/requirements.txt`）
- Node.js 18+（仅**需要重新构建前端**时需要；随包已含构建产物 `static/`，普通运行无需 Node）
- 浏览器（Chrome / Edge 等）

### 8.2 一键启动（推荐）
**方式 A：双击 `start.bat`**（Windows）
1. 首次运行自动 `pip install -r requirements.txt`
2. 自动启动后端 `python -m uvicorn main:app --host 127.0.0.1 --port 8000`
3. 自动打开浏览器访问 http://127.0.0.1:8000

**方式 B：PowerShell**：右键 `start.ps1` → 使用 PowerShell 运行（策略受限时先 `Set-ExecutionPolicy -Scope Process Bypass`）

**方式 C：手动启动**
```bash
cd backend-main-fastapi
pip install -r requirements.txt
python -m uvicorn main:app --host 127.0.0.1 --port 8000
# 浏览器打开 http://127.0.0.1:8000
```

### 8.3 启动验证
- 访问 http://127.0.0.1:8000 → 返回页面（含 `#root`，HTTP 200）
- 访问 http://127.0.0.1:8000/api/health → `{"status":"ok","service":"kaoyan-backend"}`
- 首次启动时 `main.py` 会在数据库为空时自动写入示例数据（目标/任务/题目/院校等），正常功能数据由前端挂载时从后端真实拉取

### 8.4 前端重新构建（可选）
仅当修改前端源码后需要，普通分发运行无需执行：
```bash
cd frontend
npm install
npm run build
# 将 dist/ 内容复制到 backend-main-fastapi/static/（保留 assets/ 层级）
```

### 8.5 安全说明
- 默认监听 `127.0.0.1`，不对外暴露
- 可选在 `.env` 配置 `APP_API_TOKEN` 启用 API Token 认证
- 百度网盘凭证已在 `.env` 提供（随包分发，如需公开分享请自行更换/移除）

## 9. 后续演进规划

### 9.1 GPU 本地推理接入（符合"本地离线 + 本地 GPU"诉求）
当前 AI 层为**多服务商 OpenAI 兼容封装**，天然可接入本地推理端点：
1. **方案 A（零代码，推荐）**：在「设置 → AI 服务」新增服务商，Base URL 填本地推理服务地址（如 `http://127.0.0.1:11434/v1` 指向 Ollama，或 LM Studio / vLLM 的 OpenAI 兼容端点），填入本地模型名与任意 apiKey 占位，即可在 RAG 检索基础上使用本地模型，数据完全不出网。
2. **方案 B（Ollama）**：安装 Ollama → `ollama pull qwen2.5:14b` → 配置 `http://127.0.0.1:11434/v1` + 模型名 `qwen2.5:14b`。
3. **方案 C（vLLM / llama.cpp）**：启动 OpenAI 兼容服务后，同样以自定义服务商接入。
- RAG 检索本身已完全本地（无外部向量模型），本地推理接入后整条链路（知识库 → 检索 → 生成）全部离线。
- 后端 `ai_service.py` 已支持 `provider_override`，前端直传本地端点即可，无需重启服务。

### 9.2 功能演进
| 优先级 | 方向 | 说明 |
| --- | --- | --- |
| P1 | 本地嵌入向量检索 | 引入本地嵌入模型（如 bge-small-zh）替换 TF 词频打分，提升 RAG 精度，仍离线 |
| P1 | 背诵音频 / 错题导出 | Anki 导出、单词音频 |
| P2 | 计时模考 | 定时模考 + 自动判分统计 |
| P2 | AI 作文批改增强 | 接入本地大模型批改 |
| P2 | 开放 API | 对外提供只读统计接口 |
| P3 | PWA 三端 | 已具备基础响应式，可加离线缓存（Service Worker） |

### 9.3 工程化演进
- 数据库迁移工具（当前用 `migrate.py` + `Base.metadata.create_all`，可升级为 Alembic）
- 日志集中化（当前 print + logging）
- 备份策略：SQLite 单文件，建议定期复制 `kaoyan.db` 即完成全量备份
