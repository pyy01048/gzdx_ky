## 一、融合概述

采用**方案A：以 kaoyan-study-platform 为新底座，D:\学习平台 为补强**的融合策略。

### 为什么选这个方案

| 维度 | kaoyan-study-platform（底座） | D:\学习平台（补强） |
|------|-------------------------------|---------------------|
| 前端栈 | React 18 + JSX + Zustand | Vue 3 + TypeScript + Pinia |
| 数据库 | 18张表，**5164条真实知识分块** | 20+表，空库 |
| AI检索 | TF词频（精度低） | **FTS5+向量混合检索（精度高）** |
| 本地模型 | 无 | **完整LoRA训练链路** |
| 启动体验 | ✅ start.bat一键启动 | 双cmd窗口 |
| 设置页 | ✅ 有AI服务商添加入口 | ❌ 无（P0 Bug） |

**结论**：底座有真实数据和完整体验，补强有先进AI架构。将补强的AI检索能力移植到底座，保留底座的数据和体验，是最优解。

## 三、已完成的融合工作

### 3.1 核心：FTS5 + 向量混合检索移植（★最重要）

**问题**：底座原RAG用TF词频打分，检索精度低，5164条知识分块无法有效利用。

**解决方案**：移植D:\学习平台的混合检索架构，重写为适配SQLAlchemy的版本。

**新增文件**：
- `services/search_service.py`（9.2KB）：FTS5 BM25 + 向量KNN + RRF融合
- `services/embedding_service.py`（7.6KB）：在线API生成embedding向量

**修改文件**：
- `services/ai_service.py`：重写`search_knowledge_base`方法，新增`search_knowledge_base_hybrid`异步方法
- `routers/ai.py`：`_rag_system_prompt`改为异步，优先使用混合检索；新增3个索引管理API

**检索架构**：
```
用户查询
    ├── FTS5通道（jieba分词 + BM25打分）──┐
    └── 向量通道（在线embedding + KNN）─────┼── RRF融合(k=60) ──> 排序结果
                                              ┘
```

**验证结果**：直接调用`hybrid_search("施密特触发器")`返回5条精准结果，均来自数字电子技术学科的真实文档。

### 3.2 底座数据保留

完整保留底座的真实数据：
- 442篇文档（8学科分类）
- 5164条知识分块（RAG主数据源）
- 845条知识点
- 4670条SFT训练样例
- 3家AI服务商配置（豆包/DeepSeek/通义千问）
- 6家平台配置（百度网盘已connected）
- 4条自定义导航链接

### 3.3 补强文件归档

将D:\学习平台的14个核心服务、设计系统、前端样式归档到`_legacy/`，作为Phase 2移植的参考。

### 3.4 依赖更新

`requirements.txt`新增：
- `numpy>=1.24.0`（向量计算）
- `jieba>=0.42.1`（中文分词）

## 五、如何启动

### 方式一：一键启动（推荐）

```bash
双击 D:\平台\start.bat
```

脚本自动完成：
1. 检查Python环境
2. 安装依赖（含新增的numpy/jieba）
3. 启动后端服务（http://127.0.0.1:8000）
4. 自动打开浏览器

### 方式二：手动启动

```bash
cd D:\平台\backend-main-fastapi
pip install -r requirements.txt
python -m uvicorn main:app --host 127.0.0.1 --port 8000
# 浏览器打开 http://127.0.0.1:8000
```

### 首次启动后建议

1. **构建FTS索引**：首次调用`/api/ai/rag-search`会自动建立FTS索引（5164条，约2-3秒）
2. **构建向量索引**：调用`POST /api/ai/build-embeddings`，通过在线API生成5164条分块的向量（约5-10分钟，需配置AI服务商API Key）
3. **配置AI服务商**：进入「设置 → AI服务」，添加豆包/DeepSeek/通义千问的API Key

## 九、注意事项

1. **端口冲突**：如果8000端口被占用，修改`start.bat`中的端口号，或关闭占用进程
2. **向量索引构建**：需要先配置AI服务商API Key，才能调用在线embedding接口
3. **OCR功能**：底座已集成RapidOCR，但`rapidocr-onnxruntime`在Python 3.13上可能需要手动安装
4. **前端重新构建**：修改前端源码后需执行`npm run build`，将dist复制到`backend-main-fastapi/static/`
5. **数据备份**：数据库为单文件`backend-main-fastapi/data/kaoyan.db`，复制即可全量备份
