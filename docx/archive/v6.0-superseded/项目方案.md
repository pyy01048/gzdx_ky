## 一、这一版改了什么（以及为什么）

上一版的问题不是"功能不够"，而是**功能太多、数据不可用**。体检结论如下：

| 模块 | 上一版实际状态（数据库实测） | 本版处置 |
| :--- | :--- | :--- |
| **课表** | `semesters` / `courses` / `course_adjustments` **三张表全 0 行**，却占了 15KB 路由 + 49KB 页面 + 8 处导航引用 | **整体删除**（已归档源码），三张空表 DROP |
| **知识点** | 898 条自动抽取产物，**631 条是垃圾**（幻灯片标题拼接 / OCR 断句残片 / "下页总目录推出下页"这类页面导航文字） | **重建为 206 条真考点**，旧数据归档 JSON |
| **章节维度** | `chapter` 字段里存的是**文件名和考卷名**（"《数字电路》考研复习参考共383页"），185 个数电章节名里只有 4 个是标准章名 | 重建为**标准章名**，结构率 100% |
| **题库** | 只有 **7 道**题；而真实真题正文一直躺在 `documents.content` 里当纯文本 | **抽出 1869 道真题**入库，85% 自动归章 |
| **错题本** | 与知识库**零关联**，AI 分析出的考点只写进一段文本，无法反查 | 新建 `error_knowledge_links`，**收录即挂考点** |
| **复习进度** | `mastery` 字段存在但**无任何写入路径**（死字段） | 新建 `review_records` + SM-2 变体调度，掌握度真正落库 |

**一句话**：从"能检索但不能用"变成"章节→知识点→题型三级结构 + 真实题库 + 可追踪进度"。

## 二、四级结构：从资料到考点

这是整个系统的骨架。上一版只有 `subject`（科目）一个维度，AI 检索时无法限定范围，
也回答不了"这一章考过哪些题型"。

```
科目 (subject)
  └── 章节 (chapter)            大纲为标准骨架，未录入资料的章也显示为空白节点
        └── 知识点 (knowledge_point)   带 掌握度 / 考频 / 难度 / 题量
              └── 题型 (question_types)  选择·填空·计算·分析·设计·画图…
```

## 三、四件套的关键实现

### 3.1 扫描版真题 OCR

**问题**：贵大 834 真题、空白版真题卷大多是**扫描件**，没有文本层，直接上传进知识库会是一堆空内容。

**实现**（`services/document_parser.py`）：

```
PDF 上传
  → pypdf 提取文本层
  → 文本 < 50 字 ⇒ 判定为扫描件
  → pypdfium2 逐页渲染成图（scale=2.0）→ 本地 OCR 逐页识别
  → 结果带 "--- 第N页(OCR) ---" 标记，可追溯哪些内容来自 OCR
  → 写库时在 documents 上打 ocr_used / structure_level='ocr' 标记
```

- **OCR 引擎**：本地 RapidOCR（PP-OCRv4 ONNX）。可选接入 `backend-ocr-paddle`（PP-OCRv5 微服务，端口 8888），不可用时**自动回退**本地引擎。
- **为什么要标记**：OCR 文本有识别噪声，检索命中 OCR 内容时需要区别对待（前端可筛选、可信度可降权）。
- **不出的网**：整条链路本地完成，题图不出本机。
- **依赖自检**：`python tests/check_ocr_deps.py` 会逐项报告链路依赖是否齐备。

> **环境实测提醒**：在 Python 3.13 上，`requirements.txt` 里锁定的
> `rapidocr-onnxruntime==1.3.24` 与 `onnxruntime==1.17.3` **装不上**（无对应 wheel）。
> 实测可用组合为 `rapidocr-onnxruntime 1.2.3` + 环境已有的 `onnxruntime 1.29`。
> `jieba` 是纯 Python 包可正常安装，但**若缺失会静默退化为 2-gram 分词**，
> 检索质量下降且不报错 —— 建议装好后用 `python tests/check_ocr_deps.py` 确认。

> 实测存量 1545 篇资料中 `ocr_documents = 0`，因为历次入库都是直接读文本层文献；
> 你上传扫描件真题时才会触发，标记会实时写入。

### 3.2 「章节→知识点→题型」结构化组织

**三个数据源，按可信度排序**（`services/kp_builder.py`）：

1. **834 考纲正文** —— 最权威。考纲原文"掌握逻辑函数的代数化简方法及卡诺图化简方法"直接转成考点，
   并保留 `【考纲要求·掌握】` 标注与难度分（了解=2 / 理解=3 / 掌握=4）。实测解析出 **30 条**。
2. **章节化教材** —— 文件名形如「第3章 门电路.pdf」的资料，章名即知识点。实测 **84 条**。
3. **真实真题** —— 1862 道题反推考点，考频由实际题量决定。实测 **168 条**。

去重合并后 **206 条**，100% 有章节、100% 有题型。

**章节归位算法**（`services/kp_cleaner.py`）：
- 先看现有 chapter 是否已是标准章名；再从"第N章"里的章号对齐大纲
- 否则用**分章关键词表**打分（知识点名权重 ×3、章节字段 ×2、正文 ×1，只取正文前 2000 字防长文压制）
- **宁可空着也不塞错章节** —— 归位错误会直接污染进度统计

> 关键词表设计要点：长关键词权重更高，避免「门电路」被「电路」抢占；
> 该表是按数电/模电/数二/英二/政治逐科整理的，不是通用词表。

### 3.3 错题本 ↔ 知识库联动

**问题**：上一版 AI 分析出的考点只落在 `analysis` 一段文本里，**无法反查、无法统计**。

**实现**（`services/error_linker.py` + 表 `error_knowledge_links`）：

收录错题时**自动挂考点**，逐级降级、宁缺勿错：

| 级别 | 依据 | source 标记 |
| :--- | :--- | :--- |
| 1 | **名称直击**：知识点名直接出现在错题正文里（"JK触发器"出现在题干 → 挂 JK触发器） | `name_match` |
| 2 | **章节内检索**：先判定错题所属章节，只在该章内混合检索 | `chapter_match` |
| 3 | **全局检索**：仅当字面重合度 ≥ 0.6 才采纳 | `search_match` |
| 4 | 都不成立 ⇒ **不挂**，留给用户手动指定 | — |

> 为什么第 4 级是"放弃"而不是"兜底随便挂"：早期版本会把"触发器时钟沿"的错题挂到
> "卡诺图化简"上（相关度 0.016），因为检索总能返回点什么。挂错的考点会让
> "薄弱考点"统计彻底失真，所以改成宁可不挂。

**双向可查**：
- 错题 → 考点：`GET /api/errors/{id}/knowledge-points`
- 考点 → 错题：`GET /api/taxonomy/knowledge-points/{id}`（含 `related_errors`）
- **薄弱考点评分**：`GET /api/review/weak-points` = 错题数×2 + 考频 − 掌握度/20
  —— 这就是"我最近错得最多的知识点是哪些"的直接答案

### 3.4 复习进度追踪

**问题**：`knowledge_points.mastery` 是**死字段**，没有任何代码写入它。

**实现**（`services/review_service.py` + 表 `review_records`）：

- **每次复习留痕**：对象类型、结果、复习前后掌握度、间隔、用时、下次时间
- **SM-2 变体调度**：评分 0-5 → 更新 ease factor（下限 1.3）→ 计算下次间隔（上限 60 天）
- **掌握度衰减**：距上次复习每超过 1 天扣 1.2 分（模拟遗忘）
- **三档结果**：`forgotten`（忘了，−15，间隔重置）/ `fuzzy`（模糊，+5）/ `mastered`（掌握，+12）
- **今日队列口径**：逾期 + 从未排期 + 从未复习三类都进队列，否则新库建成后队列永远是 0 条
- **`due_count` 与"新知识点"分离统计** —— 新知识点单独用 `new_count`，
  否则 206 个新考点会让"到期"这个指标恒等于总数，失去意义

**进度总览** `GET /api/review/progress` 给出：掌握率、复习完成率、分科目统计、薄弱章节 TOP15、薄弱知识点 TOP10、近 7 天复习量。

## 五、架构

```
浏览器（电脑 / 平板 / 手机）
  React 18 + Vite 5 + Zustand + React Router，HashRouter
        │  单端口 8000：静态托管 + /api
        ▼
FastAPI 后端（backend-main-fastapi，唯一服务）
  ├─ routers/     19 个路由模块
  ├─ services/    业务服务层（taxonomy / structure_parser / kp_cleaner /
  │                kp_builder / qbank_builder / error_linker / review_service
  │                / kb_service / search_service / ocr_service / document_parser）
  ├─ scripts/     迁移与重建脚本
  ├─ static/      前端构建产物
  └─ APScheduler  复习提醒 08:30 / 网盘同步每小时
        │
        ▼
SQLite 单文件 data/kaoyan.db（29 张业务表 + FTS5 全文索引表）
```

**可选外部服务**：
- `backend-ocr-paddle`（端口 8888，PP-OCRv5）—— 不启动则自动用本地 RapidOCR
- Ollama / LM Studio / vLLM（本地推理）或 DeepSeek 等云端 API —— 在设置页配置

### 检索架构（FTS5 混合检索）

```
用户提问
  ├─ FTS5 通道（jieba 分词 + BM25）      ─┐
  ├─ 向量通道（embedding + KNN）          ─┼─ RRF 融合(k=60) → 重排 → 上下文
  └─ 知识点 / 文档 通道                   ─┘
        ↓
  命中片段拼入 prompt → AI 生成 → 流式回传 + 标注来源
```

## 七、接口速查（本次新增）

### 知识结构 `/api/taxonomy`

| 方法 | 路径 | 说明 |
| :--- | :--- | :--- |
| GET | `/subjects` | 科目清单（主线 + 拓展）+ 章节大纲 + 题型池 |
| GET | `/tree` | 三级结构树（含掌握度、题量、章节覆盖） |
| GET | `/knowledge-points` | 知识点列表（科目/章节/题型/关键词/薄弱 筛选） |
| GET | `/knowledge-points/{id}` | 详情：含关联错题、关联分块、复习历史 |

| GET | `/coverage` | 结构化覆盖体检（哪些科目/章节还没结构化） |

| 方法 | 路径 | 说明 |
