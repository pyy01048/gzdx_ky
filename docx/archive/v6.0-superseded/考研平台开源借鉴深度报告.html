核心结论（8 条）

  1. 底座已远超同类开源项目。平台 19 路由 / 35 服务 / 独立 PaddleOCR 服务 / LoRA 微调链路 / BM25+向量+RRF 混合检索，已显著强于 408-ai-tutor、kaoyan-assistant 等调研对象；差距不在功能数量，而在题目结构化程度与题库答案覆盖率（真题有答案仅 15%）。
  2. 最该抄的"内核"是 MathLens 的 8 步结构化解题管线。它本质是 Cursor Agent Skill（不是 Web 服务），真正可迁移的是"已知条件→推导事实→图形→结论"四段式 CoT 契约 + 生成-校验交替回路，应剥离其 Manim/TTS 外壳，做成平台 ai_router 的解题 Agent。
  3. 题目数据模型应合并三家之长。ESQ 的稳定键（paperKey/unitKey/questionKey + contentHash）解决题库迭代；kaoyan-study 的 option 级 analysis（逐干扰项解析）+ difficulty 1-5；408-ai-tutor 的 answer_candidate.confidence（AI 答案高置信才计分）。三者合并即平台 qbank 目标 schema。
  4. 复习调度应从"对/错"二档升级为 SM-2 四档。errbook 的 AGAIN/HARD/GOOD/EASY + easeFactor(2.5→[1.3,3.0]) 已在 Next.js+Prisma 生产验证；现有 ebbinghaus_items 表需扩 ease_factor/interval/repetitions/next_review_date 四字段。
  5. RAG 层最高 ROI 增量是"检索门控"，不是再加向量。edu-rag 实证阈值（simple top1≥0.60 且候选≥0.50；complex ≥0.45/0.35）+ CrossEncoder 重排 + CRAG 重试 + 拒答，直接压幻觉；现有 25152 chunks 不必推倒，只加 rerank 节点。
  6. OCR 公式链路是最大硬缺口。8 个 OCR 仓库里只有 chineseocr_lite 是真本地轻量（ONNX CPU），公式→LaTeX 无现成本地方案；应保留 PaddleOCR 做版面切分，公式小图走 pix2tex/LaTeX-OCR（ONNX INT8），MathFormula2Tex 的云端 VLM 仅借其 prompt 骨架。
  7. 择校数据库与"规划中心"是开源生态的集体空白。for-Graduate_student 只给静态常识、无分数线库；cskaoyan 文件树即院校字典种子；cocos56 招生爬虫证明"拟招生不含推免"是建模红线。本平台可凭已有 planner/analytics 一次性闭环。
  8. 三套系统必须整合而非并存。D:\平台（FastAPI 主后端）、D:\kaoyan_ai（Qwen2.5-1.5B+LoRA，5164 块）、D:\真题（2712 题答疑引擎，端口 8765）各有数据库与模型，应统一到一个 FastAPI 主进程：kaoyan_ai 的 LoRA 走 Ollama GGUF、真题 qa_engine 作为 /api/qa 路由挂载，数据归并到同一 SQLite。

2.7 三套系统割裂问题与整合原则

割裂现状：三套系统各有数据库（主 SQLite / kaoyan_ai 语料目录 / 真题 JSON）、各有模型（Ollama / Qwen2.5-1.5B / 真题 qa_engine）、各有端口（FastAPI 主 / 8765 真题 / 8888 OCR），用户在三者间手动切换。
整合原则 1

统一进程：以 D:\平台\backend-main-fastapi 为主进程，把 D:\真题 的 api_server.py 作为子路由挂载（/api/qa/papers/*），OCR 8888 保持独立服务（GPU 隔离合理）。

整合原则 2

统一模型路由：kaoyan_ai 的 LoRA 经 Modelfile 合并后转 GGUF（Q4_K_M），由 ollama_service 统一调用；model_gateway 按任务类型分流（答疑走本地 LoRA、解题走 qwen3:8b、兜底云端 DeepSeek）。

整合原则 3

统一题库：D:\真题的 2712 题按 ESQ schema 清洗后导入 quiz_questions，与现有 1869 题按 text_hash 去重；真题 qa_engine 仅作"检索+规则"快路，不再独立判分。

整合原则 4

语料归一：kaoyan_ai 的 5164 块与主平台 25152 chunks 去重合并；subject/chapter metadata 统一由 kb_pipeline 打标，不保留两套索引。

2.8 已识别短板（按优先级）

  1. 题库答案覆盖率仅 15%（1869 题 / 293 有答案）——直接限制刷题模式可用性，须优先用 AI 生题（带置信度门）补全。
  2. taxonomy 仅 206 知识点（只数电模电）——英语/政治/数学/408 章节树全缺，KbMap 与组卷无知识维度可依。
  3. 公式→LaTeX 通道缺失——数学/电路计算题无法结构化，qbank 只能存 Unicode 简单符号。
  4. RAG 无门控——幻觉无硬约束，Assistant 回答可信度不可控。
  5. 复习调度停留在离散间隔——未用 SM-2/FSRS，记忆衰减建模粗糙。
  6. 无择校数据库——universities 表存在但无分数线/招生名额逐年，规划中心无法做择校决策。
  7. 无智能组卷——quiz 只能顺序刷，无双向细目表、无答题卡、无导出打印。
