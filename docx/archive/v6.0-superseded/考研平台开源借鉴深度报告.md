### 1.3 三个反直觉实证发现（必须先纠正预期）
1. **叫 "OJ" / "coding" 的仓库都不是在线判题系统**：`momo-yuan/kaoyan-cs-coding`、`XBearH/kaoyan-oj` 实为个人 C++ 代码存档，**本批 85 仓无一个提供真正的 OJ 判题链路**（编译沙箱+用例比对）。编程题须自建。
2. **"分数线数据库"不存在**：`kerlyyy/postgraduate_exam_grade` 是研招网成绩页**前端模拟器**、`1161967580/gaokao` 是**考研倒计时单 HTML**——均非数据源。择校库须自建字段并人工/爬虫补录。
3. **公式→LaTeX 的"本地轻量模型"本批没有现成仓**：`YunXi-Zhu0/MathFormula2Tex` 工程骨架可抄，但底层是**云端 Qwen-VL**（违反不出网）；`DayBreak-u/chineseocr_lite` 只做中文行文本、不做公式。公式段需自接 pix2tex/LaTeX-OCR（ONNX）或量化本地 VLM。

#### A1 ★ WangRongsheng/for-Graduate_student —— 考研全流程通识手册（信息架构母本）
- **URL**：https://github.com/WangRongsheng/for-Graduate_student ；README：https://raw.githubusercontent.com/WangRongsheng/for-Graduate_student/master/README.md
- **技术栈**：纯 Markdown + 图片（GitHub Pages 静态站），无后端/DB/前端框架。
- **核心功能**：一篇"考研全流程通识长文"，8 大板块：①是否考研（按大一大二/大三/大四/毕业分流）②基本常识（科目/分数/报名考试时间/国家线·院校线·单科线/英一英二/数一数二数三/408）③区别对比（专硕vs学硕、英一vs英二、数一二三、408vs自命题，全用 Markdown 表）④全年时间线（5 节点+18 逐月节点，每条带"提醒"）⑤初试择校与备考 ⑥临场操作 ⑦复试与调剂 ⑧资源导航（13 网站+公众号+APP）。
- **数据格式**：无结构化数据文件，全在单 README；可视为 schema 的是二级标题清单 + 内嵌对比表（`|维度|专硕|学硕|`）+ 时间线三元组（时间段+事件+提醒）。
- **可借鉴点**：8 板块链路直接作"考研规划中心"左侧导航一级目录；对比表抽成 `comparison_table` JSON 做交互对比器；18 节点抽成 `milestone(title, date_window, action_tip)`；择校维度=自身3因素+学校4因素。
- **映射**：Planner 升级为"考研规划中心"；对比表→taxonomy/subject_config；时间线→planner+tasks。

## 四、MathLens 式全科目 7 步分析管线与分科目适配

### 4.1 从 MathLens 8 步到平台 7 步（剥离视频外壳）
MathLens 真正可推广的是"结构化分析契约 + 生成-校验交替"，视频/TTS 只是可插拔展示层。剥离后抽象为与科目无关的 **7 步管线**：

| 步 | 动作 | 输入→输出 | 性质 | 借鉴来源 |
|---|---|---|---|---|
| 1 输入接入 | 拍照(走 PaddleOCR/公式段) 或文本粘贴；先过 pictureVerification 规格闸门 | 图/文本 → 干净原文 | 程序化 | E3/E4/B1 |
| 2 结构化 | 抽 `题干要素/已知条件/待求结论/题型/选项/材料` | 原文 → structure JSON | LLM（四段式契约） | B1 第①段式 + C7 四段式 |
| 3 分步解题 CoT | `第1步…第2步…结论…`，每步挂知识点标签 | structure → 推导链 + knowledge_tag[] | LLM | B1/B10 |
| 4 校验回路 | 确定性校验：字段非空/选项数/答案存在/解析覆盖结论/公式 LaTeX 闭合；不合格回退 | 推导链 → pass/fix | **程序化** | B1 check.py/C2 confidence |
| 5 归因入库 | 章/小节/难度(1-5)/来源/年份写库，关联 taxonomy，易错点入 error_linker | 通过产物 → DB 行 | 程序化 | C2/D9 |
| 6 讲解产物 | 按需出 HTML/SVG 图文讲解（默认）或音视频（可选插拔） | structure → 讲解页 | LLM+渲染 | B1 第②步 |
| 7 复习调度 | 按 SM-2 排期，错题优先、间隔不重复、题型轮换 | 入库 → 复习队列 | 算法 | D10/B10 |

**核心纪律**：第 2/3/4 步是 MathLens 可推广内核（结构化 + CoT + 校验）；学科推理约束层按科目写"应使用的推理范式/禁止的偷懒路径"。

## 五、目标架构七块

### 5.1 知识库自动入库与目录规范

**目录规范（采纳 HITSZ 五分类 + for-Graduate + edu-rag 切片）**：
```
knowledge_base/
├── inbox/                    # 新文件落此，storage_watcher 监听
│   ├── slides/               # 课件 PPT/讲义
│   ├── materials/            # 教材 PDF、参考书
│   ├── notes/                # 个人/学长笔记 Markdown
│   ├── assignments/          # 作业/课后题
│   ├── exams/                # 真题/期末/样卷
│   └── _unclassified/        # 识别不到的兜底人工
├── documents/  chunks/  meta/  # 既有四目录
```
**自动入库管线**（edu-rag 实证参数）：上传 PDF/MD → pymupdf 解析 → CleaningPipeline 清洗 → 切片 **CHUNK_SIZE=512 / OVERLAP=64**（recursive 分隔符 `\n\n \n 。 .`）→ 语义切分后 `_enforce_max_chunk_size` 兜底 → embedding(bge-small-zh) → 写向量(Milvus/SQLite-vss) → **重建 BM25** → 更新状态。
**chunk metadata 必带**：`doc_id/subject/grade/chapter/knowledge_point/chunk_type/page/source_file/anchor/qno/para_id/source_level(official/recollection/textbook/personal)/completeness(full/partial/missing_answers)`。
**LLM 只做轻抽取**：type/exam_weight/keywords/depends_on；识别不到章节进 `_unclassified`。文件命名正则 `^第?(\d+)\s*章?\s*(.+)/(\d+\.\d+)\s*(.+)\.md$` 自动建 taxonomy。

### 5.2 数据库字段级增量 schema（在现有 27 表上 ALTER，不推倒）

- **quiz_questions**：+`difficulty SMALLINT DEFAULT 3`(1-5)、+`options_json JSON`(替代宽表 option_a~d)、+`option_analysis_json JSON`(逐干扰项解析)、+`knowledge_point_id` FK、+`text_hash CHAR(64)` SHA256 去重、+`content_html TEXT`(富文本题)、+`source_level`、+`content_hash`(配合稳定 key)。
- **answer_records**：+`confidence REAL`、+`is_verified BOOLEAN`、+`time_spent INT`(秒)。
- **error_records**（落 SM-2）：+`ease_factor REAL DEFAULT 2.5`、+`interval INT DEFAULT 0`、+`repetitions INT DEFAULT 0`、+`next_review_date DATE`、+`wrong_count INT DEFAULT 1`、+`error_reason`(枚举:概念混淆/准则不熟/计算失误/审题失误)、+`mastery_level`。
- **knowledge_points**：改自引用四级树 `parent_id`，+`exam_weight(必考/常考/了解/不考)`、+`depends_on`(前置知识点边)、+`@@unique(subject,name)`。
- **knowledge_chunks**：+`subject/grade/chapter/anchor/page/qno/para_id`。
- **新建 paper_sections / paper_questions**（拆 mock_papers.sections_data JSON）：试卷快照表 `papers(title,subject_id,total,total_score,duration_min,created_at)` + `paper_questions(paper_id,question_id,order_no,score)`。
- **新建 question_resources**：`(question_id, resource_type[image/table_json/diagram_desc], resource_content, resource_order)` 支持图片题/材料题。
- **新建 wrong_question_records 聚合**：`UNIQUE(user_id,subject_id,question_id)`+wrong_count（可并入 error_records）。
- **universities/major/enrollment/score_line 四表**（择校库，见 §5.7）：字段清单见 G 横向结论。
- **新建 models_registry 登记**：`(model_name, base, lora_rank, quant_format, size_mb, ppl, purpose, ggf_path)`。

### 5.3 OCR 选型分工（8GB 显存 / 不出网）

```
题目图
 ① pictureVerification 规格闸门(E4)：分辨率/体积/格式不合规 → 退回复录
 ② backend-ocr-paddle(GPU 主力)：DB 检测+Rec 识别通用印刷文字，出文本框+坐标
 ③ 低优先级/批量/无 GPU → chineseocr_lite ONNX Runtime(CPU) 回退(E3)，CLI JSON
 ④ 版面分析区分"普通文字块"vs"疑似公式块"，按框裁剪公式小图(借 get_rotate_crop_image)
 ⑤ 公式小图 → 本地公式模型 → LaTeX（pix2tex/LaTeX-OCR ViT+TrOCR 导 ONNX INT8，或量化本地 VLM）
 ⑥ LaTeX 后处理：套用 MathFormula2Tex 的 system_prompt(行内\(..\)/题号 enumerate/符号易混校正/禁解题)
 ⑦ 低置信度 → 转人工复核队列
```
- **分工**：PaddleOCR 主干+chineseocr_lite CPU 备胎（按任务优先级/GPU/批量经 ocr_router 路由）；公式单独通道；云端 API（Image2Text/CharacterRecognition/MathFormula2Tex）**一律不采用**，仅借工程与提示词。
- **显存纪律**：公式模型单独进程、空闲卸载；方向分类只跑前 N 框；优先 ONNX/NCNN 量化、能 CPU 就 CPU。

### 5.4 模型网关与 GGUF 接入

- **model_gateway 主备回退链**（学 F6/G12）：本地 Ollama 优先（deepseek-r1:7b/qwen3:8b/qwen3:4b）→ 按 provider 超时依次 fallback 到云端 API（DeepSeek/豆包）；解题/出卷类任务加"生成→自检→修复"子流程。
- **检索侧**：现有 BM25(jieba, 5164 块) + 向量做 **RRF(k=60, 稠密0.7/稀疏0.3)**，加 `bge-reranker-base`(~300MB, GPU)；**门控只认 rerank 分**，阈值 simple/medium top1≥0.60 且候选≥0.50，complex top1≥0.45 候选≥0.35；未达重试(query variants/HyDE)，`MAX_RETRIES=2` 耗尽拒答。
- **GGUF 接入流程**（G9+G11）：选 Qwen2.5-1.5B/3B-Instruct → SFT 按 `{"conversations":[{role,content}]}` JSONL → LoRA(rank 8~64, alpha 16~128, FP16+梯度累积+Flash-Attn) → 合并 adapter → llama.cpp `convert_hf_to_gguf.py` → `quantize Q4_K_M`(8GB 甜点) → 写 Modelfile `ollama create` → 本地 ollama_service 优先调用；每次产出登记 model_registry。**注意 ComfyUI 精度转换仓不产 GGUF，量化必须 llama.cpp。**

### 5.6 智能组卷双向细目表

**双向细目表 = 知识点(维1) × 难度(维2) × 题型(维3) × 分值(维4)**：
- 题目表须有：`difficulty(1-5)`、`category_id/sub_category_id`、`question_type`、`default_score`。
- 组卷配方（试卷模板，roizenken 实证）：`{subject, sections:[{type,count,score}], total_score, duration_min}`。例：数学二=10选择×5+6填空×5+6解答×12=150/180min；政治=16单选+17多选；408=40选择+7综合。
- **智能组卷 = C4 动态组卷(题型×数量) × C2 薄弱知识点掌握度(=correct/total) 加权**；用户配"细目表矩阵"(横轴知识点多选、纵轴难度、每格填题数)，后端按格抽满即止。
- **试卷快照**：papers + paper_questions 关联表保存题目数组，题库变动不失效；支持打印时 HTML+CSS→WeasyPrint/Playwright printToPDF，`page-break-before:always` 试题答案分页。

- **R1 显存挤爆**：PaddleOCR+rerank+公式模型不同时常驻，公式模型空闲卸载；优先 ONNX INT8。→ 验证：`nvidia-smi` 峰值 <7GB。

### 7.2 TRAE 使用说明（把本报告转交 AI 编程工具）

1. **导入上下文**：在 TRAE 打开 `D:\平台` 工程，把本 Markdown 作为参考文档加入（拖入对话或 `@` 引用）；让 TRAE 先读 §2 现状矩阵与 §5 目标架构，再读 §6 路线图。
2. **按 P0→P1→P2 分批下达任务**：每批只给一个可验收单元（例："按 §5.2 给 error_records 加 SM-2 四字段并移植 errbook sm2.ts，写 pytest 单测"），不要一次性让它改全库。
3. **强调约束**：在 system/对话中固定写入——"本地数据不出网；8GB 显存；在现有 27 表上 ALTER 不推倒；GPL 仓只借设计不复制代码；AI 答案必须 confidence+is_verified 门"。
4. **给它源码锚点**：重点改造时把对应开源仓 URL 一并贴给 TRAE（如做 SM-2 就附 `https://github.com/clawzhang/errbook` 的 sm2.ts；做组卷就附 roizenken 配方与 OpenExam IMPORT_SCHEMA）。
5. **验收命令**：每完成一步跑 `pytest`（对应服务应像 hailuo core.js 那样与 UI 分离可单测）、`nvidia-smi` 验显存峰值 <7GB、抽 50 题人工核对答案置信度门。
6. **不要让它做的**：不要让 TRAE 直接 git clone GPL 仓整包代码进工程；不要引入云端 OCR/VLM 处理真实题库；不要把"OJ 判题"列入近期范围（本批无现成方案，需单独立项）。
