## 二、融入建议（开源项目用什么方式进来）

**五类融入方式**，务必分清——**不是所有项目都适合把代码搬进来**：

| 方式 | 含义 | 适用项目 | 风险 |
| :--- | :--- | :--- | :--- |
| ① 源码移植 | 读源码后用你现有技术栈重写 | edu-rag 的检索策略、kaoyan_ai 的加权器、专有答疑模型的检索思路 | 低（不引依赖） |
| ② 依赖引入 | `pip install` 直接用 | chineseocr_lite（onnx/ncnn）、model_precision_converter | 中（体积/版本冲突） |
| ③ 外部服务 | 独立进程 + HTTP 接入 | **专有答疑模型（现成）**、TTKOCR（桌面工具） | 低 |
| ④ 内容/语料导入 | 只取数据，不取代码 | 数学/英语/408/专业课资料仓库 | **版权** |
| ⑤ 方法/模板借鉴 | 借提示词与流程 | **MathLens（8 步工作流）**、zhangxuefeng-skill、codex-skills | 低 |

## 三、冲突与取舍（必须提前决定，否则会返工）

1. **检索栈冲突**：edu-rag 用 Milvus Lite + LangGraph，你已用 SQLite FTS5 + 向量 + RRF。**决定：只借策略，不引依赖**——保持 SQLite 为唯一事实源，避免引入第二个数据库。
2. **三套 AI 资产合并**：`D:\平台`、`kaoyan_ai`、`专有答疑模型` 各有一套语料与检索。**决定：以平台知识库为唯一事实源**，`kaoyan_ai` 只保留训练能力与加权算法，`专有答疑模型` 以外部服务方式接入（它 2,712 题的真题库可直接作为平台的"真题检索引擎"）。
3. **前端框架差异**：绝大多数参考项目是 Vue/Next.js，你是 React + Vite。**决定：只借交互与信息架构，不搬前端代码。**
4. **模型规模取舍**：不要为了"更全"同时加载多个大模型。**决定：坚持"按显存判定 + 分科路由 + 用后卸载"**（这是你现有设计里最正确的部分之一）。
5. **内容合规**：真题/教材类仓库（cskaoyan、KaoYanZhenTi-PDF、NJUCS、PDFbooks、IBAS0742/kaoyan 等）多为他人版权。**决定：只作个人备考的本地索引，不对外分发；AI 生成的答案解析一律标注"待人工核验"。**
6. **成本控制**：MathLens 单条视频成本 0.2–1 元、耗时 1–10 分钟。**决定：默认只生成 HTML 讲解页（第 1–2 步），视频作为按需深加工。**
