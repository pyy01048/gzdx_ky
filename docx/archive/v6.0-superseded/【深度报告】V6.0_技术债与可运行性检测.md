## 1. 后端可运行性体检

### 1.1 语法正确性：156/156 通过，但 22 个文件带 BOM

**方法**：用 `ast.parse` 逐文件解析（**只读、不生成 .pyc**，优于 `compileall`）。

```bash
D:/Anaconda/python.exe -c "
import ast,pathlib
root=pathlib.Path(r'D:\平台\backend-main-fastapi')
files=[p for p in root.rglob('*.py') if '__pycache__' not in p.parts]
bad=[]
for p in files:
    raw=p.read_bytes()
    try: src=raw.decode('utf-8-sig')
    except UnicodeDecodeError: src=raw.decode('gbk')
    try: ast.parse(src, filename=str(p))
    except SyntaxError as e: bad.append((p,e.lineno,e.msg))
print('TOTAL',len(files),'ERRORS',len(bad))
for b in bad: print(b)
"
```

**结果**：`TOTAL 156 ERRORS 0` — **无语法错误**。

**⚠️ 隐藏隐患**：首轮用 `utf-8` 解码时出现 **22 处 `invalid non-printable character U+FEFF`**。
这不是语法错误（CPython 加载器会自动剥离 BOM），但说明**22 个文件被以带 BOM 的方式写入**，
是典型的「多个 AI / 多个编辑器反复保存同一文件」的痕迹：

```
main.py, models.py,
routers/{errors,flashcards,kaoyan,netdisk,planner,review,tasks}.py,
scripts/{import_kb_data,migrate_structure}.py,
services/{error_linker,kb_pipeline,netdisk_service,review_scheduler,review_service,scheduler}.py,
temp/{_f2_probe,_route_count}.py,
tests/{test_core,test_knowledge_pipeline,test_netdisk}.py
```

**影响**：低。但会让 `grep`/行号统计产生 1 行偏移，干扰审计与调试。
**建议**：一次性批量剥离 BOM（`sed -i '1s/^\xEF\xBB\xBF//'`），并在 `.editorconfig` 固定 `charset = utf-8`。

**附带发现**：2 处 `SyntaxWarning: invalid escape sequence`
- `backend-main-fastapi/resume_train.py:6` — docstring 内 `D:\平台\...` 未转义
- `backend-main-fastapi/scripts/diagnostics/diagnose_missing_sources.py:4` — `D:\考研资料数据集V1.0\...`

## 9. 给决策者的一句话总结

> 这个平台的代码**能跑**，架构里有真正的巧思（naive-UTC 统一、`test_api_contract.py`
> 的5xx 红线、SPA fallback 的 MIME 修复），但**缺三样基础设施**：
> **版本控制、依赖锁定、CI 门禁**。
> 三者缺失导致「模型幻觉写下的假注释被后续 AI 当成事实」、
> 「重构后测试没跟上」「前端改请求体没人校验」「接口断链无人发现」反复发生。
>
> **先做 P0-1（闪卡 422，改一个字段名即可恢复 652 张卡片的复习数据）+ P0-2（git init），
> 再补 CI**，投入产出比最高。文档层面的"混乱感"很大程度上来自
> **5 处数字失真的历史报告**（§5），建议本报告取代它们成为唯一事实基准。
