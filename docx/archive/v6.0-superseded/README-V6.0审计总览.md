## ⚠️ 三个必须知道的数据现实

这三条决定了择校页面能做什么、不能做什么。

### 1. 择校数据 97.1% 未验证 + 关键字段「值对名错」

`kaoyan_scorelines` 的 `source` 分布：`unverified` **789** / `school_official` 16 / `csv_sample` 6

更重要的是**字段名与实际内容大面积不符**（详见下文「能展示什么」一节）——
多数字段值是对的但名字错了，所以最低成本修复是**改前端标签**而非迁移数据。

### 2. 「校复试线」是假字段
`total_line = retest_line` 的行数 = **788 / 811（97.2%）**，且 `national_line` 填充率 **0 / 811（0%）**
→ `retest_line`（校复试线）只是总分线的复制，从未有独立数据。

### 3. 历年趋势功能目前绝对不能做
`year` 分布：2026年 **825 行** / **2025年仅 6 行** / **2099年 1 行（脏数据）**
→ 只有一年数据，无法做任何趋势对比。

### 4. 493 所院校里只有 356 所是真实的
137 行是重复录入的空壳记录，其中「西安建筑科技大学」有 **6 个空白页**（详见下文）。

**因此择校看板在数据修复前，只能做「院校 / 专业 / 省份 / 考试科目 / 分数段分布」这5 个维度的展示与对比，
绝不能展示复录比推论、复试线、历年趋势、热力图、散点图。**

## ⚠️⚠️ 最高风险发现：项目完全没有版本控制，且密钥明文躺在磁盘上

这一条 QA 在收尾时才发现，**风险等级高于所有 P0 数据问题**，请优先处理。

### 1. `D:\平台` **不是 git 仓库**

实测 `git status` → `fatal: not a git repository`，根目录**不存在 `.git` 目录**。

后果：
- **无法回滚**——多轮 AI 接力的所有改动都没有历史，任何一次 AI 改坏都不可恢复
- **无法对比**——这正是你"不敢让它继续写"的技术原因：没有安全网
- 目录下却有 `.gitignore`（998 字节），说明**曾经打算初始化但从未执行**
- `_archive/` 里堆着 5 个 `kaoyan_*.db-wal` 备份（均为 0 字节），是用备份代替版本控制的临时替代品

**建议立即执行**（这是所有后续工作的前提）：
```bash
cd /d/平台 && git init
# 先备份数据库（270MB 不应进版本库）
echo "database/*.db*" >> .gitignore
git add -A && git commit -m "V6.0审计前基线快照：多轮AI接力现状"
```
在建立基线之前，不要让任何 AI 继续改代码。

### 2. `.env` 里的百度网盘密钥是**真实值**，不是占位符

`backend-main-fastapi/.env` 实测（仅检查长度、未回显明文）：

| 键 | 值长度 | 判定 |
|---|---:|---|
| `BAIDU_NETDISK_APP_ID` | 9 | 疑似真实值 |
| `BAIDU_NETDISK_APP_KEY` | **32** | **疑似真实值** |
| `BAIDU_NETDISK_SECRET_KEY` | **32** | **疑似真实值** |

**32 位是典型的百度网盘 API SECRET_KEY 形态，不是占位符。**

风险叠加点：由于项目**没有 git 仓库**，如果这份 `.env` 将来进入任何版本控制或被复制/上传，
你**无法像正常项目那样用 git 历史清除密钥**。清理成本会高得多。

**建议立即执行**：
1. 先去百度网盘开放平台**重置**这组密钥（重置比清理更彻底，顺序不能反——先重置再改文件）
2. 改用环境变量注入，不落盘到 `.env`
3. 若必须保留 `.env`，确认它被 `.gitignore` 覆盖（当前 `.gitignore` 已有 `env` 相关规则，但因无 git 仓库而形同虚设）

### 3. `temp/` 目录里有一个 1 字节的可执行文件

`backend-main-fastapi/temp/virus.exe`，**1 字节**，可执行权限，2026-10-09 06:55 创建。
同目录还有 `f1_smoke.py`、`_f2_probe.py`、`_route_count.py`、`backup_20261009_EF/`、两个 0 字节 txt。

QA 判断很可能是误命名或占位，**但在没查清来源前不要执行它**。1 字节的 exe 不是有效的 Windows 程序，
所以"执行了也没有实际危害"，但它的存在说明**项目里有随手创建、未做清理的文件习惯**。

`temp/` 目前未被 `.gitignore` 覆盖，且其中脚本 `backup_20261009_EF/` 可写真实数据库 —— 建议直接清空并加入 `.gitignore`。

### 4. `models.py` 与空目录 `models/` 并存 —— 定时炸弹

QA 补充了这一点，我此前判定"当前不构成 shadowing"（已实测验证模块优先加载），**但风险仍然存在**：

- 当前：`models/` 是**空目录**，Python 加载 `models.py` ✅ 一切正常
- 定时：任何人只要往 `models/` 里放一个 `__init__.py`（哪怕是空的），**包的优先级会立刻超过模块**

`.gitignore` 里有一条 `models/` 规则，说明**曾有人想删掉它但没删成**。
**建议直接删除这个空目录**（零风险，消除定时炸弹）。

## 用户报告的两个界面问题：根因已定位

### 「打开浏览器看不见文字」

根因是**择校模块存在第二套设计系统**：

| | 主应用 | 择校 10 页 |
|---|---|---|
| 配色 | 暖纸底 `#f4f1e9` / 墨蓝 `#2f4b6e` / 朱红 `#b0442e` | Tailwind 冷色标准色 `#0f172a` `#0284c7` `#ef4444` `#94a3b8`… |
| 实现 | `global.css` 设计令牌 + CSS 类 | **224 处内联 `style={{}}` + 34 处硬编码色值** |
| 响应主题 | ✅ 令牌可切换 | ❌ 内联样式不响应 `data-theme` |

**两个色系交集为 0。** 平均每 49 行代码就有 1 处内联样式。
这不是"配色没调好"，是**有两套设计系统并存**，是"多家 AI 接力、无人收口"的典型症状。

### 「切换也切换不了」

同一个 HTML 属性 `data-theme` 被**4 处代码**写入，互相覆盖：

| 位置 | 问题 |
|---|---|
| `App.jsx:46-47` useTheme(theme) | 会解析 system（正确） |
| `Layout.jsx:178-181` useEffect(..., **`[]`**) | 把 'system' 原样写入；空依赖数组导致**永不响应变化** |
| `Layout.jsx:161-164` toggleTheme | 绕过 store 直写 DOM，与 store 不同步 |
| `Settings.jsx:131-134` setTheme | 第四条路径；saveSettings 还会整体覆盖 |

致命点：`Layout.jsx:149` `isDark = settings.theme === 'dark'`
→ 当 theme 为 `'system'` 时**恒为 false**，所以按钮显示"深色"、点击后写入 `'light'`，
**用户点了什么都没变**。这就是"切换也切换不了"的直接机制。

> 注：`global.css` 的设计令牌本身**完整无缺**，明暗两套变量都正确。这不是 CSS 的问题。

**修复方向**：主题收口为唯一真源（只允许 store 决定）+ `useResolvedTheme()` 统一处理 system + main.jsx 首帧注入防闪烁 + 224 处内联样式迁到 CSS 类/token。

### 2. 字段「值对名错」——最低成本修复是改标签，不是迁移数据

我用 txkyer 原始 1115 条记录对平台做了**逐字段全量回归（825 行全匹配，非抽样）**，结论如下：

| 平台列名 | 实际装的字段 | 命中率 | 前端若照字面展示 |
|---|---|---:|---|
| `enroll_count`「进线人数」 | txkyer `en:进线人数` | 787/825 = 95.4% | ✅ 正确 |
| `retest_count`「进复试人数」 | txkyer `en:`**录取**人数` | 798/825 = 96.7% | ❌ 录取人数被标成复试人数 |
| `admit_count`「拟录取人数」 | **无对应字段·伪造列** | **274/825 = 33.2%** | ❌ **整列作废** |
| `admit_avg_score`「录取均分」 | `enterAvg` **进面**均分 | 777/825 = 94.2% | ❌ 进面均分被标成录取均分 |
| `major_avg_score`「专业课均分」 | `mathAvg` **数学**均分 | 8/825 = 1.0% | ❌ 数学均分被标成专业课均分 |
| `retest_ratio`「复录比」 | `ratio` 复录比 | 774/825 = 93.8% | ✅ **复录比本身是对的** |
| `total_line`「总分线」 | `enterMin` **进面最低分** | 774/825 = 93.8% | ❌ |
| `retest_line`「校复试线」 | `enterMin` 同一值 | 774/825 = 93.8% | ❌ 假字段 |
| `politics_line`「政治线」 | `enterMin` 进面最低分 | 0/825 | ❌ |
| `math_line`「数学线」 | — | 27/825 = 3.3% | ❌ |
| `major_line`「专业课线」 | — | 4/825 = 0.5% | ❌ |

**关键洞察：绝大多数字段「值是对的，只是名字错了」。**
→ **最低成本修复是改前端标签（`displayName`），不是迁移数据。** 这是当天就能完成的止损。

**`admit_count` 整列作废**：该列无任何数据源支撑，比率全是无规律小数（1.0×280、0.667×40、0.833×27…），
疑似某次 AI 补数时用 `round(retest × 随机系数)` 填充。**不可用于任何展示或计算。**

**工程问题（重要）**：txkyer 825 行的导入器**不在仓库里**——
`services/kaoyan/import_yz_json.py` 是 **0 字节空文件**，`import_csv.py` 读的是英文列名且只导入 7 行。
**导入器丢失意味着无法回归验证、无法增量补数**，这是本次审计最需修复的工程问题。

### 3. 僵尸院校：493 行里只有 356 所真实院校

```

  ├─ seed_txkyer     225 行 / 225 唯一校名（干净）→ 挂 832 专业 + 811 分数线
  └─ school_official 268 行 / 131 唯一校名（重复）→ 挂 0 专业 + 0 分数线  ⚠️ 54% 是空壳
```

实测重名实例：「西安建筑科技大学」占 **6 个 school_id**（444/446/448/450/452/454）、
「陕西科技大学」6 个、「山东建筑大学」5 个、「青岛理工大学」5 个。

**用户后果**：搜索「西安建筑科技大学」会看到 **6 张卡片，点进去全是 6 个空白页**。
根因：`school_official` 按院校代码逐行 insert，无唯一约束（`kaoyan_schools` 无 `dwdm` 字段、无 UNIQUE）。
且 `official_url` 列名不符——实测 245/268 行存的是**院校代码**（如 `368559`），含 `http` 的仅 23 行。
`GET /api/kaoyan/schools`（`routers/kaoyan.py:48-92`）**无任何去重**，院校级聚合必然重复计数。
