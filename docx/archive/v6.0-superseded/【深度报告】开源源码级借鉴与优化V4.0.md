## 1.2 最刺眼的发现：八张空表 = 八个"已造好但没用起来"的引擎

平台 README 自列 7 项短板。实测数据库后，**问题不止于"数据少"，而是"功能已实现却从未被触发"**：

| 空表 | 行数 | 已实现的对应逻辑 | 状态 |
|:---|---:|:---|:---|
| `error_knowledge_links` | **0** | `services/error_linker.py` 已实现错题↔知识点挂靠 | 引擎在，链路未通 |
| `review_records` | 1 | `services/review_scheduler.py` SM-2 已实现 | 引擎在，无数据 |
| `ebbinghaus_items` | **0** | 艾宾浩斯复习队列 | 前端有入口，后端无产出 |
| `daily_plans` / `week_plans` / `month_plans` | **0 / 0 / 0** | 三级学习计划 | 表建好了，功能没启用 |
| `phase_plans` / `phase_daily_reviews` | **0 / 0** | 阶段复习管理 | 同上 |
| `study_stats` | **0** | 学习统计汇总 | 5 条 study_sessions 未聚合 |
| `error_records` | 10 | 错题本（拍照 OCR 收录） | 有 AI 按钮，10 条记录说明无人用 |
| `flashcards` | 1 | SM-2 记忆卡片 | 同上 |

**结论**：平台当前最紧迫的问题**不是缺功能，而是缺"闭环"**。已有的 8 张空表若打通，平台完成度立刻从 45% 提升到 65%+，且**零新增架构成本**。这比再抄 10 个开源项目的新功能优先级更高。

## 1.3 数据层最关键的三个结构缺陷

| # | 缺陷 | 证据 | 后果 |
|:--:|:---|:---|:---|
| 1 | **`quiz_questions` 缺 `year` 字段** | 字段仅 `id, content, options, answer, analysis, subject, chapter, knowledge_point, difficulty, source, question_type, created_at` | 无法按年份组真题卷、无法做"2019 数学二第 18 题"精确定位、无法与 `真题（公共课）` 2712 题做答案交叉校验 |
| 2 | **缺 `question_knowledge_links` 多对多关联表** | 仅有 `error_knowledge_links`（0 行），且 `quiz_questions.knowledge_point` 是**单值文本字段**而非外键 | 一道题挂多个考点不可能 → 知识点刷题、薄弱点统计、错因归类全部无从下手 |

## 2.2 检索层的三个具体升级点（对照 edu-rag 源码）

现有 `hybrid_search` 的四路是：`FTS5 chunks` / `向量 chunks` / `knowledge_points LIKE` / `documents LIKE`。对照 `EasyRoc/edu-rag` 的 `core/retrieval_quality.py`：

| edu-rag 做法 | 平台现状 | 差距 |
|:---|:---|:---|
| **CrossEncoder 重排**（bge-reranker-base） | `rerank_results()` 是基于词重叠的启发式 | 🔴 无神经重排，`top1_score` 不可信 |
| **双阈值门控**：`RERANKER_RELEVANCE_THRESHOLD=0.50`（是否相关）< `RETRIEVAL_ACCEPT_TOP1_THRESHOLD=0.60`（是否放行） | 无 | 🔴 无拒答能力 |
| **`observe` 灰度模式**：先记录 `would_abstain` 不真拒 | 无 | 🔴 缺上线安全阀 |
| `reason_codes` 驱动重试（空召回→HyDE / 分低→step_back） | 无 | 🟡 |
| `top1_margin`（top1−top2）指标 | 无 | 🟡 判断"答案是否唯一"的关键维度 |
| 子问题覆盖门控（考研真题"一题多问"正是典型） | 无 | 🔴 解答题会漏答小问 |

## 2.3 平台已做对、应保留的三个决策（开源项目都没做好）

1. **`kb_pipeline --heal` 自愈链**：修复顺序有依赖（状态归一化 → 找回源文件 → 空正文重解析 → 元信息 → 补向量），不可调换。这是 95 个项目里最实用的工程设计之一。
2. **`model_registry` 按本机显存判定而非看排行榜**：开源项目一律按参数量推荐。
3. **知识库健康面板 + 存储 watcher**：`knowledge_base/inbox` 收件箱 + 自动扫描，正是 408-ai-tutor「题库包机制」的简化版，且更适合个人使用。

# 第四部分 核心方案一：跨科目题目分析引擎（MathLens 逻辑复用）

> 你的原话：「参照 MathLens 帮我把所有题目和科目的都做成这个分析逻辑」

## 4.1 MathLens 真正的资产不是视频，是"题目→结构化分镜"这条中间产物链

MathLens（Cursor Agent Skill）表面是"AI 生成数学讲解视频"，但可复用的只有 **8 步流水线的前 2 步**——第 3 步之后全是视频工程（TTS/Manim/渲染），与你的平台无关。

| 步 | 名称 | 输入 | 输出 | 对你是否有用 |
|:--:|:---|:---|:---|:---|
| 1 | `analyze_problem` | 题目图片/文本 | `math_analysis.md` | ⭐⭐⭐⭐⭐ **这就是"分析逻辑"本体** |
| 2 | `html_visualization` | 分析结果 | SVG 讲解页 | ⭐⭐⭐⭐ 可插拔后端 |
| 3 | `storyboard` | — | 分镜 | ⭐⭐ 分镜结构可借，内容不必 |
| 4 | `generate_tts` | — | 音频 + 句级时间戳 | ⭐⭐⭐ 思路可借（见 4.4） |
| 5–8 | 音频校验/脚手架/动画实现/渲染 | — | MP4 | ⭐ 与平台无关 |

## 4.2 步骤 1 的固定输出模板（必须照搬，这是产物契约）

```markdown
## 数学事实分析
### 已知条件
- 条件1 / 条件2
### 推导的事实
1. **事实名称**: 描述 → 计算过程 / 数学表达
### 图形构建方法
- 点的坐标 / 边的关系 / 圆弧定义
### 需要证明的结论
```

SKILL.md 里有一句关键设计：**「证明题要证明的结论，在分镜中都可作为已确立的事实来使用」**——把"待证"提前折叠成"已知"，避免后续步骤反复纠结。

## 4.3 跨科目改造：只换"分析模板"这一个模块

**流水线其余部分完全复用**。这是本方案最重要的设计判断——用户要求"所有题目和科目都用这个分析逻辑"，正确做法不是写 16 套流水线，而是**一套流水线 + N 个分析模板**：

```
题目（图片/文本/LaTeX）
  ↓
① 科目识别（平台已有 ai_router.detect_subject）
  ↓
② 科目专属分析模板  ← 唯一需按科目重写的部分（见下表）
  ↓
③ 结构化 Analysis 对象（统一 schema，跨科目一致）
  ↓
④ 可插拔渲染后端：
   ├─ SVG/HTML 讲解页（电路图/波形图/时序图 → 最有价值）
   ├─ LaTeX 讲义（数学/电路公式 → KaTeX 渲染）
   ├─ 文字分步 + 前端高亮（所有科目兜底）
   └─ 语音跟读（句级时间戳驱动）
```

## 4.4 必须照搬的五个机制

### ① `@[关键词]` 锚点 + 句级时间戳（MathLens 最巧的一环）

MathLens 的动画不写秒数，只写 `@[关键词]`，关键词取自**读白原文的特征词（2~6字）**：

```markdown
**动画**:
- @[切线长定理]: BF、BD 依次高亮，出现等号
```

`generate_tts` 监听 Edge TTS 的 `WordBoundary` 事件生成句级时间戳，代码里 `wait_for_narration("内切圆")` 在 `sync_points` 里**子串匹配**找到时间。**"文字内容"成为时间轴的唯一真源**，彻底绕开 TTS 时长不可预知的问题。SKILL.md 明确禁止"写硬编码秒数"。

**平台落地**：把 `audio_info.json` 的 `sync_points` 换成通用的 `timings.json`：
```json
{"steps":[{"text":"根据切线长定理...","offset_ms":0},{"text":"所以 BF 等于 BD","offset_ms":3200}]}
```
前端据此**高亮当前讲解步骤**。这对 834 的电路分析（分步推导）体验提升极大。

## 6.1 借鉴 edu-rag 的检索门控

### 架构改造（LangGraph 九节点 → 你只需两处改动）

edu-rag 的九节点：`classify → retrieve → rerank → retrieval_gate →(条件边)→ generate / retry_planner→retrieve / abstain → finalize`

**你不需要 LangGraph**。现有 `hybrid_search_with_rerank()` 已是 `retrieve → rerank`，只需在中间插一个门控判断：

```python
# services/retrieval_gate.py  ★新增
# 配置分层（照抄 edu-rag config.py）
RERANKER_RELEVANCE_THRESHOLD  = 0.50   # 管"算不算相关"
RETRIEVAL_ACCEPT_TOP1_THRESHOLD = 0.60   # 管"能不能放行"，必须 > 上面
COMPLEX_RELEVANCE_THRESHOLD   = 0.35   # 复杂问题用更宽的两套
COMPLEX_ACCEPT_TOP1_THRESHOLD = 0.45
RETRIEVAL_GATE_MODE = "observe"          # ★ observe 灰度 / enforce 拒答

def evaluate_gate(results, query, is_complex=False) -> GateDecision:
    """返回 accept | retry | abstain + reason_codes + metrics"""
    rel_t  = COMPLEX_RELEVANCE_THRESHOLD   if is_complex else RERANKER_RELEVANCE_THRESHOLD
    acc_t  = COMPLEX_ACCEPT_TOP1_THRESHOLD  if is_complex else RETRIEVAL_ACCEPT_TOP1_THRESHOLD

    if not results:
        return GateDecision("retry", ["empty_recall"], {})      # → HyDE 重写
    if reranker_unavailable:
        # 关键：不能因为重排器挂了就全线拒答，按 mode 决定
        mode = "abort" if RETRIEVAL_GATE_MODE == "enforce" else "accept"
        return GateDecision(mode, ["reranker_down"], {})
    top1 = results[0].score
    if top1 < rel_t:
        return GateDecision("retry", ["low_relevance"], ...)    # → step_back 重写
    if top1 < acc_t:
        return GateDecision("abstain", ["below_accept"], metrics)
    return GateDecision("accept", [], metrics)
```

**四条硬规则（照抄 edu-rag 的设计决定）**：
1. **只信 rerank_score**：RRF 只决定候选顺序，**能否生成答案由重排分数决定**，不混用余弦/BM25 分数做阈值
2. **拒答必须是一个节点而不是 if-else**：返回固定话术 + `abstain_reason`，前端据此渲染"资料未覆盖"提示条。实现成本极低，但能把"幻觉"变成**可观测指标**
3. **`observe` 灰度是上线必备开关**：先跑一周收集 `would_abstain` 率，定阈值后再切 `enforce`
4. **reason_codes 驱动重试策略**，不随机重试：空召回 → HyDE（生成假设答案再检索）；有文档但分低 → step_back（回溯更宽泛概念）

## 6.5 子问题覆盖门控（解答题救星）

考研真题"一题多问"（如 18 题问 (1)(2)(3)）是典型复杂问题。edu-rag 的做法：

1. 拆子问题 → 每问单独检索
2. **子问题两段重排**：按 `source_sub_query` 分组，各自独立 rerank 后合并去重（避免原查询二次打分压低局部证据）
3. **覆盖门控**：每问单独算 top1，标 `covered/weak/missing`；`missing` 用 HyDE 修，`weak` 用 step_back 修；`coverage_ratio < 1` 就不许生成
4. 复杂问题子答案合成：先各问独立作答（`SUB_ANSWER_MAX_TOKENS=512`），再 `synthesize_final_answer` 汇总

```python
def build_paper(subject: str, paper: str, *, year=None,
                mode="normal", count_override=None,
                kp_ids=None, question_source="all",
                exclude_recent_days=14) -> ExamPaper:
    """
    mode: normal | weakest | random
    question_source: all | error | ai_generated
    """
    blueprints = load_blueprints(subject, paper, year)
    sections = []
    for bp in blueprints:
        n = count_override or bp.count
        # ★ 跨章节均匀采样（pigking0606 算法）：不是纯随机
        candidates = query_questions(bp, kp_ids, question_source,
                                     exclude_question_ids=recent_ids(exclude_recent_days))
        if mode == "weakest":
            picked = sorted(candidates, key=lambda q: mastery_score(q))[:n]
        else:
            picked = uniform_sample_by_chapter(candidates, n)   # ★
        sections.append(Section(bp, picked))

    # ★ 试卷冻结：交卷前题库变动不影响已考卷面
    session = ExamSession(config=to_json(sections),
                          status="ongoing", expires_at=now() + bp.time_limit)
    bulk_insert(session.answers_snapshots)   # 题目全量快照
    return session
```

**均匀采样算法**（直接可用）：
```python
def uniform_sample_by_chapter(candidates, n):
    """按 chapter 分组 → 组内随机 → 按组轮转取题直到满 n"""
    groups = defaultdict(list)
    for q in candidates:
        groups[q.chapter].append(q)
    for g in groups.values():
        random.shuffle(g)
    picked, rounds = [], 0
    chapters = list(groups.keys())
    while len(picked) < n and rounds < max(len(v) for v in groups.values()):
        for ch in chapters:
            if groups[ch] and len(picked) < n:
                picked.append(groups[ch].pop(0))
        rounds += 1
    return picked[:n]
```

```python
def score_major(hist: list[AdmissionHistory], *, kp: KnowledgeProfile) -> ScoreResult:
    # 1. 报录比归一化（越低越好）
    ratio_score = normalize(-hist[-1].ratio)
    # 2. 分数线归一化（越低越好）
    cut_score_norm = normalize(-hist[-1].admit_min_score)
    # 3. 线性回归趋势（近 5 年）
    trend_score = regression(hist, key="cut_score")   # 上升/下降/稳定
    # 4. 合成 0-100 热度
    heat = 100 * (0.4*ratio_score + 0.4*cut_score_norm + 0.2*trend_score)
    # 5. 置信度（年份越少、数据越旧，置信度越低）
    confidence = f(len(hist), latest_year=hist[-1].year)
    # 6. 按风险承受度映射冲稳保
    bucket = map_to_bucket(heat, user.risk_tolerance)  # 保守/稳健/激进
    return ScoreResult(heat, confidence, bucket, trend=trend_score)
```

## 9.1 `D:\真题（公共课）\专有答疑模型` 的架构实测

**2-gram 字符倒排索引**，零第三方依赖（仅标准库）：

| 环节 | 实现 |
|:---|:---|
| 归一化 | `NFKC`（全角→半角）+ `re.sub(r"\s+","")` 去所有空白 + 小写。**构建与查询必须同口径** |
| 切 gram | `{text[i:i+2] for i in range(len(text)-1)}` 字符级 2-gram 集合 |
| 倒排 | `postings: dict[gram → list[doc_id]]`，实测 **79231** gram，`index.pkl` 9.8MB |
| 阶段1 | 倒排累加 `score += idf[gram]`，`idf = log((N-df+0.5)/(df+0.5)+1)` |
| 阶段2 | BM25 变体 + 长度归一化 + **覆盖率加权** `× (0.7 + 0.3*coverage)` |
| 阶段3 | **★ OCR 噪声惩罚**（最实用的设计）：白名单外字符占比 >0.35 → `score *= 0.30`；>0.25 → `×0.50`；>0.15 → `×0.70`；>0.10 → `×0.85`。白名单显式保留 `=+*/−()（），.。:；'"【】〖〗[]{}、？！？%√∞πλθμ∑∫≤≥` —— **数学符号全放行** |
| 阶段4 | **二次校验重排 top-60**：中英考点映射（`极限↔lim`、`导数↔dy/dx,f'(x)`、`积分↔integral,dx,∫`、`行列式↔det`、`特征值↔λ,∑`）；中文关键词子串命中 **+6.0**/条；**年份命中 +8.0**；**有答案 +6.0，无答案 −1.0**；乱码严重且 kw_hits<2 → **−60.0 强降权** |
| 变式题 | Jaccard 相似度（`min_sim=0.08`）全扫描 top-3 |
| 科目识别 | 别名表**按别名长度倒序**匹配（保证"英语二"(3字) 优先于 "英语"(2字)）—— 正确的细节 |
| API | `python api_server.py --port 8765`，OpenAI 兼容 `/v1/chat/completions`。**忽略 `stream` 参数**；`usage` 是**字符数不是 token 数**（会误导计费） |

**关键定位判断**：它的 `render_answer` 输出**检索到的原题全文，不是生成式回答**——本质是"相似真题检索器"，不是"答疑模型"。所以它不能替代 FTS5+向量，但**恰好补上你平台的三块短板**。

`/℃4）`、`厂0）`、`一1`（横杠误识别）——**严重 OCR 污染**。

**结论：直接导入 2712 条会净增噪声。** 理由：
1. 有效答案仅 **633/2712（23.3%）**
2. **90.9% OCR 质量**，`/℃4）` 会污染 FTS5 倒排词表并拉低 embedding 质量
3. 英语占 **53%**（1451/2712），学科分布严重倾斜
4. 字段结构不兼容（B 有 13 字段，结构化程度更高，需映射）

## 结语：三句话总结

**第一，你的平台不缺功能，缺闭环。** 36 张表里 8 张是空的，`error_knowledge_links` 0 行、6 张计划表 0 行、`review_records` 1 行——已有的 37 个服务里有 SM-2、有错题挂靠、有艾宾浩斯、有 AI 路由，但没有一条数据真正流过它们。**P0 那 10 件事做完，完成度从 45% 到 65%，且不需要新架构。**

**第二，95 个项目里真正值得抄的是"设计决策"而非"功能列表"。** 最有价值的四个发现都来自 README 之外：edu-rag 的 `retrieval_gate.py` 里"拒答必须是一个节点而不是 if-else"、classroom-assistant 的"待教师处理清单"变成"知识盲区池"、politics-tracker 的"事件溯源为唯一真相"、hailuo-math 的"core.js 与 app.js 分离"——它们都不是功能，是让功能不会腐化的架构选择。

**第三，你点名的 MathLens 要小心。** 它是 **CC BY-NC 4.0**，其分析流水线（8 步 + 固定输出模板 + 断言层 + `@[关键词]` 锚点）是本轮最有价值的发现，但**代码与提示词必须自行重写**。真正授权最干净、可以直接改造的是 **MathFormula2Tex（MIT）** 的公式识别方案——而它恰好解决你点名的"公式识别弱"问题。
