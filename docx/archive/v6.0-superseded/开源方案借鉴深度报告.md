## 三、优势互补方案（核心章节）

> 每条 = 现状问题 → 借鉴哪些开源 → 具体落地方案 → 优先级。
> 优先级：P0 直接影响核心价值；P1 功能闭环；P2 工程质量。

### 3.1 数学公式识别与渲染链路（P0，直接补最短板）

**现状**：OCR 对工程符号/公式乱码率 0.49%，数学公式入库后无法渲染，数学答疑讲不清楚。

**借鉴**：

- YunXi-Zhu0/MathFormula2Tex：视觉 LLM（本地 qwen-vl / 云端 DashScope）按「一章一文件夹」批量识别公式图 → 输出规范 LaTeX，内置符号易混防控清单。

- ricolxwz/Kaoyanshuxue：现成高数/线代 LaTeX 源码（Apache-2.0）可直接作答案与公式数据源。

- alizeisnotalice/codex-skills：「看不清标注待核对」质量红线 + OCR 兜底人工核对。

- shuyicc/MathLens：几何坐标自校验，防 AI 画错图。

**落地方案**：

1. 在 OCR 管线后加「公式检测」：命中数学公式区域 → 送视觉 LLM 转 LaTeX → KaTeX 渲染入库（分块存 `latex_original` 字段）。
2. 前端全局引入 KaTeX/MathJax，知识点/题目/解析统一渲染 LaTeX。
3. 批量用 LaTeX 源码仓库补数学真题答案。
4. 新库数据：直接抓取 China-NPEE-math（数一/二 1999-2019 真题+解析）喂入现有入库管线。

### 3.2 知识点体系横向覆盖（P0，最高性价比）

**现状**：206 个知识点全在数电模电，数学/英语/政治/408 等 14 科为 0。

**借鉴**：

- 320wuyanzu/PG-Math：考试大纲→知识点清单→进度标记三层结构。

- XColorful/Politics-Obsidian-Note：政治五科「科目→章节→考点+标签」Markdown，可直接解析导入。

- wmathor/Postgraduate-Advanced-Mathematics：教材章节→知识点目录映射。

- xym-ee/electronics + HITSZ-OpenAuto/EE1009：现成电路/模电/数电知识树 + 「讲次→知识点→必考程度」模板。

- zezczz/modian-zongjie：总览画布→分章导图的知识地图 UI 范式。

**落地方案**：

1. 数学：按大纲章节建「考点清单」表（可加 `考频` 标注，仿 BIT「覆盖套数」），解析 303 篇数学文档填充。
2. 政治：直接导入 Politics-Obsidian-Note 的 Markdown 结构（已有 `structure_parser.py`，只需加一个解析器）。
3. 数电模电：用 xym-ee 知识树校验/扩展现有 206 个知识点。
4. 知识地图 UI 升级为「总览画布 → 分章导图 → 知识点卡片（带考频/掌握度/错题数）」。

### 3.3 真题答案补全 + 置信度判分（P0）

## 六、结语

本地平台**引擎已经非常完整**（OCR→知识库→RAG→AI→错题→记忆→规划的闭环骨架都在），最大的问题不是「缺功能」而是「燃料没加满」：知识点没铺开、答案没补全、闭环没触发、公式没渲染。开源方案的价值恰好都集中在这几处：

- **补齐燃料**：用 MathFormula2Tex 解决公式、用 Politics/数学笔记仓库解决知识点、用真题答案仓库解决答案覆盖率；

- **激活闭环**：用 408-ai-tutor 的置信度判分、errbook 的错题状态机、hailuo-math 的错因分类，把已有但空转的表填起来；

- **体验升级**：用 kaoyan-quiz 的组卷、墨题的 FSRS 与激励、for-Graduate\_student 的分数线数据、reading-locator 的阅读定位，补应试与决策体验。

建议按 P0 六项先行（成本低、收益立竿见影），再逐批进入 P1/P2。整个升级**不需要推倒重来**——现有 27 张表、32 个服务、20 个路由的架构足以承载以上全部方案。
