## 一、执行摘要

**最值得立刻做的 6 件事**（按性价比排序）：

1. **把 `D:\平台\knowledge_base\` 升级为"投递即入库"的正式底座**（目录协议 + 文件指纹去重 + 自动分流 + 质检报告），把 4853 个缺向量的分块补上——你已有 `inbox/` 与 `ingest_inbox.py`、`storage_watcher.py` 雏形，只差闭环。
2. **引入"题库构建流水线"范式**（借鉴 `satywt/build-exam-question-bank` 的去重思路 + `Albertdeng23/GEEQuestionBank` 的 PDF→JSON→向量化 + `alizeisnotalice/codex-skills` 的"图片/文档→统一格式试卷+答案解析"），把"293/1869 有答案"这个最大短板补起来。
3. **把 MathLens 的 8 步工作流抽成"科目可配置的分析模板"**，数学/数电/模电/408/政治/英语各配一套提示词与校验规则，让"分析逻辑"覆盖全科。

## 二、现有资产盘点

### 2.1 `D:\平台` —— 服务侧主平台（FastAPI + SQLite + React）

**定位**：面向**贵州大学 834 电子技术基础**（数电 + 模电）的本地化备考系统，核心链路是"扫描版真题 OCR 入库 → 章节/知识点/题型三级结构化 → 错题本与知识库联动 → 本地模型优先的 AI 答疑 → 复习进度追踪"。

**技术栈**：后端 FastAPI · SQLAlchemy 2.0 · SQLite 单文件 · APScheduler · uvicorn；前端 React 18 · Vite 5 · Zustand · HashRouter；检索 SQLite FTS5 + jieba(BM25) + 向量 KNN(bge-small-zh-v1.5) + RRF 融合；OCR RapidOCR(PP-OCRv4 ONNX) + pypdfium2 渲染；本地模型 Ollama；微调 Qwen2.5-3B + LoRA；网盘 百度网盘开放平台 OAuth。

**已有模块（19 个路由）**：仪表盘、**知识地图**（章节→知识点→题型三级 + 掌握度 + 复习队列 + 覆盖率体检）、任务打卡、**刷题中心**、**错题本**（拍照 OCR 收录 + 自动挂靠知识点 + AI 分析 + 毕业归档）、**文档知识库**（上传解析 + 扫描版真题 OCR + 知识库健康面板体检/一键修复）、AI 助手（SSE 流式 + 本地优先/云端兜底 + RAG 标注来源）、记忆卡片（SM-2）、单词（4569 词）、学习计划（艾宾浩斯）、网盘联动、设置（备考科目/模型选型/访问二维码/导入导出）。

**知识库链路（8 步）**：扫描入库 → 解析正文（pypdf→pdfplumber）→ 扫描件 OCR（pypdfium2 渲染→RapidOCR）→ 分块 → 全文索引（jieba→FTS5/BM25）→ 向量索引（bge-small-zh-v1.5）→ 结构化（章节树→章节/知识点/题型）→ 元信息标记（doc_type + 扫描件标记）。**四个入口**：目录批量导入 · 单文件上传 · 百度网盘下载入库 · 一键修复缺口。

**数据实况（文档自述）**：文档 1,545 篇（0 篇空正文）；知识分块 25,152；已向量化 20,299（缺 4,853）；知识点 206（仅数电模电）；真题 1,869（293 有答案、解析仅 10 条）；数据库 `kaoyan.db` 约 262 MB。

**平台自述的 7 条短板**：① 知识点只覆盖数电模电，其余 14 科为 0；② 真题答案覆盖率 15%；③ 19% 分块缺向量；④ 错题↔知识点关联未启用（表空）；⑤ 复习记录未启用（SM-2 已实现）；⑥ torch 是 CPU 版无法 GPU 训练；⑦ 前端无自动化测试（后端 128 项）。

**已存在但未闭环的能力**：`knowledge_base/` 目录（`chunks/`、`documents/`、`inbox/`、`meta/`、`README.md`）已建立；`scripts/ingest_inbox.py`、`services/kb_ingest.py`、`services/storage_watcher.py` 说明"投递目录→自动入库"的骨架已在，缺的是**协议化与质检**。

### 2.2 `D:\kaoyan_ai` —— 训练侧 AI 板块（独立工程）

**定位**：基于 Qwen2.5-1.5B-Instruct 微调 + RAG 资料库的考研复习问答。

**流程**：360 个 PDF + 74 个 Office 文件 → `data/processed/*.txt`；清洗后 296 个有效文件 + 网络补充八科目 → **5,164 个知识分块**（`data/kb_chunks/`，逐块一个 JSON + `index.json`）；SFT 数据集 **4,435 train + 235 val**（知识点问答 + 资料讲解型）；LoRA 微调 Qwen2.5-1.5B-Instruct（r16/alpha32、bf16、2 epochs、`target_modules` 覆盖 q/k/v/o/gate/up/down_proj）；`04_app/chat.py` 提供 **BM25 + jieba 分词 + 术语加权精排**的检索器（含同义词组如 DAC↔数模转换器、TTL↔晶体管逻辑；封面/导航噪声降权；粗召回 60 条再精排）+ LoRA 模型生成。

**亮点**：`chat.py` 里的 `CORE_TERMS` 术语加权、`TERM_SYNONYMS` 同义词组、`NOISE_TERMS` 降权、以及"术语出现在前 200 字符内额外加权（定义句通常靠前）"——这是**很实用、可直接移植到平台检索层的中文教育检索技巧**。

**问题**：与 `D:\平台` 的知识库（25,152 分块）完全平行、互不联通；`config.yaml` 与平台配置各一套。

### 2.3 `D:\真题（公共课）\专有答疑模型` —— 检索式答疑（第三套）

**定位**：基于 1986–2026 年公共课真题的本地检索式答疑模型，覆盖**数学二 426 / 英语一 1,082 / 英语二 369 / 政治 835 = 2,712 题**，纯离线、零第三方依赖。

**引擎设计（`qa_engine.py`）**：
- **检索**：字符级 2-gram 倒排索引 + BM25 变体（idf 加权 + 文档长度归一化 + 查询覆盖率加权）；**二次校验**用 query 关键词在题干/选项/答案/解析中的直接包含度加权；**年份加权**；**科目限定**；**OCR 噪声惩罚**（异常字符比例越高折扣越大，最高降 70%）；**答案优先**（有标准答案的题额外加分）。
- **变式题识别**：以命中题题干 2-gram 为查询，算 Jaccard 相似度返回 Top3。
- **规则推理**：数学命中"极限/导数/积分/微分方程/矩阵/级数"等考点词给出解题步骤引导；政治命中"矛盾/实践/资本/价值/认识/改革/法治"给出答题要点。
- **接口**：`api_server.py` 提供 **OpenAI 兼容 `/v1/chat/completions`**（零依赖标准库），任何 OpenAI SDK / Ollama / LangChain 客户端可直接调用。

**价值**：这是**你已经造好的、最接近"可复用检索服务"的一块**，只差注册进平台。

### 2.4 三个资产的关系问题

三者是**三套独立的检索与模型栈**：`D:\平台`（FTS5+向量+RRF，25k 分块）、`kaoyan_ai`（BM25+术语加权，5k 分块，LoRA 1.5B）、`专有答疑模型`（2-gram 倒排，2.7k 题，规则推理）。同一批考研资料被处理了三遍，**检索质量、数据口径、模型调用都不统一**。本报告的方案部分把"三合一"作为一条主线。

### 3.2 A 组：数学与分析逻辑（10 个）

- **`shuyicc/MathLens`（★363，Python）——本报告的"参照母版"**。它是一个**数学题目讲解 Agent Skill**，核心是一套 **8 步工作流**：`analyze_problem`（数学建模，输出 `math_analysis.md`：已知条件/推导事实/图形构建方法/待证结论）→ `html_visualization`（HTML+SVG 画图并**展示画图过程**）→ `storyboard`（分镜：每幕画面/字幕/读白/动画，**不限幕数**）→ `generate_tts`（Edge TTS，**自动捕获句级 sync_points 时间戳**）→ `validate_audio`（校验音频并回填时长、打印同步点摘要）→ `scaffold`（生成 `script.py` 脚手架）→ `implement`（实现 Manim 动画）→ `check_and_render`（渲染并检查，失败回到第 7 步）。三个可直接复用的工程化设计：**① 音画对齐**——分镜里用 `@[关键词]` 锚定读白句子，代码里用 `wait_for_narration("关键词")` 等到读白说出该词再触发动画，**禁止硬编码秒数**；**② 防遮挡**——定义 `ZONES`（标题/几何/字幕/公式四区互不重叠）与 `Z_LAYERS`（bg_grid→fill→geometry→label→highlight→subtitle→title 七层）；**③ 正确性校验**——`assert_geometry()` 用相对误差验证题目给定条件（如 AB=BC、E 是中点、直角点积≈0）并检查画布范围。另有"节奏预算"约束（单幕重动画连续不超过 3 个、每句读白 8–20 字、结论后留 0.2–0.4s 停顿）。**这套东西是"把一道题讲透"的可复制流水线，价值远超它当前只覆盖数学。**

## 五、借鉴优化方案（八个模块）

### 5.1 知识库与数据库底座（优先级：最高）

**目标**：把 `D:\平台\knowledge_base\` 变成"**丢文件进去就自动进库**"的正式底座，并在根目录下把"数据库"独立成专门文件夹。

**目录协议（建议）**：

```
D:\平台\
├── knowledge_base\            ← 知识库（人可读的原始资料 + 元信息）
│   ├── inbox\                 投递区：任何新文件丢这里
│   │   ├── 数学\  英语\  政治\  数电\  模电\  电路\  408\  公共课真题\  教材\  笔记\
│   ├── documents\             已入库原件（按科目/来源归档）
│   ├── chunks\                分块产物（与 documents 一一对应）
│   ├── meta\                  每篇文档的元信息（doc_type/来源/年份/科目/扫描件标记/指纹）
│   ├── manifest.json          清单：文件指纹 → 文档ID → 分块数 → 向量状态
│   └── README.md              目录协议说明（放什么、命名规范、如何回填）
├── database\                  ← 数据库底座（专门文件夹）
│   ├── kaoyan.db              SQLite 主库（从 backend/data 迁出或软链）
│   ├── backups\               每日备份（已有 backup_service）
│   ├── embeddings\            向量索引缓存
│   └── migrations\            迁移脚本与版本记录
└── ...
```

**关键机制（按借鉴来源落地）**：

1. **文件指纹去重**：入库前算 SHA-256（内容指纹）+ 文件名规范化指纹，已在 `manifest.json` 的即跳过——解决"同一份资料重复入库"。（借鉴 `build-exam-question-bank` 的"整理、去重"定位）
2. **目录名即元数据**：`inbox/数学/xxx.pdf` 自动带 `subject=数学`；配合文件名规则（`2023-数二-真题.pdf`、`模电-第3章-笔记.md`）自动解析年份/科目/章节。**这是让"添加新文件更快识别入库"的关键——不依赖模型，靠约定。**
3. **自动分流**：有文本层 → pypdf/pdfplumber 解析；无文本层 → 渲染 + OCR（现有链路）；公式密集 → 追加 LaTeX 转换（借鉴 MathFormula2Tex）。
4. **入库质检报告**：每批入库产出 `meta/ingest_report_YYYYMMDD.json`——成功/跳过/失败清单、OCR 噪声比例、空正文、缺向量项。**参照 `yhzyly/pictureVerification` 的"图片校验"与 `check_ocr_quality.py` 的噪声量化。**
5. **ID 与检索协议**：给每篇文档、每个分块、每道题分配稳定 ID（如 `DOC-数电-001`、`Q-2023-数二-017`），并写清检索协议（按 ID 直查、按科目+章节过滤、按相似度召回）。**直接借鉴 `ZavionWang/exam-knowledge-base` 的 `kb-id.py` / `kb-search.py` / `kb-backfill.py` 三件套。**
6. **一键回填**：`--heal --embeddings` 已有，补齐 4,853 个缺向量分块；新增"缺答案/缺解析/缺知识点"三类回填。

**收益**：新资料从"手动上传-等待-检查"变成"丢进 inbox → 自动识别 → 质检报告告诉你哪些需要人工处理"。

### 5.2 全科"MathLens 式"题目分析逻辑（优先级：最高）

**目标**：把 MathLens 的 8 步工作流**抽成科目可配置的模板**，让数学、数电、模电、电路、408、政治、英语都能套用同一套"分析逻辑"。

**抽象后的通用 8 步（保留 MathLens 的工程化设计）**：

| 步 | 通用名称 | 数学（MathLens 原版） | 数电/模电 | 政治 | 英语 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | 题目解析 | 数学建模：已知/推导事实/图形构建/待证结论 | 电路建模：器件/参数/端口/时序关系 | 材料定位：题干关键词→考点范围 | 篇章定位：题型/题干定位/选项差异 |
| 2 | 可视化 | HTML+SVG 展示画图过程 | 电路图 + 波形图（含时序） | 逻辑框架图/时间轴 | 长难句结构图 |
| 3 | 分镜脚本 | 画面/字幕/读白/动画，`@[关键词]` 锚点 | 同 | 同 | 同 |
| 4 | TTS | 句级 sync_points | 同 | 同 | 同 |
| 5 | 音频校验 | 时长回填 + 同步点摘要 | 同 | 同 | 同 |
| 6 | 脚手架 | `script.py` 骨架 | 同（可换为电路仿真脚本） | 同 | 同 |
| 7 | 实现 | Manim 动画 | Manim / 电路仿真 | Manim / 板书动画 | Manim / 板书动画 |
| 8 | 校验渲染 | 几何断言 + 渲染检查 | 电路定律断言（KCL/KVL、真值表一致） | 结论与材料一致性 | 答案与原文一致性 |

**可直接移植的三个工程机制（建议照搬）**：
- **音画对齐**：分镜用 `@[关键词]` 锚定读白，代码用 `wait_for_narration("关键词")`，**禁止硬编码秒数**。
- **防遮挡**：`ZONES`（标题/图形/字幕/公式四区）+ `Z_LAYERS`（7 层 z-index）。
- **正确性断言**：`assert_geometry()` 用相对误差验证题目条件；数电/模电版改成"真值表一致、KCL/KVL 成立、时序关系正确"的断言。

**落地形态（建议）**：在平台里新增 `分析模板` 服务——`services/analysis_template.py`，每个科目一份配置（提示词 + 产物规范 + 断言规则 + 渲染后端），前端"刷题中心"每题加一个"深度讲解"按钮，走 8 步生成 HTML 讲解页（第 1–2 步即可交付，不必每次都出视频，视频按需触发）。**关键：先做"HTML 讲解页"，视频作为可选深加工，避免成本失控**（MathLens 自述单条视频 1–10 分钟、成本 0.2–1 元）。

### 5.3 OCR 与录题质检流水线（优先级：高）

**目标**：把"拍照→识别→切题→质检→入库"做成稳定流水线。

- **切题能力**：你现在的 OCR 主要出整页文本。借鉴 `chenguanyou/CharacterRecognition` 的"**含位置信息版 OCR**"，用**坐标做版面分析**——按行/块聚合，识别"题号"模式（`1.`/`（1）`/`一、`）切分题目与选项。这是"题库结构化"的前置条件。
- **竖排与轻量**：借鉴 `DayBreak-u/chineseocr_lite`——**4.7M 总模型**、支持竖排、ncnn/mnn/tnn 推理。可作为一个**可选轻量 OCR 引擎**（当前 RapidOCR 之外的备选），尤其适合手机端。
- **手写识别**：借鉴 `jjcheer/ocrcn_tf2`，用于识别你手写的解题过程与笔记。
- **录题质检**：借鉴 `yhzyly/pictureVerification`，把质检规则显式化——图片清晰度/倾斜/裁切完整/是否重复/是否含答案。
- **公式→LaTeX**：借鉴 `YunXi-Zhu0/MathFormula2Tex`，对公式密集题追加一次多模态转换，产出可编译 LaTeX（前端已可渲染 MathJax/KaTeX）。
- **桌面批量**：借鉴 `Greedysky/TTKOCR`，做一个"选目录→批量 OCR→出质检报告"的桌面小工具（可作为平台外的辅助入口）。

### 5.4 题库构建与"组题网"（优先级：最高）

**A. 题库生产流水线（补答案与解析）**

流程：`PDF/图片 → 版面切题 → 结构化 JSON → 去重 → 答案/解析生成 → 知识点挂靠 → 入题库`。

- **去重**：借鉴 `satywt/build-exam-question-bank`（整理、去重 → 结构化题库 + 交互式网站）。
- **答案解析生成**：借鉴 `Albertdeng23/GEEQuestionBank` 的"VLM 考点分析 + 流式生成"，以及 `alizeisnotalice/codex-skills` 的"图片/文档→统一格式试卷 + 答案解析"。
- **相似题/变式题**：平台已有 2712 题的**变式题识别（Jaccard）**能力（在 `专有答疑模型` 里），把它并入题库后即可"做一道题，推三道同类题"。
- **解析质量把关**：借鉴 `blueraina/astrbot_plugin_mathsolve` 的 **DeepThink 多角色迭代求解**——让"解题者/审查者/纠错者"三个角色互相校验，再落库，能显著降低错误解析入库的概率。

**B. 组题网（组卷引擎，从 0 到 1）**

核心能力：
1. **抽题**：按 `科目 / 章节 / 知识点 / 题型 / 难度 / 年份 / 来源` 多条件抽题；支持"按错题知识点优先抽"。
2. **组卷**：设定题量、题型配比、难度分布、总分与时长；一键生成试卷。
3. **导出**：试卷 + 答案 + 解析分册导出 PDF（借鉴 `HaujetZhao/MakePracticeBook` 的版面处理与 `errbook` 的打印 PDF）。
4. **模考**：限时答题、自动批改客观题、主观题对照答案自评。
5. **回写**：错题自动进错题本并挂知识点，触发复习队列。
6. **统计**：按科目/章节的正确率报表（借鉴 `menggou1/kaoyan-politics-tracker` 的日报/周报/月报）。

**最直接的形态参照**：`roizenken-design/kaoyan-quiz`（随机刷题 + **组卷模考** + 真题卷 + 错题本 + 统计，纯前端离线）——建议把它的交互流程"照抄"，后端换成你的题库 API。

### 5.7 本地模型 + API 协同与提速（优先级：高）

**核心问题**：三套 AI 资产并行、CPU 版 torch、8GB 显存、Ollama registry 下载慢。

**方案**：

1. **统一 AI 网关**：平台已有 `services/model_gateway.py` / `ai_router.py` / `model_registry.py`。把 `专有答疑模型` 的 **OpenAI 兼容 `/v1/chat/completions`** 注册为一个 Provider（`provider_type=local-retrieval`，base_url `http://127.0.0.1:8765/v1`）——**它零依赖、纯检索、毫秒级返回，适合做"真题检索型问题"的第一跳**，命中真题时直接用，未命中再交给生成模型。这是**最立竿见影的提速**。
2. **检索层合并**：把 `kaoyan_ai/chat.py` 的 **术语加权 + 同义词组 + 噪声降权 + 前 200 字符加权**移植到平台 `search_service`，与现有 FTS5+向量+RRF 融合（三条召回通道 + 精排），检索质量会明显提升。
3. **显存友好**：借鉴 `namoamitabha1978/ComfyUI_model_precision_converter` 做**精度转换**（bf16/fp16/int8 互转），在 8GB 显存下把模型跑得更稳；分科路由沿用你现有"按显存判定"的原则（这是你做得比多数项目好的地方，坚持）。
4. **微调与对齐**：`kaoyan_ai` 已有 LoRA 全流程；若要再进一步，借鉴 `chensi-cs/FastTrack4LLM` 的 **DPO / 知识蒸馏**脚本（`trainner/train_dpo.py`、`train_distillation.py`）与数据管线。
5. **模型下载提速**：Ollama registry 慢的问题，用 `kaoyan_ai` 已验证的 **ModelScope** 通道（`modelscope>=1.18.0`）替代——这是你本地已有且跑通的路子。
6. **云端兜底策略**：保持"本地优先、云端兜底"，但**兜底要按科目选**（你已有分科路由），并给云端调用加**结果缓存**（平台已有 `ai_optimizer` 缓存）。
7. **CPU torch 问题**：`kaoyan_ai` 的 `requirements.txt` 明确要求 CUDA 版 torch，且其环境已跑通 GPU 训练——把 `kaoyan_ai` 的环境作为训练环境，平台只做推理，**不必强行在平台侧装 CUDA torch**。

### 5.8 评测与质量闭环（优先级：中高）

**问题**：平台自述"训练用 torch 是 CPU 版""前端 0 测试""答案正确率未独立验证"。没有评测，所有优化都是凭感觉。

**方案**（主要借鉴 `EasyRoc/edu-rag` 的 `evaluation/`）：
1. **检索评估**：构建"问题 → 应命中文档/题目"的标注集（可先用 20–50 条人工标注起步），算 Recall@K、MRR。
2. **答案评估**：借鉴 **RAGAS**（忠实度/答案相关性/上下文精确度）自动打分。
3. **测试集生成**：借鉴其 `testset_generator.py` 自动从知识库生成测试题，解决"人工标注成本高"。
4. **端到端验收**：平台已有 `tests/smoke_acceptance.py`（后端）——补一条**前端 E2E**（Playwright 已预装）与**答疑质量回归**（固定 50 题，每次改动后跑分对比）。
5. **训练数据收集**：借鉴 edu-rag 的 `training_collector` 节点——把线上问答中"用户追问/纠正"的样本自动沉淀，形成下一轮微调数据（与 `kaoyan_ai` 的 SFT 流程闭环）。
