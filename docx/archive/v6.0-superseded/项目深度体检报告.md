## 七、本次审计发现并修复的问题

### 🔴 Bug 1：`today_duration` 永远是 0

**现象**：仪表盘"今日学习时长"恒为 0。

**根因**：`StudyStats` 表**全项目没有任何写入代码**，
但 `dashboard_service.py` 和 `routers/dashboard.py` 都从它读：

```python
today_stats = db.query(StudyStats).filter(StudyStats.date == today).first()
"today_duration": today_stats.total_duration if today_stats else 0,   # 永远 0
```

而同一函数里的 `week_duration` 却是从 `study_sessions` **正确聚合**的 ——
两处口径不一致。

**修复**：改为与 `week_duration` 一致，直接聚合 `study_sessions`。

**验证**：插入一条 42 分钟会话后 `/api/dashboard` 返回
`today_duration = 42`（修复前恒为 0）。

### 🟠 问题 2：`.bat` 启动脚本带 UTF-8 BOM，cmd 无法执行

**根因**：Windows PowerShell 5.1 的 `Set-Content -Encoding UTF8` **默认写 BOM**，
cmd.exe 把首行 ``锘?echo off`` 当命令，直接报"不是内部或外部命令"。

**修复**：改用 Python 按字节写入（无 BOM + CRLF），
并加了**构建后校验**（读回前 3 字节确认不是 `EF BB BF`）。

### 🟠 问题 3：`timeout /t` 在无真实控制台时失败

**现象**：`ERROR: Input redirection is not supported`。

**修复**：改用 `ping -n N 127.0.0.1 >nul` 做延时（任何上下文都能用）。

### 🟡 问题 4：桌面路径硬编码错误

**根因**：本机桌面被重定向到 **`D:\桌面`**（不是 `%USERPROFILE%\Desktop`）。

**修复**：`create_shortcuts.py` 改为按
`[Environment]::GetFolderPath('Desktop')` → 注册表 → 候选路径 三级兜底。

### 🔴 问题 5：后台模式静默只监听本机

**现象**：用「后台模式」启动后，`netstat` 显示
`TCP 127.0.0.1:8000 LISTENING` —— 手机访问不了。
但 `/api/access-info` 却报告 `host: 0.0.0.0, exposed: true`，**自相矛盾**。

**根因**：`run_server.py` 是独立入口，在读取
`os.getenv("HOST")` 时 **`.env` 还没被加载**（`main.py` 里有 `load_dotenv`，
但后台入口绕过了它），于是退回默认值 `127.0.0.1`。

**修复**：在读取环境变量**之前**显式 `load_dotenv()`。

**验证**：修复后 `netstat` 显示 `TCP 0.0.0.0:8000 LISTENING`，
`http://192.168.10.6:8000/` 返回 200。

> 顺带说明：`main.py` 直接启动**没有**这个问题（它自己加载了 `.env`），
> 只有后台模式受影响。

## 十、优化建议（深度）

### 建议 1：先补知识点的"横向覆盖"（最高性价比）

现在 206 个知识点全在数电模电。**知识地图对其余科目是空壳**。

做法：复用已验证的 `scripts/rebuild_knowledge_base.py` 流程，
对 303 篇数学/英语/政治文档跑一遍结构化解析。
`taxonomy.py` 里的章节大纲（数学 10 节、英语 6 节、政治 5 节）**已经写好了**，
只差执行。

### 建议 2：真题答案用 RAG + 本地模型批量生成，但必须标注来源

1869 题只有 293 题有答案。可从：
1. 已入库的"答案"类文档（文件名含 `答案` 的约 200 篇）抽取
2. 剩余用本地模型生成**并标注"AI 生成，待核对"**

⚠️ **不要直接把 AI 答案当真答案** —— 考研备考错一个答案代价很大。
建议加 `answer_source` 字段区分 `official` / `extracted` / `ai_generated`。

### 建议 3：启用错题闭环（改动最小，收益明显）

`services/error_linker.py` 的 `auto_link_error()` 已实现三级匹配
（名称匹配 → 章节匹配 → 检索匹配），但从未被调用。

只需在错题创建接口里加一行调用，`error_knowledge_links` 就能填起来，
错题本与知识地图立刻联动。

### 建议 4：删除 `study_stats` 表或补齐写入

已修 `today_duration` 绕过它。要么彻底删表（推荐，减少认知负担），
要么加定时任务物化统计。**不要在两者之间摇摆**。

### 建议 5：拆分 `ai_service.py`

1001 行混了：服务商选择、Ollama 调用、云端 API、RAG 检索、
流式输出、测试连接。建议拆成：

```
services/ai/
  __init__.py       对外门面（保持 AIService 接口不变）
  provider.py       服务商选择与降级
  ollama.py         本地调用
  cloud.py          云端调用
  knowledge.py      RAG 检索
  stream.py         SSE 流式
```

### 建议 6：dashboard 去重

`routers/dashboard.py`（245 行）和 `services/dashboard_service.py`（212 行）
是**逐行重复**的两份实现。让路由只做参数校验，
全部计算委托给 service。

### 建议 7：模型放 D 盘 + 设环境变量

```bash
setx OLLAMA_MODELS "D:\ollama-models"
```
C 盘只剩 92.9GB，12GB 模型放 D 盘更稳。

### 建议 8：给前端加最小测试

至少覆盖：学科筛选、知识地图渲染、错题提交。
用 Vitest + Testing Library，不必求全，覆盖关键路径即可。
