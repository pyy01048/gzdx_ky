## 一、架构定稿（单后端 + 轻前端 + 单文件库）

| 层级 | 选型 | 说明 |
|------|------|------|
| 前端 | React 18 + JSX（保留现有工程）+ zustand + 自写响应式 CSS | 保留既有技术积累；Tailwind/TS 渐进引入，不阻塞落地 |
| 后端 | Python FastAPI（唯一服务） | 业务接口、AI SSE 流式、网盘对接、文档解析、定时调度全在此进程 |
| 数据库 | SQLite 3 + SQLAlchemy 2.0 | 单文件便携，单用户性能过剩 |
| 定时任务 | APScheduler（进程内） | 网盘扫描、复习提醒、每日计划，无需消息队列 |
| AI | 统一多服务商封装 + 轻量 RAG | 豆包/DeepSeek/通义千问等可切换；先检索知识库再回答，防瞎编 |
| 部署 | Docker Compose 双容器（前端静态 + 后端）或本地直跑 | 个人本地优先 |

## 二、明确砍掉的冗余
- Express 代理层（FastAPI 原生 SSE）
- Redis 缓存（SQLite 单用户查询毫秒级）
- 独立消息队列（APScheduler 进程内够用）
- 复杂权限系统（单用户免登录/单管理员）

## 三、对既有工程的处置
- `kaoyan-agent-app` 原工程保留不动（已验证基线）。
- `frontend/` = 原 React 工程复制件，作为改造基座，全部模块从 localStorage 迁移为 API 驱动。
- `backend-main-fastapi/` = 参考项目 FastAPI 后端复制件，作为业务后端基座，按极简方案改造（去掉 Express 依赖、补网盘真实 OAuth、补 AI 统一封装、补 APScheduler）。
- Express `server/` 不再作为业务依赖，仅保留 CodeBuddy Agent 的会话/登录接口作可选增强，不纳入主链路。

## 四、P0 核心模块（先做透，做完即可用）
1. 刷题中心：科目-章节-知识点三级分类；顺序/专项/错题重刷三种模式；真题批量导入（Markdown 优先）。
2. 错题本：答错自动收录；错误原因标签；关联知识点；与刷题中心打通看原题详情。
3. SM-2 间隔重复：内嵌统一算法，错题与知识点卡片复用；到期提醒。
4. 驾驶舱：倒计时、今日任务、最近错题、平台连接状态、本周统计、自定义快捷导航；全部真实数据。
5. 三端响应式 PWA 基础框架。

## 五、P1 模块
网盘 OAuth（手动扫描）+ 文档解析入知识库 + AI 统一封装（多服务商/测试/Token 统计/防瞎编 RAG）+ AI 错题精讲 + 对话式 AI 助手 + 任务管理（自定义阶段/模板/打卡/AI 计划）+ 可视化看板 + 文档笔记搜索。

## 六、P2 模块
计时模考、AI 作文批改/长难句、Anki/墨墨数据导入导出、开放 API、背诵音频。

## 七、落地顺序（每步真实可用，无假数据）
- 阶段 1：FastAPI 骨架（异常/日志/配置/ORM/健康检查）→ 前端路由布局 → 题库+刷题+错题真实入库 → SM-2 内嵌 → 基础驾驶舱。
- 阶段 2：网盘 OAuth + 手动扫描入库 → 文档解析（PDF/MD/Word）入知识库 → AI 多服务商面板 + 连通测试 → AI 错题精讲（RAG）→ 对话式 AI 助手。
- 阶段 3：任务管理（自定义阶段/模板/打卡/AI 计划）→ 驾驶舱 UI 精简 + 平台状态卡片 → 数据可视化 → PWA 三端适配。
- 阶段 4：按需扩展（模考/作文批改/其他平台/API/音频）。

## 八、省 Token 与防瞎编硬约束
- 网盘扫描/文档解析默认手动触发；AI 分类默认关闭，点击才运行。
- 学习类问答必须走本地知识库 RAG，命中内容作为上下文传给 AI，答案标注来源。
- 所有 AI 调用统一走封装层，支持自动降级与 Token 用量统计。
