## 7. 各阶段详解

### 阶段 1：OCR 抽取（PDF 为主，这是主干）

**为什么它是主干**：你的 79GB 知识库 PDF 占绝大多数，其中扫描件必须 OCR 才能拿到文字，这些文字是"知识库入库"和"合成数据"的唯一原料。

**它做了什么（关键优化）**：
- **先走 PDF 原生文字层**（PPT 导出/讲义/题库 PDF）→ 毫秒级出全文字，比逐页 OCR 快两个量级
- 文字层不足 30 字的页才**渲染成图做 OCR**（扫描版/混合版）
- 结果按 `digital / hybrid / scanned` 分类打印，一眼看出你的书是扫描版多还是数字版多

**参数怎么理解**：
| 参数 | 默认 | 含义 |
|---|---|---|
| `--workers` | 12 | OCR 是 CPU 密集，A10 实例一般 8~32 核，开满通常比用 GPU 更划算 |
| `--max-pages` | 300 | 单文件页数封顶。红宝书 1655MB、张宇高数 909MB 全抽必超时，教材前 300 页已覆盖主体考点 |
| `--time-budget-min` | 240 | 到点优雅收尾，明天再跑自动接着抽 |

**重要认知：不必一次抽完 79GB。** 抽到 300~500 本合格文本，合成数据已经足够训出好模型（每篇出 3 个种子，500 篇 ≈ 1500 种子 ≈ 万条问答候选）。全量抽完是长期工程，不是今天的阻塞项。

**看什么**：结束时打印 `PDF 类型分布`（digital/hybrid/scanned 各多少）、失败原因分布。失败率高（>30%）通常是扫描质量太差，可接受。

### 阶段 2：题目抽取（含原页配图）★

这是把知识库变成**能刷的题库**的一步，也是你说的"题目有图"的关键。

**做了什么**：
1. 在 OCR 的分页文本里识别题号行（`1.` `1、` `(1)` `1）`），收集后续选项行（A/B/C/D）和答案标注（`答案：B` / `【答案】ACD`）
2. 给每道题打质量等级：**A**（题干+选项+答案齐全，可直接刷）/ **B**（有答案无选项，判断填空简答）/ **C**（有题干没答案，留给本地补）/ **JUNK**（解析行、目录行，直接丢弃）
3. **把题目所在的原页渲染成 PNG**，随题目一起产出——这就是"题目配图"
4. 额外产出视觉训练集 `vl_dataset.jsonl`（题干+原页图→答案），喂给 `qwen2.5vl:7b` 做识图能力训练

**产物**：
| 文件 | 内容 |
|---|---|
| `quiz_out/quiz_questions.jsonl` | 题库记录：题干/选项/答案/题型/页码/配图路径/等级/科目 |
| `quiz_out/quiz_questions.csv` | 同上，Excel 打开方便你人工核对质量 |
| `quiz_out/vl_dataset.jsonl` | 视觉训练集 |
| `question_images/*.png` | 题目原页图 |

**建议先小样验证**：如果不确定抽得对不对，先跑 5 篇看 CSV：

```bash
python3 extract_questions.py --ocr-dir /mnt/workspace/ocr_out \
  --out-dir /tmp/quiz_test --img-dir /tmp/img_test --max-docs 5
# 然后在 VSCode 里打开 /tmp/quiz_test/quiz_questions.csv 核对
```

确认没问题再跑全量。

### 阶段 3：合成数据（7B 当工人）

用同一个 7B 基座（阶段 6 也要用，**只需下载一次**）造 5 类能力数据：主动追问、易混辨析、智能出题、总结提炼、记忆卡片。

设计要点：**问题由程序按模板确定性构造，答案由 7B 依据资料生成**。不让模型自己出题，是为了避免格式崩溃和幻觉；三道质检闸（不得照抄问题 / 长度区间 / 必须提及种子术语）保证不污染。

耗时估算：A10 上 7B 批量生成约 1.5~3 小时（每类 1500 条上限，可调小）。想快点就 `--max-per-kind 600`。

### 阶段 4：合并数据集

把 v3(2484) + 合成 + 抽出的真题（自动转成答疑问答对）合并成一个训练集：去重 → 照抄质检 → 来源配比压制（防止某一类灌顶，默认单来源≤45%）→ 9:1 划分。

看打印的"按来源/按科目"分布：某个来源超过一半就要留意。

### 阶段 5：LoRA 训练

Qwen2.5-7B-Instruct + QLoRA 4bit（A10 上约 11GB 显存）。**只有 assistant 轮进 loss**、按步评估+早停回滚最优——这两条是本地 v3b 训练踩坑换来的，别改。

耗时：数据 8,000~10,000 条时约 1~2 小时。

### 阶段 6：回传 OSS

adapter（~500MB）自动 `cp` 到 `/mnt/data/考研资料数据集/lora_out/final`。**只传 adapter，不传 15GB 合并模型**。

## 11. 故障速查

| 报错/现象 | 原因 | 处理 |
|---|---|---|
| `torch.cuda.is_available()` False | 误跑了 `pip install -U torch`，换成了不兼容 CUDA 的版本 | `bash env_setup.sh --restore` 回滚镜像基线 |
| `No module named 'rapidocr_onnxruntime'` | OCR 依赖缺失 | `pip install rapidocr-onnxruntime pypdfium2 pillow` |
| `PDFium: File access error` | pypdfium2 文档句柄未释放 | 已是 spawn 多进程+逐页 close，一般不会犯；若出现请贴日志 |
| OCR 跑了很久才出第一篇 | 第一篇可能是超大扫描件 | 正常；用 `ls ocr_out | wc -l` 看累计 |
| 合成阶段 `CUDA out of memory` | 批量太大 | `SYNTH_BATCH=4 bash run_everything.sh` |
| 训练 OOM | bf16 模式吃紧 | 默认就是 4bit；若用 `--no-4bit` 请去掉 |
| 题目抽出 0 条 | 试卷排版题号形式没覆盖 | 用 `--no-images` 抽文字看 CSV 排查；题号形式特殊可反馈，我加正则 |
| git clone 慢/失败 | DSW 到 GitHub 偶发不通 | 重试；或改用 OSS 上传（README 有方式） |
