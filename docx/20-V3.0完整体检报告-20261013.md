## 三、后端代码逐字逐句审查（10 项）

### 3.1 ✅ prefer 签名已对齐（19 号问题 4 已修）

**结论**：19 号问题 4 已修复。

### 3.2 ❌ check_batch 循环未透传 prefer（新 bug）

[services/answer_cross_check.py](file:///D:/平台/backend-main-fastapi/services/answer_cross_check.py#L437-L448) `check_batch` 函数签名有 `prefer`，但循环里：
```python

```
**影响**：批量接口虽然签名对了，但实际每条题都用默认 prefer，单题和批量的 prefer 行为不一致——**这是 19 号修复时漏掉的"半修"状态**。
**修复**：补 `prefer=prefer` 参数透传。

### 3.3 ❌ check-batch 超时只是把阈值调高（19 号问题 5 未真修）

[utils/timeout_guard.py](file:///D:/平台/backend-main-fastapi/utils/timeout_guard.py#L45-L56) 把 `/api/answers/check-batch` 写请求阈值放宽到 **600 秒**。
[L143-L149](file:///D:/平台/backend-main-fastapi/utils/timeout_guard.py#L143-L149) `_timeout_for` 按路径前缀匹配专用阈值。
**结论**：19 号问题 5（6992 秒超时）**没有真正修复**——只是把阈值从 60s 放宽到 600s，让超时晚点发生；6992 秒的极端慢仍然会触发，且 600 秒也远超用户体验阈值。
**修复**：改为异步任务队列（提交任务返回 task_id，前端轮询 `/api/answers/check-batch/status/{task_id}`）。

### 3.4 ⚠️ AI Key 兜底有但默认引擎仍可能无 Key

[services/ai_router.py](file:///D:/平台/backend-main-fastapi/services/ai_router.py#L366-L407) 所有引擎失败时返回"所有 AI 引擎都暂时不可用"——**这是兜底**。
但：①前端默认引擎是"自定义 AI API（SSE 流式）"②`.env.example` 里 `DEEPSEEK_API_KEY` 注释③用户 .env 实际配置未知。
**结论**：兜底逻辑有，但默认引擎选择策略不对——应该"启动时检测无 Key 自动切到本地 Ollama 默认"。

### 3.5 ⚠️ AI 答非所问（系统提示词问题）

## 五、优秀平台应具备的优点（结合本平台实际，详细版）

> 18 号报告已给 7 条优点，本节做**更详细的展开 + 验收标准 + 当前差距**三件套。

### 优点 1：专业课本位——电路图/波形/公式是"一等公民"

**为什么对你成立**：通用考研平台（kaoyan.cn、考研帮）做不了电路图深解析（用户是几百个专业）；你只服务数电/模电，**电路图识别、波形分析、公式 LaTeX 化就是护城河**。

**具体做法（详细到模块）**：
- **电路图识别**：上传/截图 → 检测元件（R/C/Q/Op-Amp 位号）→ LLM 结构推理（已有 `services/circuit_analysis.py` + `services/circuit_vision.py` 基础）→ 输出结构化网表
- **波形分析**：分段识别（方波/三角/正弦）→ 标注时间常数 τ、幅度 V_pp → 结合题目讲"为什么是积分波形"
- **公式 LaTeX 化**：OCR 后公式区域用 KaTeX 渲染，可点击查看"每一步推导"
- **解题输出**：拍照一道模电计算题，10 秒内给出"图识别结果 + 结构化解题步骤"，不是一段文字猜测

**验收标准**：
- 上传一道含三极管放大电路的题，10 秒内输出：①识别出的元件清单 ②Q 点计算公式 ③数值结果 ④答案引用出处
- 错误率 < 10%（与人工对照）

**当前差距**：★★（满分 5）—— `circuit_analysis.py` 已存在但未端到端打通到 AI 助手；前端 `Assistant.jsx` 未集成"上传图片"入口。

---

### 优点 2：学习闭环——但闭环的"节拍器"是 834 知识点

**为什么**：通用平台闭环是"刷题→错题→复习"；你的闭环必须挂载在 **834 知识点树**上（如：三极管放大电路→静态工作点→Q 点计算），因为考研复习按知识点推进。

**具体做法**：
- 每道题关联知识点（已有 `kp_links` 6288 条）→ 做题记录按知识点聚合正确率
- 薄弱知识点（`weak_knowledge` 表）→ 自动生成"今天补哪个知识点、练哪几道题"
- 复习调度用 FSRS（08 报告已调研，pip 直装），**复习单元是知识点卡片 + 代表题**，不是裸题
- 错题卡 = 题干 + 我的错误选项 + 正确解法 + 关联知识点 + 变式题

**验收标准**：
- 做错一道"Q 点计算"题 → 系统自动加到"三极管放大电路"知识点的复习队列
- 7 天后复习时不止给原题，还给 2 道变式（同知识点不同数值）
- 掌握度从 30% 涨到 70% 时，复习间隔自动拉长

**当前差距**：★（大）—— 19 号问题 7"掌握度全 0"未修，闭环根本没跑起来；FSRS 未引入；变式题未生成。

### 优点 3：AI 助教——但必须"读得懂专业课"

**为什么**：通用 AI 问答任何平台都能接 GPT，没有价值；你的 AI 必须 ①记得你上周卡在哪道题 ②能引用你知识库里的教材原文 ③会看电路图。

**具体做法**：
- **会话记忆持久化**：表 `ai_sessions`（id, user_id, messages JSON, last_active），AI 助手页打开自动恢复上次会话
- **检索必须来自你的 1846 篇文档**（不是全网），答案带出处（文件名 + 页码 + 片段）
- **电路图/公式走视觉管线后再讲**（07 方向二 Tutor）
- **三 Agent 分工**：Tutor（专业课答疑）+ Planner（计划生成）+ Radar（院校情报），不要 8 个 Agent 臃肿

**验收标准**：
- 问"KVL 是什么"→ AI 回答：①KVL 定义 ②公式 ΣU=0 ③举例（带电路图）④引用你知识库第 X 页
- 不出现"1. 明确考查目标 2. 拆成可执行的小步骤..."这种规划类套话
- 切换会话能记住上周问过的题

**当前差距**：★★★（中）—— RAG 检索已有；但 19 号问题 2 "答非所问"未修；会话记忆未持久化；电路图未集成到 Assistant。

### 优点 4：院校数据——真、准、随时更新，但不做"信息大而全"

**为什么**：kaoyan.cn 的核心是"信息聚合"（分数线/报录比/经验贴），那是它靠商业团队运营的护城河；你一个人做不了全网院校运营，**硬抄它的广度=自杀**。你的优势是**聚焦**：0854 电子信息相关院校，把 50~100 所目标院校的数据做深做准。

**具体做法**：
- **聚焦 0854 相关 50~100 所**（已有 493 所基础，按"是否有电子类硕士点"过滤）
- **分数/招生/公告自动爬取** + **版本留痕** + **同比批注**（"今年比去年扩招 5 人"）
- **择校决策从"查得到"升级为"算得清"**：你的预估分 → 冲/稳/保三档 + 概率区间（已有 `score_insight` 基础）
- **公告过滤收紧**：博士录取、非 0854 专业录取通知一律不进首页公告栏

**验收标准**：
- 输入预估分 320 → 系统给"冲 3 所 / 稳 5 所 / 保 2 所"三档清单，每所附"胜率 65%"概率
- 公告栏 0 条博士录取、0 条非电子类专业
- 院校详情页"今年招生人数"旁标"↑5（vs 2025）"同比箭头

**当前差距**：★★（中）—— 493 所基础好；但 19 号问题 11"公告混入博士"未修；冲稳保概率模型未端到端打通。

### 优点 5：多语言刷题 + 复试——但聚焦"电子信息复试真考什么"

**为什么**：leetcode 是全栈工程师题库（C++/Python/Java 全要），你是电子信息考研，复试机试通常考 **C 或 Python**（少数学校 C++），面试考专业课概念 + 项目。

**具体做法**：

**验收标准**：

**当前差距**：★（大）—— 复试题库未建；只设计了字段未落地。
