> **定位**：在 `07-考研备考系统深刻优化方向报告.md` 五大层方案基础上，按用户点名的**四个参考网站**（txkyer / kaoyan.cn / codebrick / leetcode.cn）深化每一层的**界面结构、数据模型、交互方式与接口契约**。
> **编制**：2026-10-11 ｜ **重要**：本文**只做方案，不写代码**；执行顺序见「八、落地优先级路线图」。

## 三、院校库深化（抄 kaoyan.cn，三大页 + 公告）

### 3.1 院校列表页（school-list 模式）
**筛选项三组**：
| 组 | 选项 | 数据来源 |
| :--- | :--- | :--- |
| 地区 | 全部 / A区（22省）/ B区（10省）/ 香港 / 澳门 | 院校表 province 字段 + 区划映射 |
| 类型 | 综合/理工/农林/医药/师范/语言/财经/政法/体育/艺术/民族/军事/其他 | 院校表 type 字段 |
| 特色 | 985 / 211 / 双一流 / 自划线 / 高等院校 / 科研院所 | 院校表 tags 字段 |

**列表卡片**：校徽 + 名称 + 省份 + 标签（211 985 双一流）+ 类型 + 快捷按钮（简章/分数线/问招办）
**新增字段**：院校表需补 `region(区)`、`tags(JSON 特色标签)`、`hot_value`、`hot_change`、`logo_url`

### 3.2 院校详情页（school/198 模式）
信息架构（从上到下）：
1. **头部卡**：校徽、名称、省份、人气值、类型标签、官方网址/电话/邮箱
2. **Tab 导航**：学校概况 / 招生直播 / 招生信息 / 复试分数线
3. **学校概况**：简介 + 高校排行（软科/校友会/US 三榜）+ 基本信息（一级博士点/硕士点/国家重点学科/重点实验室/创建时间/隶属/面积/地址）+ 校园风光图
4. **新增字段**：院校表补 `intro`、`rank_soft/rank_alumni/rank_us`、`phd_count/master_count`、`national_key`、`lab_count`、`founded`、`affiliation`、`area_mu`、`address`、`gallery(JSON 图集)`

### 3.3 招生计划页（school/198/plan 模式）
- 按院系→专业方向→招生计划明细：拟招人数、考试科目（政治/外语/业务课一/业务课二）、学制、备注
- 表格化展示 + 年份切换（2025/2026/2027）
- 数据源：`enrollment_plans` 表扩展（补 `exam_subjects JSON`、`duration`、`note`）

### 3.4 历年分数页（school/198/score 模式）
- 年份切换器（2023~2026）+ 各专业复试线/录取线表格
- **同比批注（用户点名）**：每行分数后批注 `↑12 / ↓5 / —`（对比前一年）+ 涨跌箭头着色
- 数据源：`score_lines` 表已有 810 条，加计算列 `yoy_change`（查询时对前一年做差）

### 3.5 公告爬取链路（school/198/news 模式）
- 目标：从各院校官网/研究生院"招生信息""复试分数线"栏目定时爬取
- 链路：爬虫（已有 kaoyan_spider 基础）→ 正文抽取 → 相似去重 → 入库（announcements 表补 `source_url`、`published_at`、`content_hash`）→ 首页"当日更新"展示
- **主页公告界面（用户点名）**：首页保留公告栏，按日期分组展示"当日哪些院校更新了信息"，点击进院校详情

## 四、刷题中心深化（抄 codebrick + leetcode）

### 4.1 知识点全景刷题模式（codebrick panorama）
- 左侧：知识点树（章节→知识点），带正确率环/进度条
- 主区：选中知识点的题目流（先选后提交 + 即时反馈）
- 右侧：该知识点考频小图 + 相关错题
- 数据：已有 kp_links 6288 条 + 做题记录聚合

### 4.2 考频分析页（codebrick exam-strategy）
- 按知识点维度统计：历年出题频次、年份分布、题型分布
- 呈现：热力图 / 柱状图 / 折线图（ECharts）
- 数据：真题套卷 3008 题按知识点聚合出题频次表 `topic_freq(kp_id, year, count)`

### 4.3 力扣式刷题页（leetcode problemset + problem detail）
**题目列表页**：
- 左侧分类栏（知识点/难度/题源：力扣/考研真题/复试真题）
- 表格：题号 | 标题 | 难度（简单/中等/困难）| 通过率 | 我的状态（未做/已做/AC）
**题目详情页**（leetcode problem 模式）：
- 左栏：题目描述（含公式 LaTeX/代码块）+ 示例 + 约束
- 右栏：讨论/题解 + 提交区（语言选择：C++/Python/C/Java → 本地代码高亮编辑器 + 提交判题）
- 判题：本地判题服务（sandbox 子进程编译运行 + 用例比对），参考 LeetCode 单测用例设计

### 4.4 多语言复试题库（用户点名重点）
- 题目覆盖 **C++ / Python / C / Java** 四种语言
- 内容来源：①网上获取复试机试真题（C++/Python/C/Java）②你提供粘贴文本 + 我爬取知识点整理成题
- 题型：编程题（LeetCode 式）+ 选择题（408 式）+ 概念题（复试问答式）
- 数据表：`problems` 扩展 `lang_support JSON`、`judge_cases JSON`、`source`（leetcode/kaoyan/fushi/manual）

### 4.5 复试专项刷题库（新增模块）
- 复试科目题库：专业综合面试题、英语口语题、机试编程题
- 知识点爬取：从院校复试细则/经验贴爬取"复试范围知识点" → 整理入库 → 供刷题
- 界面复用力扣式刷题页 + 知识点全景模式

## 六、学习科学引擎深化（GitHub 实测调研结论）

> 本节来自对 GitHub 头部项目的实测侦察（均已验证可 pip 安装/可参考），**抄机制不抄界面**。

| 借鉴对象 | 星数 | 抄什么 → 怎么接 |
| :--- | :--- | :--- |
| **py-fsrs**（open-spaced-repetition） | 507★ | `pip install fsrs`，Scheduler/Card/Rating/ReviewLog 四件套 → 写适配层灰度替换 SM-2，零算法自研，benchmark 全面优于 SM-2 |
| **pyBKT**（伯克利官方） | 283★ | `pip install pyBKT`，Model().fit/predict → 掌握度从"1-错误率"升级为贝叶斯知识追踪；设数据量门槛（每知识点 ≥20 条作答）+ 旧公式 fallback |
| **open-rag-eval**（Vectara） | 412★ | 不整库引入，抄指标定义：忠实度/相关性/完整性三指标 → rag_eval_log 表 + 周期离线评测 → 检索质量看板 |
| **Duolingo HLR 论文** | — | 单词卡 4569 词个体化遗忘：p = w₀/(1+e^(−Σwᵢxᵢ))，sklearn 逻辑回归即可训练 |
| **组合先例** | — | GitHub 实测存在 "IRT 出题 + BKT 掌握 + FSRS 复习"三件套同构项目 → 证明本路线工程可行 |
| **商业机制** | — | Khan（精通四档+连对门槛）、Quizlet（按掌握度升级题型）、Anki（日志可回放重算）、猿题库（难度动态校准）——抄机制不抄界面 |

**关键修正（相对 07 报告）**：
- M1 不再等任何东西：FSRS/BKT 均为 pip 直装成熟库，全部云端可开发可测试——原计划"深度要等真机 GPU"被推翻
- M1 落地顺序：适配层 → BKT 接 weak_knowledge → Elo 内核 → replay 回放验证 → 首页能力卡，约 3 天

## 七、数据自动导入（用户点名：从院校公布数据识别导入）

### 7.1 目标
院校的分数线/招生计划/公告，**随时从各大院校公布的数据识别并导入平台**，不手工录入。

### 7.2 链路
```
院校官网/研究生院/研招网公开页
  → 爬虫采集（kaoyan_spider 扩展，支持各校页面结构）
  → 内容识别（LLM 抽取结构化字段：院校/专业/分数线/拟招人数/考试科目/公告）
  → 质量校验（字段完整性 + 与历史对比合理范围）
  → 去重合并（content_hash / (school_id, year, major) 唯一键）
  → 入库 + 打时间戳（更新记录表，首页公告栏可查"当日更新"）
  → 版本留痕（score_lines 保留历史版本，支持同比批注）
```

## 九、给智谱清言 / GLM 的续写要求

1. **本文是深化底座**，保持"抄功能类型不抄风格"原则，界面沿用现有学术蓝风格。
2. **学科零硬编码**：所有科目/知识点/院校标签由表驱动，可添加。
3. **院校数据必须真实**：分数线/招生计划来自公开来源识别导入，不做假数据；同比批注用真实历史对比。
4. **执行顺序按第八节**：先 P0（学科可扩展 + 院校三页 + 公告 + panorama），再 P1，逐项验收。
5. **铁律**：不批量改库 / 改数据先备份 / 删除走回收站 / 禁 git add -A / AI 生成可溯源不编造 / 不并行改同一批文件。
6. **真库**：`D:\平台\database\kaoyan.db`；`backend-main-fastapi/data/kaoyan.db` 是诱饵勿信。
7. **文档联动**：每完成一个模块，回写本文档（勾选状态）并在 docx/README 登记。
