## 0. 我们在造什么

一个**本地部署**的考研备考平台：后端 FastAPI + 前端 React 18 + PostgreSQL 真库 + Ollama 本地推理；重算力任务（训练、OCR）放到阿里云 PAI-DSW（A10 24GB）上做；两边通过 GitHub（代码与数据集）和 OSS（产物）交换。

**不是**做一个聊天机器人。目标是让平台这四件事真正有内容、有智能：

| 功能域 | 现在的状态 | 目标 |
|---|---|---|
| 知识库 | 135 篇文档 / 4024 文本块 / 500 知识点 | 79GB 原始资料挖进去，chunks 上 3 万，KP 上 1500 |
| 题库 | **0 题**（丢失） | 从原始资料重新抽出可刷题，且**带原页配图** |
| AI 答疑 | v4（3B LoRA）在跑 | 7B LoRA，覆盖 9 项生成能力 |
| 学习闭环 | 各模块孤立 | 新资料 → 入库 → 合成数据 → 重训的周级飞轮 |

一句话概括技术路线：**云端负责"造数据 + 训模型"，本地负责"存数据 + 跑模型 + 给用户用"。**

## 2. 目标定义：模型要干什么（能力全景 13 项，四层）

学生视角的完整需求不止"答疑"。按**实现层**分四类，避免把一切塞给大模型：

### 第一层：理解与应答（模型生成，进 LoRA）

| # | 能力 | 输入 → 输出 |
|---|---|---|
| C1 | 答疑 | 学生提问（可带检索上下文）→ 引导式讲解 |
| C2 | 讲题 | 题目+选项+学生答案 → 判定+分步解析+错项分析 |
| C3 | 错题归因+变式 | 错题+错解 → 归因知识点 + 变式题 |
| C4 | 批改 | 学生解答 → 判定+扣分点+正确路径 |
| C5 | 主动追问（苏格拉底） | 概念问题 → 先反问定位盲点，再讲解 |
| C6 | 易混辨析 | 两个相近概念 → 对比表+判定方法+典型错例 |

### 第二层：生成与生产（模型生成，进 LoRA）

| # | 能力 | 输入 → 输出 |
|---|---|---|
| C7 | 智能出题 | 知识点+题型+难度 → 新题+答案+解析 |
| C8 | 总结提炼 | 章节/多文本块 → 结构化笔记 |
| C9 | 记忆卡片 | 知识点 → 问答卡片（SM-2 格式） |

### 第三层：识别与视觉（管线 + 独立视觉模型）

| # | 能力 | 实现 |
|---|---|---|
| C10 | 题目/资料识别 | OCR → 分类 → KP 挂靠（smart_ingest + chunk_classifier + quiz_quality_gate） |
| C11 | 识图作答 | `qwen2.5vl:7b`，先 RAG 直接用，后期单独 LoRA |

### 第四层：规划与自治（产品逻辑 + 定时管线）

| # | 能力 | 实现 |
|---|---|---|
| C12 | 学习规划 | SM-2 算法排程 + 模型生成计划文案 |
| C13 | 自主学习飞轮 | 新资料 → OCR → 入库 → KP → 图谱 → 合成数据 → 定期重训 |

> **明确不做成模型能力**（属产品逻辑）：督学提醒、学习统计看板、进度跟踪、已读未读——这些是 CRUD + 规则，别浪费训练数据。

## 3. 技术路线

### 3.1 架构决策：一个模型 + 三条管线 + 产品层

```
LoRA 模型（Qwen2.5-7B，Ollama Q4 本地部署）   ← 学 C1–C9 九项生成能力
    训练地：DSW（A10 24GB）   部署地：本地 Ollama
─────────────────────────────────────────────
视觉模型（qwen2.5vl:7b）                      ← C11 识图作答
─────────────────────────────────────────────
管线层（本地 Python，不训练）                  ← C10 识别入库 / C12 SM-2 / C13 飞轮
─────────────────────────────────────────────
产品层（FastAPI + React）                     ← 按功能位选 prompt 模板 + 是否挂 RAG
```

**为什么 9 项进同一个模型**：共享同一套"辅导老师"人格与知识，数据格式同为 ChatML，一次训练全获得。分开训 9 个模型既浪费部署资源又丢上下文。

### 3.2 训练策略

| 项 | 选型 | 理由 |
|---|---|---|
| 基座 | `Qwen/Qwen2.5-7B-Instruct` | DSW 一次性训（免费额度内），本机只承担推理 |
| 量化 | **QLoRA 4bit nf4**（默认） | A10 上约 11GB，余量足；`--no-4bit` 切 bf16（约 19–21GB，贴顶） |
| LoRA | r=16, α=32, dropout=0.05，全投影层 | 与本地验证版一致 |
| batch/accum | 2 / 8（有效 16） | 可调，A10 有余量 |
| max_len | 1024 | 样本 p95=662 |
| epochs / lr | 3 / 1e-4 cosine | 小数据集 + 早停（patience=3） |
| 评估保存 | 按步，每轮 4 次，保留最优 | 按 epoch 评估会白跑一轮过拟合（v3b 教训） |

**版本节奏与门槛**：

| 版本 | 触发 | 数据量 | 门槛 |
|---|---|---|---|
| v3 | 题库恢复 + 知识库清洗完 | 2,500+ | 照抄率 <0.15；不劣化 v4 |
| v4 | 合成数据两轮后 | 6,000–9,000 | 照抄率 <0.10；人工抽检 20 条通过率 >80% |
| v5 | 上线运行 1 个月 | 10,000+ | 同 v4 + 历史问题复答率 |

**上线纪律**：每版用新 tag，对照评测通过后才切换模型名，**不覆盖在跑模型**。

### 3.3 数据战略：四个来源

| 源 | 内容 | 规模预期 | 状态 |
|---|---|---|---|
| **A 题库** | 真题 + 标准答案 → 答疑/讲题/归因 | 3,000–6,000 | ⛔ 断供（题库丢失） |
| **B 知识库** | KP 释义 + chunks → 概念问答 | 2,000+ | ✅ v3 已产出 2,484 |
| **C 合成** | 7B 按 5 类能力模板造 | 6,700 | ⏳ 待云端生产 |
| **D 用户历史** | 答疑会话中有效轮次 | 增量 | 🔶 v5 起 |

**配比原则**：题库质量最高但受限（约 30–40%），合成补规模（≤50%），历史补"真实问法"。

### 3.4 训练质量红线（本地踩坑换来，不得改）

1. **只有 assistant 轮进 loss**（prompt 掩码）——否则模型学复述题目，v2 之前照抄率 0.72
2. **截断后无学习目标的样本剔除**——labels 全 -100 会让交叉熵返回 NaN 毁掉整轮训练
3. **`use_reentrant=False` 双处开关一致**——peft 与 TrainingArguments 两套开关叠加会丢梯度
4. **照抄检测 n 随问题长度自适应**——固定 n=16 时，v3 的 17 字短问题根本测不出复读（本轮实测修复的 bug）
5. **早停 + 回滚最优 checkpoint**——小数据集第 3 轮多半过拟合

## 4. 云端执行方案（DSW 一条龙）

### 4.1 职责边界

| 环节 | 位置 | 理由 |
|---|---|---|
| OCR 文本抽取 | ✅ 云端 | A10 快得多；只做"文件→文字"，产物写 JSON 传 OSS |
| 题目抽取 + 原页配图 | ✅ 云端 | 渲染 PNG 是重活 |
| 合成数据生产 | ✅ 云端 | 7B 批量生成，GPU 密集 |
| LoRA 训练 | ✅ 云端 | 7B 只有 A10 训得动 |
| **融合 merge** | ❌ 本地 | 只回传 500MB adapter，传 15GB 合并模型是浪费 |
| 入库写库 | ❌ 本地 | DSW 连不到 PostgreSQL |
| Ollama 部署/评测/集成 | ❌ 本地 | — |

### 4.2 七阶段流程

```
[1/7] 环境体检   env_setup.sh（只补缺失，绝不 -U 核心包）
[2/7] OCR 抽取   ocr_extract.py —— 文字层优先，扫描页才 OCR；断点续跑+页数封顶+时间预算
[3/7] 题目抽取   extract_questions.py —— 题干/选项/答案 A/B/C/JUNK + 原页渲染 PNG + 视觉训练集
[4/7] 合成数据   gen_synthetic.py —— 7B 当工人，5 类能力（追问/辨析/出题/总结/卡片）
[5/7] 数据合并   merge_dataset.py —— 去重 + 照抄质检 + 来源配比压制（单源 ≤45%）
[6/7] LoRA 训练  preflight.py 体检 → train_dsw.py（7B + QLoRA 4bit）
[7/7] 回传 OSS   push_checkpoint.sh —— adapter 500MB → /mnt/data/考研资料数据集/lora_out/final
```

每阶段可 `SKIP_OCR=1` / `SKIP_SYNTH=1` / `SKIP_QUIZ=1` 跳过，可断点续跑。

### 4.3 两个关键设计

**（1）PDF 文字层优先**：知识库 PDF 占绝大多数，其中数字版（PPT 导出/讲义/题库 PDF）带文字层，直接 `get_text_range()` 取字毫秒级，比逐页 OCR 快两个量级；只有文字层不足 30 字的页才渲染 OCR。产物按 `digital / hybrid / scanned` 分类打印。

**（2）题目必须带图**：用户明确要求"题目有图，没图做题库没用"。对每道抽出的题目，用 pypdfium2 把它**所在原页渲染成 PNG** 随题产出；OCR 产物因此保留 `pages_text` 分页信息，供题目映射回原页。

### 4.4 产物清单

| 产物 | 位置 | 用途 |
|---|---|---|
| 知识库文本 | `ocr_out/*.json`（含分页） | 传回本地 → `knowledge_chunks` |
| 题库记录 | `quiz_out/quiz_questions.jsonl` + `.csv` | 传回本地 → `quiz_questions` |
| 题目配图 | `question_images/*.png` | 随题目入库，前端显示原题页图 |
| 视觉训练集 | `quiz_out/vl_dataset.jsonl` | 喂 `qwen2.5vl:7b` |
| 最终训练集 | `train_data_v4/` | 备份 |
| adapter | `lora_out/checkpoints/final/` | → OSS，本地下载后 merge |

### 4.5 三档速度

| 档位 | 命令 | 耗时 | 得到 |
|---|---|---|---|
| ⚡ 快档 | `SKIP_OCR=1 SKIP_SYNTH=1 bash run_everything.sh` | ~40 分钟 | v3(2484) → 7B 答疑模型 |
| ★ 标准档 | `OCR_BUDGET_MIN=240 bash run_everything.sh` | 4–6 小时 | 知识库文本 + 题库(配图) + 合成 + 训练 |
| 🔬 完整档 | `OCR_BUDGET_MIN=720 bash run_everything.sh` | 10–14 小时 | 尽量抽完 79GB |

> **不必一次 OCR 完 79GB**：抽到 300–500 本合格文本，合成数据已足够训出好模型。全量抽完是长期工程，不是今天的阻塞项。

## 5. 本地执行方案

### 5.1 入库（题库 + 知识库）

云端只出产物，写库必须本地做。产物字段已按库表组织：

- `ocr_out/*.json` 的 `text`（带页标记）→ `knowledge_chunks` 的 `text` + `page_start/page_end`

### 5.3 网站集成

每个能力一个 prompt 模板 + 路由（C1 挂 RAG、C2 挂题干、C7 不挂）；C12 接 SM-2（`ebbinghaus_items` 表已在）；C13 用 APScheduler 每周扫新资料 → 入库 → 增量合成 → 累积到阈值触发重训。

**关键纪律**：训练数据的 system prompt 与推理时的 system prompt **逐字一致**——不一致是效果打折的隐形杀手。

## 9. 铁律（执行时不得违反）

1. **备份数据库只能**用 `services/backup_service.py::create_backup()`，严禁 cp/shutil.copy 复制 .db
2. **删除记录前**过 `services/delete_guard.py::require_physical_delete_enabled`
3. **科目唯一来源**：`services/subject_registry.py`，不新造科目字典
4. **git 禁用** stash/reset/checkout/restore；提交前 `git status` 确认只有自己的文件
5. **DSW 上禁** `pip install -U` 核心包（torch/transformers/peft），缺什么补什么
6. **训练数据只从 JSONL 读**，不直连数据库训练（数据库在本地，DSW 够不着）
7. **adapter 回传 OSS，不传 15GB 合并模型**——merge 在本地做
8. **合成数据**必须过照抄门禁 + 出题类人工抽检，不抽检不上训
9. **模型上线用新 tag**，对照评测通过才切换，不覆盖在跑模型
10. **真库判断一律以 PostgreSQL 为准**，两个 .db 都是诱饵库
