## 一、🔴 致命问题 1：AI 助手"检索到引用、但不回答"（API 引擎失效）

**实测过程**（浏览器可复现）：
1. 进入 AI 助手页（`#/assistant`），默认引擎显示"自定义 AI API（SSE 流式）"
2. 输入"三极管放大电路的静态工作点怎么计算？"→ 点击发送
3. 等待 40 秒+ → 页面显示"📎 本轮引用 · 本地知识库 6 条命中"，但**没有任何 AI 回答正文**
4. 网络请求：`/api/ai/rag-search` 返回 ok，但生成正文的调用没有发生

**根因**（已查证）：
`backend-main-fastapi/.env` 中 `DEEPSEEK_API_KEY` 和 `CODEBUDDY_API_KEY` **均被注释**（`# DEEPSEEK_API_KEY=...`），而前端引擎默认是"自定义 AI API（SSE 流式）"——后端检索完知识库后，调用 LLM 生成时**没有可用 API Key**，直接静默失败，前端只显示引用不显示正文。

**影响**：平台最核心的 AI 答疑功能**实际不可用**。用户问问题 → 只看到"引用了哪些文档"→ 没有任何答案。这是"体验感差"的第一大原因。

**修复方向**：
- 在设置页配置可用的 API Key（DeepSeek/其他兼容 OpenAI 的接口），或
- 默认引擎改为"本地 Ollama"（已验证可用），API 仅作可选项

## 二、🔴 致命问题 2：AI 本地引擎"答非所问"（模板套话）

**实测过程**：切换到"本地"引擎（Ollama），输入"什么是KVL基尔霍夫电压定律？"

**AI 实际回复**：
> "收到。这个问题先帮你拆解一下：1. 明确考查目标：结合你当前复习阶段（距考试 438 天），建议先回归教材/真题定位；2. 拆成可执行的小步骤，同步到「任务打卡」里；3. 相关错题可收录进「错题本」，我会按艾宾浩斯帮你安排复习。你可以更具体地描述问题……"

**问题**：回复是**规划类模板套话**，完全没有回答"KVL 是什么、公式怎么写、怎么用"——这是把"答疑引擎"和"规划引擎"混用了，或提示词没约束"必须回答本题"。

**影响**：即使配好引擎，用户得到的是"正确的废话"，不是知识讲解。

**修复方向**：检查 AI 路由器的系统提示词——答疑模式下必须"直接回答本题 + 给出公式/步骤"，规划内容仅作为补充；模型分级（7b 主答 → 3b 兜底）需在答疑场景真正生效。

## 三、🔴 致命问题 3：错题/题库 OCR 污染（水印广告 + 科目错乱）

**实测截图证据**（错题复盘页 `#/error-review`，共 39 条错题中大量出现）：

**3a. 水印广告混入题干**：
```
"东坡哥微信：haidongpo8 微信公众号：电子与通信工程考研 第13页 --- 第14页(OCR) --- 水木观畴，你身边的考研专家！"
```
出现在**至少 5 条错题**中，作为题干的一部分展示。

**3b. 题库管理页广告残留**（政治题里）：
```
"6 公众号；考研糖 公众号【研池大叔】，免费分享考研干货！"
```

**3c. 科目分类错乱**——"数字电子技术"分类下混入：
- 数学题："已知曲线L:y=α(x-1)x-7)，则能确定实数α的值…"
- 逻辑推理题："三、逻辑推理（本大题共30小题…）"
- 刑法数罪并罚题（题库管理"真题综合"分类下）

**3d. OCR 乱码**：`a  2 b ≤ 1`、`2.3    a 2`（Unicode 乱码字符）

**根因**：题库/错题数据来自 PDF 扫描件 OCR 导入，导入时**没有清洗**：
- 未过滤页眉/页脚/水印/公众号广告
- 未做"题目分类校验"（解析后科目标签错误）
- OCR 特殊字符未映射

**影响**：刷题/复习看到的是**充满垃圾的题干**——用户瞬间失去信任。这是"题库体验差"的直接原因。

**修复方向**：
- 数据清洗脚本：正则过滤广告/水印/页眉页脚（`微信|公众号|考研专家|第\d+页\(OCR\)` 等模式）
- 已入库脏题批量清洗（逐条扫描 9171 题）
- 加"题目分类校验"：解析出的科目与选项结构自检
- OCR 后处理：乱码字符映射表

## 四、🔴 严重问题 4：后端 500 错误（代码与签名不匹配）

**错误日志实证**（`server_restart_err.log`）：
```
File "D:\平台\backend-main-fastapi\routers\answers.py", line 33, in cross_check
    result = answer_cross_check.cross_check_question(db, req.question_id, prefer=req.prefer)
TypeError: cross_check_question() got an unexpected keyword argument 'prefer'
```

**根因**：`routers/answers.py` 调用了 `cross_check_question()` 但传了 `prefer` 参数，而**服务函数签名里没有这个参数**——典型的"改路由没改服务"或"两个 AI 协作留下的不一致"。

**影响**：答案交叉核对接口（`/api/answers/...`）直接 500，题库答案核对功能不可用。

**修复方向**：对齐 `answers.py` 与服务函数签名（补参数或删调用）；加接口冒烟测试。

## 五、🔴 严重问题 5：批量接口超时（最慢 6992 秒 ≈ 1.9 小时）

**错误日志实证**（`server.log`）：
```
ERROR | 请求超时，已中断并返回 504: POST /api/answers/check-batch - 超过阈值 60s
（实际 2689.4ms / 2962.6ms / 6992.3ms / 6372.9ms / 1577.6ms / 1581.9ms / 5092.1ms / 5004.3ms）
WARNING | 慢请求: POST /api/answers/check-batch - 500495.2ms (阈值 3000ms)
```

**根因**：答案批量核对接口对整批题目串行调 LLM，单批耗时分钟级~小时级，远超 60s 超时阈值。

**影响**：批量回填答案/解析功能**每次必然 504**，答案覆盖率（33%）提不上去。

**修复方向**：改异步任务队列（后台执行 + 进度查询）；或分片（每批 ≤10 题）+ 前端轮询。

## 六、🟠 严重问题 6：数据口径互相矛盾（三个题数）

**实测证据**：
| 页面 | 显示题数 | 来源 |
| :--- | :--- | :--- |
| 题库管理页 | **3402 道** | "共 3402 道" |
| 刷题中心 | **5525 题** | 题库总量 |
| 01 文档 | **9171 题** | database/kaoyan.db 实测 |

**根因**：三个统计口径不同且未统一——3402（可能只统计有答案的）、5525（某筛选条件下的）、9171（全库）。前端没有标注口径。

**影响**：用户看到前后矛盾的数字，对数据信任度下降；后续 AI 开发也会被误导。

**修复方向**：统一为"全库题数 + 有答案数 + 有解析数"三指标并列，接口标注统计口径。

---

## 七、🟠 严重问题 7：掌握度体系全 0（闭环没真正跑起来）

**实测证据**（知识地图 `#/kbmap`）：
- 平均掌握度 **0%**
- 1067 个知识点：已掌握 0、**薄弱 1067（100%）**、待复习 1065
- 数字电子技术 404 知识点全部 0%

**根因**：掌握度 = 做题记录聚合，但**当前用户几乎没做对过题**（刷题中心显示"已完成作答 20 次、正确率 5%"）——所以所有知识点都是 0。加上"今日待复盘 39"与"本周学习 42 分钟"但"热力图 0 分钟"矛盾，说明**学习记录链路部分失效**。

**影响**：首页"今日智能推荐""薄弱科目预警"全部基于空数据，推荐无意义。

**修复方向**：
- 排查做题记录落库链路（answer records → 知识点聚合）
- 热力图数据源与"本周学习时长"统一
- 掌握度加入"未学 = 灰/未知"状态，不要把所有未学标成"薄弱"（1067 全红没有信息量）

## 八、🟠 中等问题 8：首页数据矛盾 + 加载时序错误

**实测证据**：
1. **刷新首页瞬间**显示"距 2027 考研还有 **0 天**"（应为 438 天）——数据未加载时用了错误默认值
2. **学习热力图"近12周 · 共 0 分钟"** vs 顶部"本周学习 42 分钟 / 0.7h"——矛盾
3. **今日时间轴"今天还没有学习记录"** vs "本周学习 42 分钟"——矛盾
4. 侧边栏"院校数据中心 **999+**"角标——实际是 1002 条未读通知，999+ 是死数字

**根因**：前端各组件数据源不一致（倒计时默认值、热力图口径、角标取整），后端无统一 dashboard 聚合。

## 十一、一句话总结

**页面框架已经立起来了（尤其院校库/择校中心做得很完整），真正让体验"崩"的是内容层：AI 配了引擎却没 Key → 问了不答；本地引擎答非所问 → 答了是废话；OCR 没清洗 → 题是脏的；后端还有个 500 和一个小时级超时。**
先修 P0 四件（AI Key/提示词、OCR 清洗、500、超时），平台的"能用的感觉"会立刻回来——这是从"能打开"到"能信"的关键一步。
