## 二、P0 问题（阻塞级，必须优先修）

### [P0-1] QuizBank.jsx 使用未导入的 `quizApi` → 页面必崩溃
- **位置**：`frontend/src/pages/QuizBank.jsx:37`、`:61`
- **现象**：文件第 1–3 行只 import 了 `React`、`{toast, Empty, Modal}`、`{Search, Trash, ...}`，但第 37 行调用 `await quizApi.questions(params)`、第 61 行调用 `await quizApi.remove(id)`。`quizApi` 是**完全未定义的标识符**。
- **交叉验证（主理人已核实）**：
  - `api/client.js:99` 确实 `export const quizApi = {...}`
  - `pages/Quiz.jsx:5` 正确写了 `import { quizApi } from '../api/client'`
  - 全项目搜索：`quizApi` 仅出现在 `client.js`（定义）、`Quiz.jsx`（正确导入）、`QuizBank.jsx`（**漏导入**）
  - 即：`QuizBank` 是全项目唯一漏掉该 import 的文件
- **影响**：进入「题库管理」页 → `loadQuestions()` 抛 `ReferenceError: quizApi is not defined` → 被 try/catch 捕获后 toast「加载题目失败：quizApi is not defined」→ 页面永久停留在**骨架屏永不退出**（因 `finally` 不会执行到 `setLoading(false)` 之外的路径，实际 loading 会被置 false，但列表为空 + 报错）。删除功能同样失效。
- **入口隐蔽性**：该页**不在侧边栏 23 个导航项中**，只能从 `Quiz.jsx:267` 的「📋 题库管理」按钮进入，用户很难发现这个功能坏了。
- **修复**：在 `QuizBank.jsx` 第 3 行后加一行
  ```js
  import { quizApi } from '../api/client'
  ```

### [P0-2] KaoyanGuide.jsx 静默吞掉所有请求错误 → 择校中心首页空数据无提示
- **位置**：`frontend/src/pages/KaoyanGuide.jsx:13`
- **现象**：`.catch(() => {})` 空捕获。`kaoyanApi.stats()` 或 `kaoyanApi.subjects()` 任一失败，Promise 静默 reject。
- **说明（重要更正）**：该文件语法完全正确，**不存在**三元表达式断裂或语法错误。此处原报告的「语法错误导致白屏」判定有误，已修正为下述真实问题。
- **影响**：
  - `stats` 保持 `null` → 统计概览整块不渲染
  - `subjects` 保持 `[]` → 「学科方向」网格空白
  - `loading` 被 `.finally` 置 false → 页面正常显示，但**「学科方向」和「分析工具」标题下什么都没有**
  - 用户看到的是「考研择校数据中心」标题 + 两行文字 + 两个空标题，**完全无法判断是加载失败还是本来就没数据**，也不会有任何错误提示
- **根因**：`request()` 封装已统一处理 401 并返回 `{code, detail}` 而非 reject，所以本文件里的 `.catch` 基本是死代码，真正的失败被 `.then` 内的解构静默吞掉。
- **修复**：改为 `.catch((e) => { toast('加载择校数据失败：' + e.message); setLoadError(true) })`，并在 `stats === null && subjects.length === 0` 时渲染可重试的错误态空组件。
- **同类问题**：`useStore.js` 的 `void syncAll()` 是全应用启动必经路径且**完全没有错误处理**，静默失败会污染本地缓存一致性。

## 三、P1 问题（功能缺陷与体验破功）

### A. 视觉与暗色模式（9 项，择校模块最集中）
1. **[P1] 择校 12 页面游离于设计体系外** —— `KaoyanGuide/Schools/SchoolDetail/Compare/Map/Scatter/Analysis/Recommend/Import/Assistant/PlanPage/GrowthPage` 全部使用**内联 style**（KaoyanGuide 内联 14 处），而主页面（Notebook/Documents/Settings）用 `global.css` 类名。两套体系并行，且内联样式**无法响应暗色主题切换**（硬编码 `#3A5A40`、`#fff`）。
2. **[P1] EChart.jsx 硬编码 `#fff` 背景**（`EChart.jsx:67`）→ 暗色模式下图表区亮白块。
3. **[P1] 区域热力图用 `visualMap` 文字/边框硬编码深色**（KaoyanMap.jsx:151-152）→ 暗色下不可读。
4. **[P1] 全局 `body` 背景被丢弃** —— `global.css:27-34` 的 `html, body { height/background/overscroll-behavior }` 与 `:root[data-theme='dark']` 的 body 背景规则，在构建产物 CSS 中检索不到 → 暗色模式**整页外围白底**，只切了局部容器色。
5. **[P1] `word-card` 前景色被覆盖**（`v2-design.css:238`）→ 暗色模式下单词卡文字色反转失效。
6. **[P1] `v2-design.css` 自相矛盾** —— `:root` 同时定义 `--ink:#3E3A34` 和 `--ink:#2E2C28`（`:112` 覆盖 `:85`），靠书写顺序取胜，极易在新增样式时破功。
7. **[P1] 亮色模式硬编码色值 463 处**（页面上限 100+，暗色 38 处）。
8. **[P1] 同一页面多套卡片圆角**：Notebook 混用 20/16/12/10px；KaoyanGuide 12px vs KaoyanCompare 10px vs KaoyanScatter 14px。
9. **[P1] 页面标题字号无规律**：Dashboard 32px / Notebook 26px / KbMap 与 Documents 21.3px。

### B. 数据契约与接口（8 项）
10. **[P1] `wordsApi.list()` 期待裸数组，后端返回 `{items}`** —— 单词列表永远显示为空。**主理人已复核**：契约对齐清单第 4 行确为 `items`，后端返回 `WordListResponse{items}`。
11. **[P1] `flashcardsApi.review()` 发送 snake_case，后端要 camelCase** —— `WordReviewRequest` 字段为 `reviewQuality/intervalDays/easeFactor`，前端发 `rating`/`interval_days`/`ease_factor`。后果：Pydantic 静默使用默认值 **2.5**，用户所有复习被记录为 ease 2.5（最差档）。**这是隐性的数据污染**。
12. **[P1] `taxonomyApi.overview()` 请求 `/taxonomy/overview`，后端只有 `/taxonomy/tree`** → 知识地图统计条永远空白。
13. **[P1] `assistantApi.explain()` 请求 `/ai/explain`，后端路由声明为 `/explain` 且 ai.py **无 prefix** → 实际 `/explain`，公开 API 404。
14. **[P1] `KaoyanGuide.stats` 字段名不匹配** —— 读 `school_count/major_count/admission_records/scoreline_records/subject_count`，KaoyanResponse 实际字段为 `total_schools/total_majors/total_records/avg_score/min_score` → 5 张卡全显示 0。
15. **[P1] `KaoyanRecommend` 权重字段全部对不上** —— 发 `weights:{exam:...,location:...,reputation:}`，`RecommendRequest` 要 `w_exam/w_location/w_reputation` → FastAPI 422，页面「生成失败」。
16. **[P1] `KaoyanCompare` 发 `ids[]`，后端要 `school_ids`** → 院校对比恒定失败。
17. **[P1] `KaoyanImport` 发 `major`，后端要 `major_id`** → 「爬取并导入」按钮直接 422。

### C. 交互与状态（3 项）
18. **[P1] QuizBank 骨架屏永不退出** —— `loading && questions.length===0` 才显示骨架；失败时 loading 已置 false，条件失配 → 卡在骨架屏。**与 P0-1 叠加**。
19. **[P1] 27 个页面均无骨架屏** —— Documents（45KB，列表 + 上传 + 筛选 + OCR）/ Planner（46KB，48 周网格）/ Notebook 三方初始化，均为空白闪烁。唯一 `PageFallback`（App.jsx:39）是懒加载占位，非内容加载态。
20. **[P1] Documents/Planner/Notebook 三方初始化无并发编排且无错误态** —— `Promise.all` 失败即整体白屏，无局部降级。

### D. 工程与资产（2 项）
21. **[P1] `frontend/dist/` 是陈旧废弃产物** —— 24 个文件，hash 全是旧值（`index-D2fCR4vV` 对应 10-08 旧构建，dist 内为更早一代），与现产物无任何文件重合。风险：人工部署时误取 dist 会得到**缺 27 个 chunk 的旧版本白屏**。
    - **主理人补充核实**：真实产物 `index.html` 用 `./assets/...` 相对路径引用，兼容性无问题；`main.py:288` 有 SPA fallback，`path="*"` 场景可兜住。**该问题是配置卫生问题，不是当前线上故障**，风险等级从「立即故障」下调为「部署陷阱」。
22. **[P1] `knowledge_base/china.json`（568KB）与 `frontend/public/china.json`（582KB）双份不同步副本**，公共目录在 `.gitignore` 内 → 干净克隆必崩地图。

### E. 测试与可观测性（2 项）
23. **[P1] 测试覆盖近乎为零** —— 27 页 / 3 用例 / 5.14s；根 `package.json` 无 `test` 脚本，`npm test` 退出 1。CI 不可能拦住任何回归。
24. **[P1] 构建配置自相矛盾** —— `cssCodeSplit: true` 但只产出一个 CSS chunk（131.5KB），且 content 为 `assets/mjs/` 却产物落在 `assets/`。
