## 一、总体结论

**核心判断：这个项目不是"做得差"，而是"两套体系并存"—— 一套是精心设计、有 token、有响应式、有空态的 v2 体系（Dashboard / Tasks / Notebook / Words / Cards / Documents / KbMap）；另一套是快速堆出来的择校模块（12 个页面），全部用裸内联样式、零 token、零错误处理。两者在同一个 `<Layout>` 下并排显示，用户能明显看出割裂。**

同时存在 **3 个会导致整页白屏的运行时崩溃缺陷**（QuizBank 缺 import、Empty 组件属性名不匹配），以及 **2 个导航孤岛页面**（路由存在但导航无入口，其中 `/quiz-bank` 一旦访问必然崩溃）。

## 二、跨页面一致性问题

### 2.1 导航孤岛与死链（最容易漏，重点）

**先说结论：导航有 2 个死链风险、3 个孤岛页面、1 处导航高亮 Bug。**

#### （1）孤岛页面：路由存在但侧边栏无入口（3 个）

| 路由 | 页面 | 问题 | 证据 |
|---|---|---|---|
| `/quiz-bank` | QuizBank | **侧边栏无入口 + 一访问必崩** | `App.jsx:64` 定义路由；`Layout.jsx:14-65` 的 `NAV_GROUPS` 23 个入口中无此项 |
| `/kaoyan/analysis` | KaoyanAnalysis | 侧边栏无入口，仅能从 KaoyanGuide 内部链接进入 | `App.jsx:81` 定义路由；`NAV_GROUPS` 中无 `/kaoyan/analysis`（只有 guide/schools/compare/map/scatter/recommend/plan/growth/assistant/import） |
| `/quiz-section` | QuizSection | 有入口（`Layout.jsx:27`），但 `CRUMB_MAP` **没有对应条目** | `Layout.jsx:80-106` 无 `/quiz-section` 键 |

`/quiz-section` 的面包屑会走到兜底分支：

```js
// Layout.jsx:109-113
const crumbName = (path) => {
  if (CRUMB_MAP[path]) return CRUMB_MAP[path]
  if (path.startsWith('/kaoyan/schools/')) return '院校详情'
  return '页面'          // ← /quiz-section 落到这里
}
```

用户看到面包屑是 **「首页 / 页面」**。

#### （2）死链风险：`/kaoyan/guide` 是冗余路由

`App.jsx:76-77` 同时注册了 `index` 和 `guide` 两条路由指向同一个 `KaoyanGuide`：

```jsx
<Route index element={<KaoyanGuide />} />
<Route path="guide" element={<KaoyanGuide />} />
```

导航里用的是 `/kaoyan`（`Layout.jsx:47`）。这本身不算死链（两条都渲染同一组件），但造成 **`/kaoyan/guide` 这个 URL 从任何界面都无法产生** —— 它是纯粹的死 URL，且 `CRUMB_MAP` 为它准备了条目（`Layout.jsx:95`），属于维护性负担。

#### （3）导航高亮 Bug：`/quiz` 会吃掉 `/quiz-section`

`Layout.jsx:151-154` 的 `isActive` 辅助函数用 `startsWith` 判断，但**侧边栏用的是 `<NavLink>` 而非这个函数**：

```jsx
// Layout.jsx:200-211
<NavLink
  key={n.to}
  to={n.to}
  end={n.exact}      // 只有 '/' 传了 exact=true，其余全靠 NavLink 默认的「前缀匹配」
  className={({ isActive: a }) => `nav-item ${a ? 'active' : ''}`}
>
```

react-router v6 的 `NavLink` 默认 `end=false` 即前缀匹配，因此访问 `/quiz-section` 时，**「刷题中心」(`/quiz`) 和「分项刷题」(`/quiz-section`) 会同时高亮**。同理 `/kaoyan` 与 `/kaoyan/schools`、`/documents` 与 `/documents/xxx` 都有这个问题。这是一处视觉 Bug，用户会以为在两个页面上。

#### （4）`Layout.jsx` 内 `isActive` 函数是死代码

```js
// Layout.jsx:151-154
const isActive = (to, exact = false) => {
  if (exact) return location.pathname === to
  return location.pathname.startsWith(to) && to !== '/'
}
```

全文件搜索确认：此函数**仅被底部导航使用**（`Layout.jsx:283`、`305`），侧边栏完全不用它。且底部导航的 `startsWith` 判断对 `/` 做了特判，功能正确。但同一个文件里存在两套高亮逻辑，其中一套（侧边栏）有 Bug、另一套（底部）没 Bug，属于典型的逻辑分裂。

### 2.5 响应式：择校模块系统性破版（P1）

**这是除崩溃 bug 外最严重的横向问题。**

`global.css` 的响应式断点体系是完整的（**18 个 `@media`**，分布在 `1080px / 860px / 768px / 640px / 560px / 480px / 380px`），并且有几处专门为移动端优化：

```css
/* global.css:2189-2210 */
@media (max-width: 768px) {
  .main-area { padding-bottom: calc(80px + env(safe-area-inset-bottom)); }
  .btn, .mini-btn, .link-btn { min-height: 44px; min-width: 44px; }
  table { display: block; overflow-x: auto; -webkit-overflow-scrolling: touch; }
}
```

这段全局规则**救不了择校模块**，因为它针对的是 `.main-area` 和 `table` 标签。但择校模块的问题是：

1. **表格没有横向滚动容器**。`global.css:2204` 的 `table { display:block; overflow-x:auto }` 确实能兜住表格，但 `KaoyanSchoolDetail` 的分数线表有 **8 列**、招生表有 **7 列**，在 375px 下会变成极窄的挤压布局（每列约 40px），可读性极差。`KaoyanCompare.jsx:75` 的 8 列表格、`KaoyanScatter.jsx:89` 的 6 列表格同理。

2. **内联样式写了写死的 px，无法被断点覆盖**：
```jsx
// KaoyanSchools.jsx:39
style={{ ..., width: '120px' }}    // 省份输入框写死 120px
// KaoyanAnalysis.jsx:47
style={{ ..., flex: 1 }}           // 与另一个 select 挤在一行，无 flexWrap
// KaoyanMap.jsx:72 / KaoyanScatter.jsx:71 / KaoyanCompare.jsx:52
style={{ display: 'flex', gap: '12px' }}   // 无 flexWrap，窄屏必溢出
```
这几处筛选栏都是 `display:flex` 且**没有 `flexWrap`** —— 在 375px 下两个 select 会各占一半但内容被裁切。

3. **`KaoyanAssistant.jsx:71` 的高度计算在移动端是错的**：
```jsx

```

### [P1-4] ECharts 在容器 resize 时不更新，且 resize 监听器泄漏

- **位置**：`src/components/EChart.jsx:52-58`
- **现象**：两处问题。
- **证据**：
```jsx
// EChart.jsx:47-59
useEffect(() => {
  if (!ref.current) return
  ensureChinaMap().then(() => {
    chartRef.current = echarts.init(ref.current)
    if (option) chartRef.current.setOption(option, true)
    const handler = () => chartRef.current && chartRef.current.resize()
    window.addEventListener('resize', handler)      // ← 注册了 handler
  })
  return () => {
    window.removeEventListener('resize', () => {})  // ← 传了个全新的空函数！
    chartRef.current && chartRef.current.dispose()
  }
}, [])
```
- **两个具体缺陷**：
  1. **监听器泄漏**：`removeEventListener` 传入的是一个**新建的匿名函数**，与 `addEventListener` 时注册的 `handler` 不是同一引用，因此**移除完全无效**。每次进入/离开一个含 ECharts 的页面（KaoyanMap / KaoyanScatter / KaoyanCompare / KaoyanAnalysis / KaoyanSchoolDetail —— 共 5 个页面），就永久泄漏一个 `resize` 监听器 + 一个已 `dispose` 的 chart 引用。长时间使用后内存持续增长，且 `handler` 闭包里的 `chartRef.current` 指向已销毁实例。
  2. **只有 window resize，没有容器 resize**：侧边栏在 860px 断点隐藏、主内容区宽度变化时，图表不会重绘。移动端旋转屏幕时同理。
- **影响**：内存泄漏（累积）+ 某些场景下图表尺寸不跟随容器（表现为图表溢出或留白）。
- **建议**：把 `handler` 提到 `useEffect` 外部或用 `useRef` 保存；把 `window.resize` 换成 `ResizeObserver`（现代浏览器原生支持，`EChart.jsx` 已经在按需引入 ECharts 5，顺手就能升级）。

这些是**不用动**的部分，修 bug 时不要误伤。

### 4.1 架构层做对了的事

1. **路由级懒加载覆盖全部 27 个页面**（`App.jsx:10-36`），无一遗漏。相比之下很多项目只对大页面做懒加载，这里做得彻底。

2. **全局 ErrorBoundary 兜底**（`App.jsx:55`、`:94`）包住整个 Layout + Routes，单页崩溃不会白屏整个应用。配合 lazy loading 的 `<Suspense fallback={<PageFallback/>}>`（`:38-40`）有明确的"加载中…"文案。

3. **兜底路由用 `replace` 重定向**（`App.jsx:90`）：`<Route path="*" element={<Navigate to="/" replace />} />` —— 访问不存在的 URL 会回首页，且**不会在历史里留下脏记录**。比 `Navigate to="/"` 不带 `replace` 造成"后退键点了没反应"要正确得多。

4. **CSS 变量体系健全**：`global.css` 有 122 个变量定义 + 3 个 `:root` 块；v2 体系的页面（Dashboard / KbMap / Documents / Pan）几乎 100% 使用 `var(--surface)` / `var(--ink-3)` / `var(--line)` / `var(--accent)`，**没有一个硬编码背景色**。深色模式只需要覆盖 `:root` 就能全局生效，架构是对的。

5. **移动端方案完整**：`Layout.jsx` 同时实现了移动端顶栏（`:234-249`）、底部 6 栏导航（`:70-77`、`:279-313`）、中央 FAB 快捷操作面板（`:316-337`）。CSS 侧有 `@media (max-width: 860px)` 切换布局（`global.css:538-552`）、`env(safe-area-inset-bottom)` 安全区适配（`:2190`）、≤380px 的 iPhone SE 压缩（`:1551`）、44px 最小触控目标（`:1366-1371`、`:2199`）。**这套移动端方案的水平高于大多数同类项目。**

6. **无障碍基础打得好**：`:focus-visible` 有定义（`global.css:115`、`:2030`，后者是完整的 focus ring 样式）、`prefers-reduced-motion` 有 3 处响应（`:563`、`:1373`、`:2065`）、`prefers-contrast: high` 有响应（`:2075`）、还有 `@media print`（`:2169`）。**这两项是很多项目完全没做的。**

7. **`@media (hover: none)` 处理触屏**（`global.css:2155`）—— 移动端 hover 效果误触的处理，说明作者考虑过真实设备。

### 4.2 页面层做对了的事

8. **Dashboard 的三态是全站范本**：`loading` 有骨架屏（`:290-300`，用 `skeleton` 类而非转圈）、`error` 有可读文案 + 说明已降级到本地数据（`:301-305`）、数据层做了「后端优先、本地兜底」（`:77-88`）。**用户在任何情况下都不会看到空白页。** 这个 `loading | ok | error` + `alive` 标志防竞态的模式（`:62-68`）应该推广到其他页面 —— 特别是不如 Dashboard 的 KaoyanSchoolDetail。

9. **Dashboard 的无障碍是全站最佳**：`role="button" tabIndex={0}` + `onKeyDown` 处理 Enter（`:310-312`、`:321-323`、`:332-334`、`:343-345`），4 张统计卡全部键盘可达。v2-design.css 还给 `.stat-card.clickable:focus-visible` 专门定义了 outline（`v2-design.css:425`）和箭头位移动画（`:427`）。
