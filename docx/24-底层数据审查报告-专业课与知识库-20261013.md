## 一、届数与考研年份（已修复）

### 1.1 原问题：同一应用对「考哪一天」给出三个答案

| 位置 | 原逻辑 | 算出的日期 |
|---|---|---|
| `services/dashboard_service.py` | 写死 `date(year, 12, 21)` | 2026-12-21 |
| `routers/plan.py::_exam_date` | 按「上一年 12 月倒数第二个周六」 | 2026-12-19 |
| 真库 `goals.exam_date` | 手工填 | **2027-12-25** |

而真库那一行的 `remark` 写着「目标贵大电子信息专硕」，即用户要考的是 **2027 届**。
`2027-12-25` 按规则反推（初试在上一年 12 月 → 届数 = 初试年 + 1）实际是 **2028 届**。
同一条记录内部就自相矛盾。

### 1.2 官方依据

教育部《2027年全国硕士研究生招生工作管理规定》：
- **初试时间：2026 年 12 月 19 日至 20 日**
- 报名：2026-10-15 至 10-24（预报名 10-09 至 10-12）

### 1.3 已做的修复

**新增 `backend-main-fastapi/services/exam_calendar.py` 作为唯一权威出口**

- 内置教育部已公布届：`2025 届=2024-12-21` / `2026 届=2025-12-20` / `2027 届=2026-12-19`
- 未公布的届按「上一年 12 月倒数第二个周六」推导，并标 `is_official=False`（前端显示「预估」）
- 规律推导与三个已知官方值**完全吻合**，故该规律对未公布届可信
- 关键不变式：初试必在**周六**，且必在**上一年 12 月**

**改造的调用点**

- `dashboard_service.get_countdown` —— 删掉写死的 12/21
- `routers/plan._exam_date` —— 委托给 `exam_calendar`
- `routers/plan` 三个端点原先写死 `year: int = 2027` —— 改为**不传即跟随用户配置的届**

**新增接口**（届数可随时调整）

```
GET  /api/goals/exam-calendar   → { exam_year, exam_date, is_official, days_left, year_options, source, ... }
PUT  /api/goals/exam-calendar   ← { exam_year: 2027 }  或  { exam_date: "2026-12-19" }
```

**前端设置页**把「届数」做成一等控件：选届 → 后端推官方初试日 → 自动回填日期框（可微调），并显示日期来源、距今天数、报名窗口；日期与官方公布不一致时显式提示。

### 2.2 ✅ 好消息：可作答题目质量比预期好

### 2.4 🔴 问题 2：答案字段被存成了别的东西（195 道）

这是此前**完全没被发现**的污染类型——答案字段里装的不是答案：

| 类型 | 数量 | 说明 | 危害 |
|---|---|---|---|
| 正常 | 2836 | — | — |
| 超长（疑似段落） | 262 | 答案栏塞了一整段解析 | 判分逻辑可能出错 |
| **答案壳** | **151** | 值为 `答案：` / `参考答案：` / 空 | 无意义 |
| 判断题 | 91 | `正确`/`错误`/`√`/`×` | 正常，但需与选择题区分 |
| **子问编号** | **30** | 值为 `（1）`/`（25）` | 🔴 **会判分错误** |
| **提示语** | **14** | 值为 `见解析`/`请注意…` | 🔴 **用户答什么都算错** |
| 空 | 1 | | |

**典型样例**

```
id=790  [数字电子技术] 答案='（1）'
   题干：18 在图 10-26 电路中，已知 CMOS 集成施密特触发器的电源电压 VDD＝15V…
   → 这是一道**多问题目**，「（1）」是第一小问的编号被误当成答案
   → 用户答「（1）」会被判对，实际完全没答对

id=248  [数字电子技术] 答案='见解析'
id=2640 [模拟电子技术] 答案='请注意电路中IB和IC的数量级'
   → 答案栏存的是提示语，根本没有可比对的答案
```

**这 44 道（30 子问编号 + 14 提示语）是会给出错误判分的题**，优先级最高。

### 2.5 缺图标记 1791 道从未被消费

`figure_missing` 列已由数据脚本标记 1791 道题，但全仓 `grep` 显示**没有任何路由或前端读取过它**——数据层标了，产品层一次没用上。

不过好消息：这些题绝大多数已因 `is_available` 或 `is_junk` 被挡在可作答之外，实际影响有限。

## 四、待处理清单（按优先级）
