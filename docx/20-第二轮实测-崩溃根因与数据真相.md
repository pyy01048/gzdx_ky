# 20 · 第二轮逐字逐句实测 · 崩溃根因与数据真相（2026-10-13）

> **本轮不是重复第一轮**，而是逐字逐句核对 + 追到**代码级根因**。上一轮（19 号报告）说"11 个页面崩溃"——**这个结论是错的**，本轮用「每页硬刷新 + React fiber 读错误边界」的严格方法纠正了它。真相更简单也更可怕：**全站只有 1 个页面真崩，但全局错误边界没有重置机制，一崩全崩，把 10 个正常页面全部伪装成崩溃页。**

---

## 一、最重要结论：19 号报告的"11 页崩溃"是误报，真相如下

### 1.1 真崩的页面：只有「文档知识库」（#/documents）

**严格验证方法**：每个页面 `navigate → reload（硬刷新）→ 读 React fiber 错误边界 state`。只有文档知识库每次都崩，其余 10 个页面 reload 后全部正常。

### 1.2 崩溃根因（代码级实锤）

文件：`frontend/src/components/KbHealthPanel.jsx`

```
第12行:  const [rep, setRep] = useState(null)      ← 初始就是 null
第82行:  const d = rep.documents                    ← 渲染时无条件访问 rep.xxx
第83行:  const c = rep.chunks
第84行:  const errors = rep.issues.filter(...)      ← rep 为 null → 直接 TypeError
第90行:  <div className={rep.healthy ? 'ok' : ...}> ← 同样访问 null
```

**机制**：`rep` 的初始状态是 `null`，`load()` 是异步请求（`useEffect(() => { load() }, [])`），**首次渲染在数据回来之前就执行了 `rep.issues.filter()`** → `Cannot read properties of null (reading 'id')`（`id` 来自 React 内部遍历）。只有文档知识库页嵌入了 `<KbHealthPanel />`，所以只有它崩。

### 1.3 为什么表现为"11 页全崩"？——全局 ErrorBoundary 无重置

`App.jsx` 第 85 行 `<ErrorBoundary>` 包住了整个 `<Layout>`。**React 错误边界一旦捕获错误就永久显示 fallback，不会自动重置**。文档知识库崩 → 边界锁死 → 之后你点任何导航（院校对比/分数分析/通知中心…）都渲染同一个错误页——**10 个正常页面被伪装成崩溃页**。

### 1.4 修复方向（都极小）

| 文件 | 修复 | 耗时 |
| :--- | :--- | :--- |
| `KbHealthPanel.jsx` | 在 `const d = rep.documents` 前加 `if (!rep) return null`（或 loading 占位） | 5 分钟 |
| `App.jsx` ErrorBoundary | 加 `key={location.pathname}` 或重置机制，导航后自动恢复 | 10 分钟 |

## 二、本轮逐字核对发现的新问题（19 号报告没提的）

### 2.1 倒计时数值三处不一致（437 / 438 / 0）

| 位置 | 显示 | 问题 |
| :--- | :--- | :--- |
| 侧边栏「考研初试倒计时」 | **437 天** | 与下方"距考试 438 天"矛盾 |
| 侧边栏底部「距考试」 | **438 天** | — |
| 学习画像页 | 距考研 **438 天** | 与侧栏 437 矛盾 |
| 首页 reload 瞬间 | "距 2027 考研还有 **0 天**" | 数据未加载时用了 0 做默认值（加载时序 bug） |

**根因**：倒计时存在多个数据源（`/dashboard/countdown`、前端本地计算、store 缓存），且未统一；首页在 countdown 数据到达前先渲染默认值 0。

### 2.2 错题本「七刷机制」名存实亡

- 39 条错题：**全部"待复习"，七刷中 0、已毕业 0**
- 复习队列：39 已排期 / **39 全部逾期** / 今日到期 0
- 学习画像：「复习队列已逾期 39 条，先清逾期错题再刷新题」——系统自己在催，但用户从没被触发过复习

**说明**：SM-2/艾宾浩斯调度表生成了，但**没有任何"今日到期"的题**——调度从未真正排期过（或排期时间戳异常）。

### 2.3 记忆卡片 500 张全部"今日待复习"

- 卡片总数 500 / **今日待复习 500** / 进行中 0 / 已掌握 0
- 单词 4569 / **今日待复习 4568**

**说明**：调度初始化时把所有卡片/单词都标成了"今天到期"——这是典型的**初始化 bug**（`due: spacedToday()` 应该返回未来时间，却返回了今天/过去）。

### 2.4 任务打卡页「今日无任务」vs 首页「今日 1 个任务」

- 任务打卡（#/tasks）："10月13日 · 今日 **这一天没有任务**"，已完成 2/7
- 首页："今日 **1 个任务** · 已完成 0"

**说明**：两个页面用了不同的任务日期口径（首页按 due_date，任务页按 created_at？或时区差）。

### 2.5 学习画像「生成于 2026-10-13 15:29:21」——这是未来时间？

- 当前浏览器时间约 08:30，但画像显示生成时间 **15:29**——时间源不一致（后端用 UTC？前端本地时区？）

### 2.6 设置页「服务端凭证：已配置 ✓（AppID undefined）」

- 百度网盘授权显示"已配置 ✓"但 **AppID undefined**——配置是半成品，授权实际不可用
- "已连接 0 / 7 个网盘"（网盘联动页）——与"已配置 ✓"矛盾

### 2.7 OCR 脏数据新证据（错题本逐条）

- "[陶宝搜索]选择器74195"——**"数据选择器"被 OCR 成"陶宝搜索"**（广告联想）
- "子与通信工程 微信公"（截断的水印尾巴）
- "西南科技大学2021年硕士研究生招生考试试题"（整段校名水印）
- "重庆大学2021年硕士研究生招生考试试题"（整段校名水印）
- 大量 `--- 第N页(OCR) ---` 页眉页脚 + "东坡哥微信：haidongpo8"

**结论**：题库 9171 题里脏题占比极高，错题本 39 条几乎全是 OCR 垃圾题——**错题复习练的是垃圾数据，比不练更糟**。

## 四、用户最关心的三件事 → 本轮答案

1. **"页面写死"在哪**：科目列表、题库筛选、倒计时、学科标签——**都是后端接口返回什么前端就显示什么，不是写死**；真正的"死"是**调度表（复习/卡片/单词）全部初始化成"今天到期"，数据一动不动**——看起来像写死，其实是初始化 bug。
2. **"识别出问题"在哪**：OCR 脏数据（广告水印/截断/错字）遍布题库与错题本，且**错误地进入 AI 上下文**（KVL 问答题检索命中 C++ 编程思想/模电笔记，与主题无关）。
3. **"弊端太多"的典型**：一个 5 分钟能修的 null 崩溃（KbHealthPanel），因为没有错误边界重置，把全站 22 个页面里的 10 个变成"假崩溃"，**多轮 AI 协作都没发现，直到逐字核对的这一轮**。

## 六、一句话总结

**平台不是"到处烂"，是"几个根因放大成一片烂"**：1 个 null 崩溃 → 错误边界没重置 → 10 个页面假崩溃；1 个调度初始化 bug → 单词/卡片/错题全部"今天到期" → 复习功能形同虚设；1 个 OCR 清洗缺失 → 题库/错题全是垃圾 → AI 引用错误上下文。**先修 4 个 P0（总共不到半天），平台的"能用感"会立刻翻身。**
