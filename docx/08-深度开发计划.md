## 〇、判断：这个项目"浅"在哪里（一手证据）

我改过这个项目的每一层代码，"简单"不是功能少——26+ 页面、31+ 路由、57 个 service、
61 张表、340+ 测试，功能密度已经超过多数开源考研项目。浅在**四个断裂**：

| # | 断裂 | 一手证据 |
| :- | :--- | :--- |
| 1 | **数据在睡觉**：`answer_records` 有完整作答流水、`question_knowledge_links` 有 6288 条知识图谱边、`study_events` 有毫秒级行为流——但没有任何模型在消费它们。"正确率"是唯一被算出来的东西。 | 我写智能组卷时只能按"错误次数"抽题，因为没有能力模型 |
| 2 | **学习科学缺位**：SM-2 是 1987 年的通用算法，间隔对所有人一样。题目难度是录入时定的静态值，不随作答数据演进。掌握度 = 1 - 错误率，是最粗糙的估计。 | weak_knowledge 的 mastery 公式是我写的：`acc*0.7 + 频次*0.3`，能用，但无认知科学依据 |
| 3 | **Agent 是路由表不是大脑**：V12 的 agent_router 只做意图分类转发，Agent 之间零数据流动，会话无记忆，Tutor 不知道学生现在的能力画像。 | 我写的 route() 返回端点地址就结束了 |
| 4 | **内容生产为零**：平台只能"消费"题目（刷/判/复习），不能"生产"内容（变式题/讲解卡/微课）。错 100 道同类题，系统不会生成第 101 道变式让你证明学会了。 | flashcard_gen 有骨架但从没被学习闭环驱动 |

**深度的定义**：做完本计划后，系统应该能回答这些它现在回答不了的问题——
「我在 834 数电上现在值多少分？置信区间多少？」「下周刷哪个知识点的题期望涨分最多？」
「这道题错是因为概念不清还是计算失误？系统怎么知道的？」「这个遗忘间隔为什么适合我？」

## 一、D1 学习者能力模型（学习科学内核）⭐ 最高优先

> 这是整个深度计划的地基。没有它，后面所有 AI 功能都是"无画像的通用问答"。

### D1.1 知识点 Elo 能力估计（替代"正确率"）

**理念**：借用国际象棋 Elo / Khan Academy 的做法——每道题有难度分（rating），
每个「知识点×学习者」有能力分。答对：能力 += K×(1 - 预期胜率)；答错：能力 -= K×预期胜率。
比正确率深在：**做对一道难题和做对一道简单题，权重完全不同**。

```sql
-- 新表（SQLite，沿用原生 DDL 幂等模式）
CREATE TABLE IF NOT EXISTS ability_ratings (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    subject TEXT NOT NULL,
    knowledge_point TEXT NOT NULL,
    ability REAL NOT NULL DEFAULT 1200,      -- Elo 能力分（初始 1200）
    attempts INTEGER NOT NULL DEFAULT 0,
    last_event_at TEXT,
    updated_at TEXT NOT NULL,
    UNIQUE(subject, knowledge_point)
);
CREATE TABLE IF NOT EXISTS question_difficulty (
    question_id INTEGER PRIMARY KEY REFERENCES quiz_questions(id) ON DELETE CASCADE,
    difficulty_elo REAL NOT NULL DEFAULT 1200,     -- 动态难度（初始=录入难度映射）
    prior_difficulty INTEGER,                      -- 录入时的静态难度(1-5)作先验
    attempts INTEGER NOT NULL DEFAULT 0,
    correct_count INTEGER NOT NULL DEFAULT 0,
    updated_at TEXT NOT NULL
);
```

**算法要点**（`services/ability_model.py`）：
```
预期胜率 E = 1 / (1 + 10^((D_q - A_kp)/400))
赛后更新：A_kp += K_kp × (S - E)          # K 随 attempts 衰减：新手 K=48 → 稳定 K=16
题目难度：D_q += K_q × (E - S)            # 双向更新，题目难度随真实作答校准
K_q 同样衰减；attempts<5 的题难度不动（样本不足，防抖动）
```
- **接入点**：`routers/quiz.py submit_answer`（判分后调用，一次 DBAPI 写入，不引入延迟）
- **冷启动**：`question_difficulty` 初始 Elo 由静态难度 1-5 映射（1000/1150/1200/1350/1500）；
  真题可用"官方区分度"先验（数电真题逐年有公认难度）
- **验收**：答对一道 difficulty_elo=1500 的题后，对应知识点能力分涨幅 > 答对 1200 的题；
  全量 answer_records 回放后能力分排序与直觉一致（组合逻辑 > 触发器进阶 > A/D 混杂）

### D1.2 知识图谱传播（BKT 简化版）

**理念**：错一道「触发器」题，不能只降「触发器」掌握度——`question_knowledge_links`
里 6288 条边告诉你触发器和时序电路、寄存器强相关。**沿图谱边按衰减系数传播掌握度变化**，
这是"知识追踪"（Knowledge Tracing）的工程化最小实现。

```
传播规则（ability_model 内）：
掌握度变化 Δ = 基础变化 × w_edge × 0.5^hop        # 每跳衰减一半，最多传播 2 跳
w_edge 来自 question_knowledge_links 的权重列（若无则统一 0.6）
```
- **验收**：错一道寄存器题后，相邻「时序电路」知识点的 ability 下降但幅度小于本知识点，
  且 weak_knowledge 刷新后时序电路出现在"疑似薄弱"列表（标注"由图谱传播推断"）

### D1.3 个体化遗忘曲线（FSRS 替代 SM-2）

**理念**：SM-2 的间隔序列（1/6/15/35 天）对所有人一样。FSRS（现代 Anki 内核，开源算法，
三条参数可拟合）用**用户自己的复习日志**拟合 R（可提取性）= exp(-t/S)，
S（稳定性）随每次成功回忆增长。数据量要求低：**个人场景每人自己的记录拟合自己**。

- 接入点：`ReviewScheduler` 换内核（对外接口不变：`ebinghaus_next_review(review_count)` →
  `next_review(item, rating)`），旧 ebbinghaus_items 数据可迁移（保留字段映射）
- **验收**：同一知识点，复习时总答错的间隔增长明显慢于总答对的（差异可从 review_records 拟合出）

### D1.4 预测分引擎 + 涨分路径 ⭐ 面向用户价值最大

**理念**：834 蓝图已有（数电/模电分值分布）。把「知识点能力分」按蓝图加权 →
**预测总分 + 置信区间**。再算「边际涨分」：每个知识点 涨分空间 × 可提升概率 排序，
直接回答「**接下来 10 小时刷哪里最划算**」——这是大平台都没有的深度。

```json
// GET /api/ability/forecast
{
  "predicted_total": {"score": 112, "ci": [104, 121], "blueprint": "szd834"},
  "gain_paths": [
    {"kp": "卡诺图化简", "current": 1150, "ceiling": 1400, "expected_gain": 6.5,
     "hours_est": 8, "reason": "分值占比12% × 当前薄弱 × 题目储备充足"},
    {"kp": "A/D 转换", "expected_gain": 2.1, "reason": "分值占比3%，性价比低"}
  ],
  "honesty_note": "基于 Elo 能力模型与蓝图加权估算，非官方预测"
}
```

**工作量**：D1 全部约 3~4 个会话（ability_model 核心 1 个、接入判分链 0.5、
forecast 接口 0.5、回放校准脚本 1、前端能力雷达+预测卡 1）。
**依赖**：云端可开发可测试（合成数据），真机跑历史 answer_records 回放。

## 二、D2 Agent 从"路由表"到"协作大脑"

### D2.1 会话状态机 + 学生模型注入

- `agent_sessions` 表：session_id、agent、turns(JSON)、student_snapshot(JSON)、topic

- 规格书 §5 的 `/api/agents/chat` 形态：route → 选中 Agent → 带画像对话 → 回写会话

### D2.2 事件总线（Agent 间协作）

```
services/event_bus.py：内存发布订阅（单机够用）
Radar 检出「XX大学改考 408」→ 事件 → Planner 重算该院校匹配度并标记计划冲突
                                    → Tutor 生成「改考应对」建议卡
```
- 表：`agent_events(id, event_type, payload JSON, status, created_at)`，轮询/触发均可
- **验收**：改考雷达扫出事件后，择校推荐页该院校的风险标签自动变化（端到端无人工）

### D2.3 意图识别升级

## 三、D3 内容生产管线（从消费到生产）

### D3.1 错题变式生成 + 自动 QC

- 触发：同一知识点错误 ≥3 次且错因相同 → 生成 2 道变式
- 生成模板（数电可枚举场景多）：数值替换 / 问法翻转 / 条件反转
- **QC 门**（防幻觉，规格 §3 精神）：变式题的参考答案必须通过 `_extract_option_letter`
  + 一致性校验 + `answer_source='llm_generated'`（置信 0.55，不参与判分）→
  正确入 quiz_questions（variant_group=原题组）+ 入人工确认队列
- **验收**：生成的变式题在题库中带变式标记，QC 报告含"答案一致性"字段

### D3.2 错题 → 微课卡（flashcards 闭环）

错误率高 + 概念类错因 → 自动产卡：`知识点定义 + 常见误区（misconceptions 表已有！）+ 一道变式`。
产出进 flashcards，走 FSRS 复习。**学习闭环最后一块拼图：错 → 学 → 变式 → 卡 → 复习**。

### D3.3 SVG 电路讲解（远期，数电特色）

数电波形图/门电路可参数化模板生成 SVG（MathLens 思路）。先把**题型模板库**建起来
（与门/或门/触发器/计数器 ≤ 20 个模板覆盖 80% 题型），LLM 只负责填参数。

## 六、不建议做清单（防止"深"跑偏成"重"）

1. **深度学习知识追踪（DKT/SAKT）**：个人作答数据量（数千条）远不够训深度模型，Elo+BKT
   是数据量匹配的正确选择——等累计 10 万+ 作答再评估
2. **多用户/账号体系**：定位是个人备考平台，口令鉴权（已有）足够；多用户会拖垮所有
   "个人化"设计的前提
3. **微服务拆分**：单机 SQLite 场景，进程内模块边界（routers/services）已经是正确的
   架构粒度
4. **自训大模型**：LoRA 微调通道保留（kaoyan_ai 侧），但平台核心逻辑**不能依赖**
   自训模型质量——所有 AI 功能必须有无模型降级路径（现在的 model_gateway 模式保持）
5. **前端全面重写**：v2 设计体系（styles/v2-design.css）已在位，渐进增强优于推倒重来

## 八、外部最优实现调研与"抄法"（2026-10-11 GitHub 实测调研）

> 原则：**算法不自己发明，工程不重复造轮**。以下均为实测可用的开源库/论文/产品，
> 每项标注：抄什么 → 怎么接进平台 → 依赖。开源库优先（pip 直装），产品只抄机制不抄界面。

### 8.1 遗忘调度：FSRS（py-fsrs，507★，MIT）——直接替换 SM-2
- **实测**：`pip install fsrs`，API 四件套 `Scheduler / Card / Rating(Again..Easy) / ReviewLog`；
  DSR 三变量模型（Difficulty/Stability/Retrievability），srs-benchmark 实测全面优于 SM-2
- **抄法**：新建 `services/fsrs_scheduler.py` 适配层，实现与 `ReviewScheduler` 相同接口
  （`next_review(state) -> datetime`），按环境开关 `REVIEW_SCHEDULER=fsrs|sm2` 灰度切换；
  `ebbinghaus_items` 现有字段映射：Card 状态（due/stability/difficulty）持久化到 payload JSON
- **依赖**：云端可开发可测（纯 Python，无模型依赖）★ M2 首选

### 8.2 掌握度估计：pyBKT（伯克利官方，283★）——从"1-错误率"升级为认知模型
- **实测**：`pip install pyBKT`，`Model().fit(data).predict()`，支持多技能/先验个性化
- **抄法**：`services/mastery_bkt.py`——把 question_knowledge_links 的知识点当 skill，
  answer_records 流水按时间序喂 fit()；weak_knowledge.mastery 改由 BKT 输出（保留旧公式
  做 fallback，列名不变）。**数据量门槛**：每知识点 ≥20 条作答才启用，不足用旧公式
- **依赖**：云端可开发可测 ★ M1 并行

### 8.3 个体化遗忘：Duolingo HLR（论文 Settles & Meeder 2016，开源复现可查）
- **公式**：`p(记住) = w₀/(1+e^(-Σwᵢxᵢ))`，特征 = ln(间隔)/词长/历史正确率等
- **抄法**：只用于**单词卡模块**（4569 词，数据量够）；`services/hlr_words.py`，
  每 7 天用 study_events 全量重训 w（逻辑回归，sklearn 即可）；预测 p<0.5 的词进
  今日听写队列。**抄机制不抄规模**：特征先只用 ln(Δt)+正确次数+错误次数 三个
- **依赖**：云端可开发 ★ M2

### 8.4 RAG 评估：vectara/open-rag-eval（412★）+ tonic_validate（328★）
- **实测**：open-rag-eval 主打 "no golden answers required"（UGEN 指标族），正合个人
  知识库无标注数据的现状
- **抄法**：不整库引入，**抄指标定义**：忠实度（答案句是否被检索块支持）/ 相关性 /
  完整性三指标；每次答疑把 {query, 检索块ID, 答案} 落 `rag_eval_log` 表，周期性离线评
  （启发式版云端可跑，LLM 评审版走 model_gateway）→ 检索质量看板（07 方向三轻量落地）
- **依赖**：启发式版云端可跑；LLM 评审版需真机 ★ M3

### 8.5 自适应出题组合的先例验证
- GitHub 实测存在 **"IRT 出题 + BKT 掌握 + FSRS 复习"三件套**同构项目（gmat-ai-prep 等），
  证明 D1 组合路线工程可行；IRT 部分我们用 **Elo 替代**（题目量小、冷启动友好，
  Khan Academy 亦用 Elo 系）——理由已写入 D1.1

### 8.6 商业产品机制借鉴（抄机制，不抄界面）
| 产品 | 机制 | 平台落点 |
