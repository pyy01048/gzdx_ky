## 3. 第 2 层精度修复（本轮重点）

初版第 2 层用「词重叠 + 领域术语 + 章名片段」多信号，覆盖率冲到 77.4%，但**误挂严重**
（如 Q7019 讲 "TTL 反相器" 挂到 "ROM/RAM"、Q4705 讲 "晶体管 β" 挂到 "高频等效模型"）。

**根因**：①未约束"章"；②单一泛词（电路/放大/逻辑）即单独成链；③把 KP 的**章名片段**
并入匹配片段，导致"题干提到某章名"就滥挂该章全部 KP；④跨科兜底门槛过低。

**修复后的严判据**（`match_question_rule`）：

1. **同章硬约束**：题目与 KP 的 `chapter` 均有值时**必须完全一致**，否则不匹配。
2. **强片段**：只从**知识点名本身**拆词（不再并入章名），只保留 **≥3 字且非泛词**的实词
   （泛词表 `_SEGMENT_STOPWORDS` 覆盖 电路/放大/逻辑/方法/系统/模型… 约 60 词）。
3. **成链门槛**：要么整个 KP 名直击；要么命中 **≥2 个不同强片段**。
4. **无章题更严**：题目无 `chapter` 时（本库未链题几乎都无章），整名须 ≥6 字且非常见泛概念名，
   或强片段 ≥3 个。
5. **泛概念名黑名单** `_GENERIC_KP_NAMES`：放大倍数/输入电阻/输出电阻/功率放大/逻辑函数…
   在无章题中不得仅凭其名成链。
6. **跨科兜底默认关闭**（`--cross-subject` 才开），且开启时要求整名 ≥6 字 + ≥2 强片段。
7. 第 1 层已链上的题**不再进第 2 层**（避免重复挂与虚高）。

## 5. 关键诊断：为何规则层几乎无增量

- 未链题**全部无 `chapter`**（层 1 已把所有"有章+同科同名"的题链完）。
- 同科内命中极低：模电 1230 题中仅 **112** 题题干含任一"本学科 KP 强片段"；数电 756 题中仅 **16** 题。
- 事实：剩余未链题**多为 OCR 碎片、答案串、或科目字段写错**（如"政治"栏下放的是模电半导体内容），
  其题干**根本不含对应学科的知识点名** → 词法匹配天然无能为力。
- 修复前那 900+ 条"命中"，**1092 条来自跨科兜底**（匹配到它科泛概念名），即噪声主体，已按精度要求关闭。

## 6. LLM 层（第 3 层）现状

- 已实现：复用**项目既有** `services.model_gateway._chat_openai_compat`（不另写 HTTP），
  批量（默认 8 题/次）分类，解析容错，失败静默跳过。
- **本机可用性**：Ollama 在运行（装有 `kaoyan-assistant` / `qwen3:4b` / `qwen2.5:1.5b` 等）；
  云 API（豆包/DeepSeek/通义）**均已启用但 API Key 为空**。
- **实测质量不足**：`qwen2.5:1.5b` 输出 JSON 混乱、几乎全错；`kaoyan-assistant` JSON 规范但
  判定仍偏差大（抽查 8 题仅 2 条可被"题干字面佐证"）。故已加**强制字面佐证闸门**
  （`LLM_REQUIRE_CORROBORATION=True`，可 `--llm-uncorroborated` 关闭）。
- 结论：**本机 LLM 不足以可靠分类**，第 3 层默认不产生有意义的有效增量。

## 7. 结论与建议

- **规则层已达精度上限**：可靠增量 ≈ 0（第 2 层仅 3 条，且抽查 100% 正确）。
  覆盖率稳定在 **64.5%**，**不写库也不会丢任何"高置信"关联**。
- 若要继续提升覆盖率，只能依赖**语义级**判断，需其一：
  1. 配置云端大模型 API Key（豆包/DeepSeek），第 3 层才可能达 >85% 准确率；
  2. 或引入/训练更强的本地分类模型。
- 风险提示：强行回填那 3260 题会大量污染"薄弱点分析 / 按知识点刷题"，**不建议**。

## 8. 遗留问题

- 未链题中的 OCR 碎片/答案串（如 `BDBBA DCDCC`）**本就不应关联**，需数据清洗而非回填。
- 部分题目 `subject` 字段写错（政治↔模电/数电），应做**科目纠正**后再回填，属独立数据治理项。
- `knowledge_points.question_count` 回填口径已改为**去重关联题数**（primary+related），待写库时生效。
