## 1. 对标方法论：三层，抄哪层很关键

| 层 | 含义 | 能不能抄 |
|---|---|---|
| **机制层** | 调度算法（SM-2/FSRS）、判题流程、检索增强、闭环逻辑 | ✅ **大胆抄**——这是经过验证的通用规律 |
| **信息架构层** | 层级组织（科目→章→知识点）、筛选维度、导航结构 | ✅ **可抄架构**——但要换成 834 专业课的骨架 |
| **视觉层** | 配色、圆角、动效、字体 | ❌ **不抄**——沿用本平台 `tokens.css` / `v2-design.css`，不引入新 UI 库 |

> 铁律：**抄信息架构不抄视觉风格**。对标产品的截图只用来理解"信息怎么组织"，不用来抄皮肤。

**三条取舍原则**：
1. **不抄社交**（排行榜、社区、打卡分享）——单人本地平台，社交是负担不是价值
2. **不抄广告与商业化**（课程推销、会员墙）——你是自己的唯一用户
3. **不抄"为了通用而牺牲专业"的设计**——通用平台做不了电路图深解析，那是你的护城河

| **学习者画像** | `LearnerProfile` | **Khan Academy 掌握度面板** | 知识点掌握度雷达、能力诊断 | 课程推荐 |

### B 组｜知识域

#### B1 `KbMap` 知识图谱（`/knowledge`）

**对标**：**codebrick.tech/practice/panorama**（信息架构），加 Obsidian 双链感。

**现状**：路由 `/knowledge` → `KbMap.jsx`；`/panorama` 和 `/kbmap` 都重定向到这里（之前做的 Panorama 页被合并了）。

**要做成**：

```
┌─────────────┬────────────────────────────────────────────┐
│ 科目树       │  数字电子技术 · 第3章 组合逻辑电路            │
│ ▸ 电路  280  │  ┌──────────────────────────────────────┐  │
│ ▾ 数电  113  │  │ 知识点矩阵（热力 = 掌握度）            │  │
│   ▾ 第1章    │  │  ┌────┐┌────┐┌────┐┌────┐          │  │
│     · 逻辑门 │  │  │编码器││译码器││选择器││加法器│          │  │
│     · 卡诺图 │  │  │ 85% ││ 42% ││ 60% ││ 73% │          │  │
│   ▾ 第3章    │  │  └────┘└────┘└────┘└────┘          │  │
│     · 编码器 │  └──────────────────────────────────────┘  │
│ 政治  51     │  选中「译码器」→                            │
│ 数学  45     │  ┌──────────────────────────────────────┐  │
│ 模电  11     │  │ 释义 | 关联题 273 道 | 掌握度 42%     │  │

│              │  └──────────────────────────────────────┘  │
└─────────────┴────────────────────────────────────────────┘

**关键交互**：
- 左树三级：科目 → 章节 → 知识点（后端 `taxonomyApi.tree(subject)` 已就绪）
- 中间矩阵用**颜色深浅表示掌握度**（`knowledge_points.mastery`），点格子选中
- 选中后右侧出详情 + 三个动作按钮（刷题 / 看文档 / 问 AI）
- **必须带"关联题量"**（`question_count`），让用户看见"这个知识点有多少题可练"

**数据支撑**：`knowledge_points`（500 条，全带 description）、`question_knowledge_links`（当前 0，待回填）、`taxonomyApi.coverage()`

**验收**：从打开页面到"点某个知识点 → 开始刷这个知识点的题"不超过 3 次点击。

#### B2 `KnowledgeArticle` 知识点详情（`/knowledge/:id`）

**对标**：Wikipedia 条目 + Notion 页面。

**形态**：释义正文 + 右侧"关联题/关联文档/前置知识点"三栏卡 + 底部"问 AI"。
**验收**：看完释义能一键跳到配套题，不用回列表找。

#### B3 `Documents` / `Library` / `Textbooks` 文库

**对标**：**Zotero**（文献管理）+ 百度网盘（文件树）。

**形态**：左侧目录树（按学科/年级）→ 右侧文件列表（卡片/表格切换）→ 预览弹窗（PDF 内嵌 + 提取的文字并排）。
**关键**：预览时必须能**调用 OCR 结果**（当前 `documents` 135 篇、`knowledge_chunks` 4024 条，OCR 已修复）；支持"导入到题库"（`DocQuestionPreviewModal.jsx` 已存在）。
**验收**：搜一个术语能同时命中文档名和正文；预览能看图也能看字。

### C 组｜刷题域

#### C1 `Quiz` 刷题（`/quiz`）

**对标**：**LeetCode**（闭环）+ 牛客（筛选）。

**现状**：`Quiz.jsx` 已有三 tab（`knowledge | year | review`），是主力页。

**要做成**：

```
┌──────────────────────────────────────────────────────────┐
│ 科目[数电▾] 章节[第3章▾] 知识点[译码器▾] 题型[单选▾] 难度[中▾]│
│ 排序：默认 | 正确率 | 最近错   共 273 题   [开始练习]      │
├──────────────────────────────────────────────────────────┤
│  第 1 / 273 题                           ⏱ 02:31  ✅ 已答  │
│ ┌──────────────────────────────────────────────────────┐ │
│ │ 【单选】如图所示电路，当使能端有效时输出为？           │ │
│ │   [题目原页配图]  ← 关键：题目有图必须显示            │ │
│ │   A. 全 0    B. 全 1    C. 高阻    D. 随输入变化      │ │
│ └──────────────────────────────────────────────────────┘ │
│  [提交答案]                          [收藏] [报错] [问AI]  │
├──────────────────────────────────────────────────────────┤
│  判定结果：❌ 你选 B，正确答案 A                            │
│  解析：使能端无效时所有输出被禁止…                          │
│  考点：译码器 > 使能端  [加入错题本] [出一道变式题]        │
└──────────────────────────────────────────────────────────┘
```

**关键交互**：
- **筛选必须支持 `kp_id`**（后端已支持，前端 `Quiz.jsx` 需接入——这是已识别的待办）
- 提交后即时判定 + 解析 + 归因知识点 + 一键入错题本 + 一键出变式题（C3/C7 能力）
- **题目配图必须显示**——云端 `extract_questions.py` 已产出原页 PNG，本地入库后前端渲染
- 每道题可"问 AI"（C2 讲题能力）

**数据支撑**：`quiz_questions`（**当前 0 条，P0 阻塞**）、`options`、`answer`、`analysis`、`image`、`question_knowledge_links`

**验收**：选知识点 → 刷 → 判 → 看解析 → 入错题，全链路 5 次点击内完成；带图题目正常显示。

#### C2 `ExamCenter` 真题模考（`/exam`）

**对标**：研招网真题 + 考研帮模考。

**形态**：年份选择（横向时间轴）→ 卷别 → 进入限时答题（复用 `Quiz` 组件）→ 交卷出成绩报告（得分/用时/知识点正确率雷达）。
**关键**：`/exam/year/:year`、`/exam/paper/:paper` 路由已存在并复用 `Quiz`。
**验收**：选一套真题能完整答完并出诊断报告。

### D 组｜错题与记忆

#### D1 `ErrorReview` 错题本（`/error-review`）

**对标**：**Anki**（调度）+ 墨墨（数据呈现）。

**现状**：`/errors`、`/cuoti` 都重定向到这里；已有 `ErrorReview.css`。

**要做成**：

```
┌──────────────────────────────────────────────────────────┐
│ 今日待复习 12  ▸ 已掌握 38  ▸ 全部 96      筛选[科目▾][知识点▾]│
├──────────────────────────────────────────────────────────┤
│ ┌──────────────────────────────────────────────────────┐ │
│ │ 错因标签：概念不清 · 计算失误 · 审题错                  │ │
│ │ 题干（含原图）+ 你的错误答案 B + 正确答案 A             │ │

│ │ 上次复习 3 天前｜下次 今天｜掌握度 ▓▓▓░░               │ │
│ │ [掌握了] [模糊] [忘了]        [出变式题] [移除]        │ │

└──────────────────────────────────────────────────────────┘

**关键交互**：
- **复习单元不是裸题，而是"错题卡"** = 题干 + 我的错解 + 正解 + 关联知识点 + 变式题

- **错因标签**用于归因统计（喂给 C3 错题归因能力训练）

**数据支撑**：`error_records`、`error_knowledge_links`、`ebbinghaus_items`、`study_events`（0 行待埋点）

**验收**：每天打开就有"该复习哪些"的队列，且复习后下次出现间隔按掌握度变化。

### E 组｜规划域

#### E1 `Planner` 计划 / `Tasks` 任务

**对标**：**Todoist**（任务结构）+ Notion Calendar（时间视图）+ Forest（专注计时）。

**形态**：
- **月/周甘特**：把"复习章节"排到日历格，可拖动
- **今日清单**：从计划自动派生今日任务（刷题 X 题、复习 Y 卡）
- **番茄钟**：点任务进专注模式，计时写入 `focus_sessions`

**关键**：计划必须**基于知识点优先级**（考频 × 掌握度），不是随意排——这是 C12 学习规划能力的落点。
**数据支撑**：`phase_plans`、`month_plans`、`daily_plans`、`goals`、`focus_sessions`、`milestones`
**验收**：计划能自动派生今日任务，且做完能回填进度（闭环）。

### F 组｜AI 域

#### F1 `Assistant` AI 助手（`/assistant`）

**对标**：**ChatGPT / Kimi**（交互层）。

**形态**：

```
┌──────────────────────────────────────────────────────────┐
│ 模式：[答疑] [讲题] [出题] [总结] [批改]     模型 v5 ▾     │
├──────────────────────────────────────────────────────────┤
│ 学生：译码器的使能端到底干嘛用的？                          │
│ 老师：先问你一个——如果使能端无效，你觉得输出该是全0还是保持？│
│      （苏格拉底引导，答完再展开）                           │
│      结论：使能端是"总开关"…                                │
│      记忆建议：今天、1天后、3天后、7天后各回顾一次。          │
│      ── 引用：数字电子技术基础 P128 ──                      │
├──────────────────────────────────────────────────────────┤
│ [输入问题…]  [上传题目图片]  [使用当前知识点上下文]         │
└──────────────────────────────────────────────────────────┘
```

**关键交互**：
- **模式切换 = 不同 prompt 模板**（C1–C9 能力路由），不是同一个对话框硬套
- 流式输出 + **引用来源**（RAG 检索到的 chunk，标注文档与页码）
- 支持**上传题目图片** → 走 `qwen2.5vl:7b`（C11 识图能力）
- 底部可带入"当前知识点上下文"（从知识图谱点进来时）

**验收**：问一个专业课概念，回答先引导后讲解、带引用、不复述题目；传图能识别并作答。

### G 组｜院校域

#### G1 院校系列（`KaoyanSchools` / `KaoyanAnalysis` / `KaoyanCompare` / `KaoyanGuide`）

**对标**：**研招网**（数据结构）+ 掌上考研（信息聚合）+ 各校研院官网（公告源）。

**形态**：
- **院校列表**：筛省份/层次/大区（A区B区）/类型（公办·科研院所·军队）→ 卡片列表
- **院校详情**：简介 + 学院/专业树 + 招生计划表 + 分数线趋势图 + **公告时间线（未读高亮）**
- **对比页**：多校并排对比（分数线/招生人数/考试科目）

**关键**：**公告未读标记**是用户点名要的（防止错过通知）——每条公告可标已读，首页显示"今日新增 N 条未读"。
**数据支撑**：`kaoyan_schools`（**当前 0**）、`kaoyan_notices`（**当前 0**）、`kaoyan_majors`、`kaoyan_admissions`、`kaoyan_scorelines`
**验收**：能筛到目标院校、看到分数线趋势、公告有未读标记且能一键标记。

## 4. 视觉与交互基线（不引新 UI 库）

**沿用现有设计系统**：`frontend/src/styles/tokens.css` + `tokens.js`（设计变量）+ `v2-design.css` + 各页面专用 css（`kbmap.css`、`error-review.css`、`exam-center.css`、`dashboard.css` 等）。

| 项 | 基线 |
|---|---|
| 配色 | 走 `tokens.css` 变量，深色/浅色双模已支持 |
| 组件 | 用项目内 `components/UI.jsx` 等，不装 antd/MUI/Chakra |
| 图标 | lucide-react（已在用） |
| 图表 | 若需热力图/雷达，优先轻量方案（recharts 已在依赖里则复用，否则手写 SVG） |
| 动效 | 克制：200ms 内的过渡，不做花哨进场 |
| 响应式 | 桌面优先（你是本机用），窄屏不塌即可 |

**一致性强约束**：新增页面必须复用 `kbmap.css` / `v2-design.css` 的 class 命名风格，不另起一套。
