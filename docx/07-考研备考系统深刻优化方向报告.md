## 一、为什么现有优化方向"浅"

既有清单（VLM 乱码修复、PaddleOCR 部署、分压图误判、103 冲突复核、缓存、e2e 扩充）有一个共同特征：**全部是"点状修复"**，停留在"让现有功能正常"的层面。它们没有回答三个根本问题：

1. **系统应该长成什么**——是题库仓库，还是学习闭环引擎？
2. **数据如何增值**——1014 题回填后，题目数据是否形成了可评估、可调度、可复用的资产？
3. **AI 能力如何编排**——Ollama / 视觉塔 / 专有答疑服务各自为战，还是协同作战？

对照头部开源项目后可以确认：上述问题在成熟项目里已有答案，且答案集中在**数据闭环、检索质量、多 Agent 编排、多模态内容生产、工程治理**五个层面，无一落在"修 bug"层面。

## 三、深刻优化方向（五大层）

### 方向一：从"题仓库"到"学习闭环引擎"（数据架构层）

**现状**：已有 60 表、1014 题回填，但缺"薄弱知识点聚合表"与"复习调度表"；103 条交叉冲突靠自动消解，无置信度概念；papers 表 0 条，公共课真题未归位。

**对标**：408-ai-tutor 的 wrong_questions / misconceptions / weak_knowledge / review_notes / agent_exports 五表设计；errbook 的间隔调度；OpenExam 的成长体系。

**落地动作**：

1. **答案置信度体系**：为每条答案标注来源（题库内置/来源提取/LLM 生成/用户确认）与置信度。高置信度参与自动判分，低置信度仅作参考展示。103 冲突不再"自动消解"，改为进入**人工确认队列**并标记来源——这是冲突问题的根治而非压制。
2. **薄弱知识点聚合**：按知识点维度聚合正确率与错误模式，形成 weak_knowledge 表，支撑"哪里弱补哪里"。
3. **复习调度表**：引入间隔重复调度（借鉴 Anki SM-2），为错题/薄弱点生成"待复习队列"。
4. **题库包工程化**：借鉴 bank.db（metadata+校验和+QC 报告）。公共课真题（D:\真题（公共课））通过 MinerU 高精度提取后构建为可导入题库包，解决 papers 表 0 条；导入后自动生成 QC 报告（题目数/缺选项/缺答案/图片完整性）。

### 方向二：从"单模型问答"到"多 Agent 智能导师编排"（架构层）

**现状**：8765 专有答疑仅覆盖公共课，数电/模电未接入；视觉塔、OCR、答疑服务各自为战。

**对标**：kaoyan-copilot 的 Supervisor 编排；kaoyan-mentor 的画像+复盘闭环。

**落地动作**（轻量落地，不引入 LangGraph 重量依赖）：

- 在 FastAPI 内实现**轻量路由编排器**，按意图将请求路由到：
  - **Tutor**：学科答疑（接入 8765，补齐数电/模电；视觉塔负责读图，文本模型负责讲解）
  - **Planner**：画像建档 → 生成计划 → 按完成度复盘调整（借鉴 kaoyan-mentor 闭环）
  - **Consultant**：择校决策支持（分数线/报录比/名额核验，借鉴 KaoyanPlan 信息差方法论）
  - **Radar**：院校情报监控（招生简章变化、复试线）
  - **Estimator / Interviewer / Mentor**：估分、模拟复试、心理支持（P1 后扩展）
- **模型分级降级链**：7b 主答 → 3b fallback（已验证有效）→ 专用 OCR 兜底 → 门控拒答，形成显式降级路径而非隐性乱码。

### 方向三：从"有检索"到"可门控、可评估的检索质量工程"（检索层）

**现状**：专有答疑与 RAG 检索无质量门控，VLM 乱码/幻觉靠换小模型"碰运气"。

**对标**：edu-rag 全流程。

**落地动作**：

1. **混合召回**：稠密向量（Ollama 本地 embedding，如 bge-m3）+ BM25 稀疏检索 + RRF 融合，弥补纯向量召回在公式/符号上的短板。
2. **重排**：本地 CrossEncoder（bge-reranker-base）对候选重排，复杂问题按子问题感知重排。
3. **检索门控**：证据不足时**拒答而非硬答**；复杂问题拆解子问题 → 子答案并行生成 → 合成最终答案。视觉塔乱码的系统级解法是"门控+拒答"，不是继续赌模型。
4. **RAGAS 评估闭环**：自动沉淀成功问答为测试集，定期跑 faithfulness / answer_relevancy；统计拒答率、错误接受率、重试恢复率。让"答疑质量"成为**可量化指标**。

### 方向四：从"文本 OCR"到"多模态知识表达流水线"（内容生产层）

**现状**：PaddleOCR 未部署；题图质量无校验；公式/电路图无结构化表达。

**对标**：MathLens、MathFormula2Tex、Lazy-Kaoyan、pictureVerification、GEEQuestionBank。

**落地动作**：

1. **三级视觉管线**：版面分析（MinerU/PaddleOCR 版面模型）→ 图文分离 → 视觉 LLM 结构化（含公式 LaTeX 化，借鉴 MathFormula2Tex）。
2. **题图入库校验**：借鉴 pictureVerification，录入时自动检查清晰度/倾斜/截断，不合格直接拒收，从源头保证质量。
3. **错题→变式生成**：借鉴 GEEQuestionBank，对高频错题做考点分析并生成变式新题，实现"举一反三"。
4. **可视化讲解**（P1 后扩展）：借鉴 MathLens，对数电波形/模电电路图生成 SVG 动画讲解，配合 TTS 形成微课。
5. **知识双链组织**：借鉴 Lazy-Kaoyan，"章节→知识点→方法→题型→题目/错题"知识网络，思维导图作为复习入口。

### 方向五：从"能用"到"可演进的产品化工程"（工程治理层）

**现状**：kaoyan_ai pipeline/ 130+ 脚本缺统一 CLI；无迁移/回归/冒烟体系；优化文档无状态可见性。

**对标**：edu-rag 单命令 CLI、SelfLearning 状态前缀、408-ai-tutor 的 pytest+QC、OpenExam 的产品化。

**落地动作**：

1. **单命令 CLI**：start / stop / status / logs / health，收敛 130+ 脚本入口。
2. **状态前缀治理**：pipeline 脚本按 done/doing/todo 标注，让"完成了什么"一目了然。
3. **工程底座**：alembic 迁移、pytest 回归、接口冒烟脚本。
4. **数据开放给桌面 Agent（MCP）**：借鉴 408-ai-tutor，将错题/薄弱点/误区导出为结构化快照，让 Marvis 可直读平台数据，自动生成周复盘/复习清单。
5. **成长体系产品化**：借鉴 OpenExam 等级/成就/学习日历，以游戏化对抗备考倦怠（注意避开课堂投屏规范中的排名约束——此平台为个人备考，无此限制）。

## 四、落地优先级路线图

| 优先级 | 方向 | 关键动作 | 直接解决现状问题 |
| :--- | :--- | :--- | :--- |

## 五、结论

本平台的差异化定位不是"复刻某个开源项目"，而是将开源生态的最佳实践**收敛为离线私有化产品**：

| 层面 | 学习对象 | 学习点 |
| :--- | :--- | :--- |
| 数据层 | 408-ai-tutor | 置信度 + QC + 数据开放 |
| 检索层 | edu-rag | 门控 + 重排 + 评估 |
| 编排层 | kaoyan-copilot / kaoyan-mentor | 多 Agent + 画像闭环 |
| 表达层 | MathLens / MathFormula2Tex / Lazy-Kaoyan | 可视化 + 结构化 + 双链 |
| 产品层 | OpenExam / Anki | 本地优先 + 间隔重复 + 成长体系 |

这一组合的独特价值：**本地离线、数据私有、模型可控、闭环可评估**——这恰好是商业 SaaS 产品无法提供的优势，也是本平台相对 GitHub 单点项目能"更深刻"的根本所在。
