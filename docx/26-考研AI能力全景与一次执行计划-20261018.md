## 1. 能力全景：13 项，分四层

学生视角的完整需求不止“答疑”。按**实现层**分四类，避免把一切都塞给大模型：

### 第一层：理解与应答（模型生成，进 LoRA）

| # | 能力 | 输入 → 输出 | 成功标准 |
|---|---|---|---|
| C1 | **答疑能力** | 学生提问（可带检索上下文）→ 引导式讲解 | 先结论后原理；不复述题目；概念不清先抛引导问题 |
| C2 | **讲题能力** | 完整题目+选项+学生答案 → 对错判定+分步解析+错项分析 | 判定准确；步骤可复现；指出每个错项为什么错 |
| C3 | **错题归因+变式** | 错题+学生错解 → 错因定位到知识点 + 生成 1 道变式 | 归因知识点正确；变式同考点不同数 |
| C4 | **批改能力** | 题目+学生手写解答 → 判定+扣分点+正确路径 | 计算题能找到中间错误步；不误杀正确解法 |
| C5 | **主动追问（苏格拉底）** | 学生问概念 → 先反问定位盲点，再讲解 | 反问要精准（一问命中盲点），不是泛泛"你想问什么" |
| C6 | **易混辨析** | 两个相近概念 → 对比表+判定方法+典型错例 | 判定标准可操作（"看X就选A"式） |

### 第二层：生成与生产（模型生成，进 LoRA）

| # | 能力 | 输入 → 输出 | 成功标准 |
|---|---|---|---|
| C7 | **智能出题** | 知识点+题型+难度 → 新题+答案+解析 | 题目可解、答案唯一；人工抽检通过率 >80% |
| C8 | **总结提炼** | 章节/多文本块 → 结构化笔记（基础版/冲刺版） | 覆盖该章高频考点；无原文没有的内容 |
| C9 | **记忆卡片生成** | 知识点 → 问答卡片（SM-2 格式） | 正面问、背面答；答案一句话可说清 |

### 第三层：识别与视觉（管线+独立视觉模型）

| # | 能力 | 实现 | 状态 |
|---|---|---|---|
| C10 | **题目/资料识别** | OCR → 分类 → KP 挂靠（`smart_ingest` + `chunk_classifier` + `quiz_quality_gate`） | ✅ 管线已有，OCR 已修复 |
| C11 | **识图作答** | 图片题目 → 识别+解答（`qwen2.5vl:7b`，Ollama 已有） | 🔶 模型已有，缺训练图库 |

### 第四层：规划与自治（产品逻辑+定时管线，模型只出文案）

| # | 能力 | 实现 | 状态 |
|---|---|---|---|
| C12 | **学习规划** | 目标+剩余时间+掌握度 → 日/周计划（SM-2 算法排程，模型生成计划文案） | 🔶 算法用现成 SM-2，文案待接模型 |
| C13 | **自主学习飞轮** | 新资料 → OCR → 入库 → KP → 图谱 → 合成数据 → 定期重训 | 🔶 各环节已有代码，未串成环 |

> **明确不做成模型能力的**（属产品逻辑，别浪费训练数据）：督学提醒、学习统计看板、进度跟踪、已读未读——这些是 CRUD + 规则，与模型无关。

## 2. 架构决策：一个模型 + 三条管线 + 产品层

```
┌─────────────────────────────────────────────┐
│  LoRA 模型（Qwen2.5-7B，Ollama Q4 本地部署）   │
│  学 9 项生成能力：C1-C9                      │
│  训练地：DSW（A10 24GB）  部署地：本地 Ollama │
├─────────────────────────────────────────────┤
│  视觉模型（qwen2.5vl:7b）                    │
│  C11 识图作答，先 RAG 直接用，后期单独 LoRA    │
├─────────────────────────────────────────────┤
│  管线层（本地 Python，不训练）                │
│  C10 识别入库 / C12 SM-2 规划 / C13 定时飞轮  │
├─────────────────────────────────────────────┤
│  产品层（FastAPI + React）                   │
│  路由：按功能位选 prompt 模板 + 是否挂 RAG    │
└─────────────────────────────────────────────┘
```

**为什么 9 项生成能力训进同一个模型**：它们共享同一套“辅导老师”人格与知识，数据格式同为 ChatML，一次训练全部获得。分开训 9 个模型既浪费部署资源又丢上下文。

### 3.2 各能力数据集构造表

| 能力 | 数据集 | 构造方法 | 工人 | 目标量 | 依赖 |
|---|---|---|---|---|---|
| C1 答疑 | `v3`（已有） | 定义句+主题问答 | build_qa_dataset.py | 2,484 ✅ | 无 |
| C2 讲题 | `quiz_explain` | 题干+答案 → 分步解析+逐项分析选项 | 7b 合成 | 1,500 | 题库恢复（否则纯合成） |
| C3 错题归因 | `error_attrib` | 题目+人造典型错解 → 错因+变式 | 7b 合成 | 800 | 题库或 chunks |
| C4 批改 | `grading` | 题目+含错误步的解答 → 判定+扣分点 | 7b 合成 | 600 | 题库或 chunks |
| C5 主动追问 | `socratic` | KP → 2-3 轮引导问题链 | 7b 合成 | 800 | KP（已有） |

| C7 智能出题 | `gen_quiz` | KP+chunk → 新题+答案+解析 | 7b 合成 | 1,200 | KP（已有） |
| C8 总结提炼 | `summarize` | 多 chunk → 结构化总结 | 7b 合成 | 800 | chunks（已有） |
| C9 记忆卡片 | `flashcards` | KP → 正/反面卡片 | 模板+7b 润色 | 500 | KP（已有） |
| C11 识图 | `vl_dataset` | 图片题目 → 解答 | 人工+vl 自举 | 300+ | 题库图片 |

**合成数据总目标：约 6,700 条**。加上 v3 的 2,484，v4 混合训练集约 9,000+ 条。

### 3.3 合成数据的铁律（违反即污染模型）

1. **答案不得是题干切片**——照抄样本必须 0 条（`answer_is_copy` 门禁已有）
2. **不得编造原文没有的知识**——合成 prompt 必须给出 seed 文本，要求"只依据所给资料"
3. **出题类必须人工抽检 20%**——题目不可解/多解是最大风险
4. **确定性**——同一 seed 每次生成同样结果（crc32 选模板，不用内置 hash）
5. **每能力独立分布统计**——科目/题型/长度失衡要在合并前发现

## 7. 铁律（执行 AI 必须遵守，违反即返工）

1. **备份数据库只能**用 `services/backup_service.py::create_backup()`，严禁 cp/shutil.copy .db
2. **删除记录前**过 `services/delete_guard.py::require_physical_delete_enabled`
3. **科目唯一来源**：`services/subject_registry.py`，不新造科目字典
4. **git 禁用** stash/reset/checkout/restore；提交前 `git status` 确认只有自己的文件
5. **DSW 上禁** `pip install -U <核心包>`（torch/transformers/peft），缺什么补什么，见 `env_setup.sh`
6. **训练数据只从 JSONL 读**，不直连数据库训练（数据库在本地，DSW 够不着）
7. **adapter 回传 OSS，不传 15GB 合并模型**——merge 在本地做
8. **合成数据**必须过照抄门禁 + 出题类人工抽检，不抽检不上训
9. **模型上线用新 tag**（kaoyan-assistant-vN），对照评测通过才切换，不覆盖在跑模型
