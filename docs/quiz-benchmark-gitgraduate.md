# 刷题平台功能对标调研：本站刷题模块 vs gitgraduate（研码）

- 调研日期：2026-10-18
- 方法：gitgraduate 用 fetch_content 抓公开页面（首页 / 题库页 / 英语科目页 / challenge / community / sitemap / 404 页）；本站只读代码（未启动浏览器、未启动后端）。
- 前提：本站 `quiz_questions` 表当前 0 题（任务给定，数据冷启动另线进行）。本站代码里真实库为 Postgres（`backend-main-fastapi/pipeline/load_postgres.py`），`database/kaoyan.db` 为本地 SQLite 旁路，未逐一核库表行数，按任务前提处理。
- 证据等级标注：【一手页面】= 公开页面实际抓到的内容；【页面文案】= 官方宣传页描述（意图，非实测行为）；【代码】= 本站当前实现；【未验证】= 拿不到证据，如实记录。

## 一、结论摘要

gitgraduate（研码）是「数据厚 + 学习闭环重 + 运营驱动」的考研刷题站：题库按 **科目 → 赛道卷别 → 题目来源 → 三级知识点树** 组织（数学真题 1224 + 题册 2120 + 模拟卷 5077；全站真题 5,218 道，2000–2026），筛选维度极细（难度 / 题型 / 年份含近 N 年快捷 / 个人掌握度四档 / 全站做过人数），核心体验件是「真题地图（年份×卷别×题号格子）」「每日一题」「知识图谱掌握度分档」「错题→记忆卡→间隔重复」，运营抓手是 99 元押金挑战赛、社区、线上自习室。【一手页面】

本站刷题模块的**功能框架已经相当完整且局部领先**（练习/背题双模式、点选即判 + 文本题自评、智能组卷三模式、错题闭环含艾宾浩斯队列、AI 讲题三问+追问、后端 /quiz/questions 筛选参数面比对方公开可见的还宽）。真实差距集中在五处：① 题库数据量与元数据完备度（0 题冷启动，一切空转）；② 知识点树深度与逐级题量计数；③ 真题「原卷题号」未回填（question_no 是录入顺序号，真题地图对不上原卷）；④ 刷题入口未露出后端已有的 难度/题型/年份/掌握度 筛选；⑤ 全站热度/全站正确率等社会性证据与每日一题缺位。

整体置信：**高**（对方结论全部有公开页面直接证据；登录墙内功能只以首页文案为据，均已标注）。

### 2.2 刷题模式与视图
- **专项刷题 / 套卷刷题** 两态切换。【一手页面】question-bank
- **薄弱点练习 / 随机练习** 两个快捷练习入口。【一手页面】question-bank（知识点导航栏底部）
- **总览 / 列表 / 卡片堆** 三种做题视图（卡片堆=「一次一张，专心做，做完一张翻下一张」）。【一手页面】question-bank + 【页面文案】首页「卡片堆」卡
- **限时** 开关。【一手页面】question-bank
- **每日一题**：按卷别出题（数学一/二/三；英语一/二/2008–09 通用卷），首页方格纸呈现，「选择题点选项就判，填空、解答题先算再对答案。做完就能看解析和研码全站的正确率」，不登录可做。【一手页面】question-bank「每日一题」块 + 【页面文案】首页
- **练习判分方式**（每日一题描述）：选择题点选即判、填空/解答先做再对答案——与本站一致。

### 3.2 API 层（frontend/src/api/client.js）
- `quizApi`（L333 起）：questions/create/update/remove、submit、modes、stats、subjects、sections、years、papersIndex、frequency（考频聚合 kp/chapter/paper）、wrongReasons、exportCsv、batchDelete。**没有独立 examApi**——真题能力（papersIndex/years）都在 quizApi 内；任务提到的 `examApi` 在代码中不存在。
- 后端 `/quiz/questions`（backend-main-fastapi/routers/quiz.py L59-79）支持：subject、chapter、difficulty、source、source_kind（exam/textbook/custom）、question_type、mode（sequential/random）、q（题干关键词）、year、paper、kp_id、include_junk、answerable、is_retest（初试/复试）、分页；返回 total_count/answerable_count/applied 口径字段。
- 配套：errorsApi（错题 CRUD/aiAnalyze/graduate/知识点关联）、flashcardsApi（记忆卡 due/review，间隔重复）、quizSectionApi（weakPoints/wrongReasons/reviewStats/reviews/submitReview）、taxonomyApi（科目/树）。

### 3.3 现状短板（代码可证）
1. `question_no` 是「套卷内录入顺序号（非原卷题号）」——QuizYear.jsx 底部口径说明原文自认；格子图与原卷对不齐。
2. 刷题中心首页的练习设置**没有**露出难度/题型/年份筛选（后端参数都在，只差前端 UI）。
3. `paperView` 支持 'deck'（卡片堆，L27 注释与状态都在），但切换器只渲染 grid/list 两键（L113 只分支两态）——卡片堆是「有状态无入口」的死功能。
4. 收藏是「题目快照不含选项」→ 只能浏览模式重看，不能判分（QuizReview.jsx 收藏区明示）。
5. 错题→记忆卡未打通：flashcardsApi 独立存在，错题闭环面板无「生成记忆卡」动作。
6. 无每日一题、无全站热度/全站正确率、无倒计时展示（goalsApi.examCalendar 接口存在但 QuizHome 未消费）。

## 四、对标差距矩阵

「差距性质」：纯前端可做 / 依赖后端数据 / 依赖题库内容。「空数据」= quiz_questions 为 0 时能否演示。

| # | 能力项 | gitgraduate | 本站 | 差距性质 | 空数据可演示 | 优先级 |
|---|---|---|---|---|---|---|

## 五、空数据（quiz_questions=0）下无法演示的功能

- **完全空转**：专项/套卷/知识点练习、筛选结果、真题地图格子、判分/解析、错题闭环全部数据（薄弱点排行、错因分布、待复习队列）、智能组卷、考频分析、掌握度图谱、每日一题、全站热度。
- **仍可演示**：刷题中心信息架构与设置面板、自定义练习空态与提示、练习/背题切换、键盘快捷键框架、题库管理 CRUD（可手工建几道演示题）、错题库/ExamCenter 空态与引导、响应式布局。
- **最小可演示集（建议冷启动对齐的最小口径）**：1 个科目 × ≥1 套真题，按**原卷题号**回填 question_no + year + paper + source_kind=past_exam + 答案与解析 + 挂 knowledge_points 链接。仅这一套即可同时点亮：真题地图、按年份/套卷、题型/难度/年份筛选、判分、解析、错题闭环、智能组卷、掌握度条——P0/P1 的绝大多数演示依赖。

## 六、分期建议

**P0（闭环刚需，先把已有能力点亮）**
1. 数据冷启动对齐（配合另线）：题目入库最小元数据集 = subject/source_kind/year/paper/原卷 question_no/answer/analysis/kp 链接。
2. 刷题入口筛选补全：把后端已有的 难度/题型/年份（含近3/5/10年快捷）露出到自定义练习设置（纯前端）。
3. 真题地图升级：跨年份平铺「年份×卷别」总览、格子用原卷题号、方向键移动+回车开题（前端 + 依赖 question_no 回填）。
4. 掌握度筛选统一：把错题库的未学/薄弱/已掌握口径扩到刷题入口（未学/不会/不熟/熟练四档），后端出统一字段。

**P1（体验）**
5. 卡片堆视图接线（deck 状态已在）；限时模式（前端计时即可）；题干搜索入口接 q 参数。
6. 每日一题：按科目/卷别从真题轮转，首页方格纸呈现（先本地轮转，后端接口后续再加）。
7. QuizHome 挂考研倒计时（消费已有 goalsApi.examCalendar）。
8. 收藏补全：收藏记录存 question_id，重看时按 id 拉全题，使收藏可判分（后端已有数据）。

**P2（锦上添花/依赖规模）**
9. 全站热度/全站正确率（需要真实用户作答聚合，用户量为零时无意义）。
10. 知识图谱全景四档分色；错题→记忆卡一键生成（打通 flashcardsApi）；模考（exam_sessions）；来源题量徽标、卷别赛道分组。
11. 挑战赛/自习室/社区等运营矩阵：另线立项，不属于刷题模块本身。
