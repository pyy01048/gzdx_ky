### a.3 半成品 / 坏状态
1. **P1-3 三处错题入口边界重叠**：ErrorReview 与 QuizReview 都做“错题列表 + 薄弱点 + 错因分布 + 待复习”，同一 `/api/errors` 数据两套 UI；Notebook 是第三处。用户不知道去哪、数据虽同源但体验割裂、维护三套。QuizReview 还有定义未调用的 `loadPanel` 死代码（:15）。
2. **收藏重复**：`/favorites` 8 类筛选（文档/题目/错题/知识点/单词/卡片/链接，图6-5）与 Quiz 内嵌收藏面板重复（`evidence/ui-recon.md` P1-3）。
3. **空数据引导弱**：error_records=0 时三处都空，`/insights` 只有一张空卡（图6-6），缺“去刷题，错题会自动归集”的引导。
4. **调度多套**：error_records 自带 SM-2 列，同时又有 review_schedules（统一表）与 ebbinghaus_items，和单词/卡片同一问题（见02），到期口径需统一。
5. 错题自动归集依赖先有答题数据（quiz_questions/papers 现为 0），当前无源。

### a.4 缺失

### e.5 算法 / 开源 / 许可证
- **SRS/FSRS**：与 02 共用 `services/srs/fsrs.py`（open-spaced-repetition/py-fsrs，MIT）；错题掌握度状态机：未学 unlearned → 薄弱 weak →（连续 N 次 Good）已掌握 mastered（graduate）；再错回退。后端现有 `services/kp_mastery.py` 已作为掌握度口径唯一源（ErrorReview.jsx:35 注释证实），继续以它为准。

- OCR：复用现有 backend-ocr-paddle 与 `/api/errors/ocr`(errors.py:266)，不新引库。

## f) 数据从 0 到有（冷启动）
- 错题本**不预置数据**，它由做题产生。冷启动前提：章节题（03）、真题（04）、代码题（05）先有题、用户开始作答。
- 自动归集随作答即写（F6-02），无需单独导入；上线后可用集成测试模拟“做错一批题”验证：去重（同题不重复）、状态机（毕业/复活）、review_schedules 到期、薄弱点统计正确。
- 历史/演示：如已有旧答题记录，可写一次性回填脚本，从 quiz_attempts/paper_answers/code_submissions 中判错生成 error_records（带 source 与 batch_id，可回滚），但本平台当前这些表也为空，故一般无需回填。
- 质量门：error_records 必须能回溯到源题（question_id 或快照）；活跃错题部分唯一索引防重复；知识点挂接 relevance 阈值过滤低质量启发式链接（error_knowledge_links.source 区分题目/启发式，便于用户删除错误挂接）。
