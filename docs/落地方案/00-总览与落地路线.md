## 2. 目标信息架构（IA）与导航改版

### 2.1 原则
- **学生端 / 后台管理端物理分离**：学习功能进学生端主导航；一切 CRUD/采集/训练/体检进独立 `/admin` 区并加 RBAC。学生导航里不再出现管理页。
- **单一导航数据源**：以 `nav/navConfig.js` 为唯一真源，TopNav、移动端抽屉、面包屑、相关推荐、CommandPalette、设置·界面自定义全部由它派生（落实 NAV-SPEC.md:624）。删除 TopNav/Layout 内联数组。
- **学习闭环顺序显性化**：今日 → 学(文库/知识/教材/网盘) → 练(章节题/真题/代码/单词/卡片) → 复盘(错题/统计/轨迹/收藏) → 择校。

## 3. 统一设计与交互规范要点（强制复用，不再另造）

工程已内置完整设计系统，问题是**有规范未统一执行**。本方案一律沿用：
- **设计 Token**：`styles/tokens.css`、`styles/tokens.js`（明/暗双态 COLORS、CHART、SCALE：基准字号 15px、卡片圆角 18px、间距 4 的倍数、Apple 风格中性底色 `--bg:#F5F5F7`）；`design/design-tokens.json`。禁止再写散落的魔法色值/字号/圆角。
- **组件与页面模式**：`design/COMPONENT-SPEC.md`、`design/PAGE-PATTERNS.md`；统一用 `components/UI`、`components/States`（`LoadingState/Empty/ErrorBoundary`）。
- **三态强制**：每个数据页必须实现「加载骨架 / 空状态（含“去导入/去配置”行动按钮）/ 错误态（含重试，且错误信息绑定真实 HTTP 状态码）」。本次多页只做了其一（如 /words 空态误报成功、/insights 无图表骨架、/schools/:id 错误态无引导）。
- **口径单一来源（本工程反复踩坑）**：倒计时、文档数、连续打卡、正确率、复习队列等每个指标全平台只能有一个权威来源（后端聚合接口），前端不得再算第二份；各卡片不得各自计数（治 P1-6、P2-6）。
- **禁止硬编码演示数据**（治 P0-2）：任何“4081 篇/贵大834”类写死数字一律改为接口数据或专用 mock 开关（仅 dev 环境），并加 lint/评审检查。
- **空数据 UX**：区分“加载中 / 真为空 / 无权限 / 接口失败”四态，空态要给下一步动作（选词书、导真题、配置目标、绑定网盘）。
- **响应式/可访问性**：沿用底部 5 Tab + “更多”抽屉（Layout.jsx:34-86）；保证键盘可达、焦点可见、对比度、`aria-*`。
- **数学/代码渲染**：题干公式统一 KaTeX/MathJax，代码编辑统一 Monaco/CodeMirror（见 03/05）。

## 5. 权限角色方案（从“全开”到最小可用 RBAC）
- 现状：`utils/auth.py` 仅一个全局 `APP_PASSWORD` 开关（未启用=全开），无用户/角色。
- 分期落地：
  1. **先止血（P0）**：启用 `APP_PASSWORD` 或对 `/api/admin/*`、采集/训练/备份/批量删除/导入类接口加服务端鉴权；管理前端入口默认隐藏。
  2. **再做角色（P1）**：三角色——学生（学习数据）、数据编辑（后台内容 CRUD/导入/采集，不可管用户与系统）、超级管理员（全部 + 用户/角色 + 训练/密钥）。后端在 FastAPI 依赖里做 `require_role(...)`，前端路由守卫 + 菜单按角色渲染。
  3. **审计**：后台写操作全部记 `audit_logs`（操作者/动作/实体/前后值/时间）。
- 范围：仅本机/自用可先用单管理员密码过渡；一旦多人或公网部署，必须上完整 RBAC + HTTPS。
- **完整落地方案见 [11-登录与权限]**：users 表（内置管理员 pyy、PBKDF2 哈希、首登强改）、JWT 双 token 替换单密码中间件（保留为应急开关）、`/login` 与路由守卫、`require_admin` 覆盖全部管理路由、表级数据归属清单（公共只读 vs 补 user_id 隔离）与 Alembic 迁移回填、网盘按用户绑定、登录限流与公网安全基线。注意：仓库仅有 `alembic.ini` 壳、无 `alembic/` 目录，需先初始化（见11 e.8）。
