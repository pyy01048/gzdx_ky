### a.3 半成品 / 坏状态
1. **夸克能力边界**：后端注释明确夸克“**既无 OAuth 授权体系，也无文件列表/下载接口**（与百度 xpan 开放平台不同）”（netdisk.py:514），当前仅嵌入 `https://pan.quark.cn/` 的 Web 视图（可配置 web_view_url，:517-518）。这意味着夸克**做不到**百度那样的“站内文件浏览/统一预览/入库”，属平台能力限制而非 bug。
2. 在线预览虽有 `/preview/{id}`、`/content` 代理，但缺少“按文件类型选择渲染器”的完整前端体系（PDF/Office/视频/音频/图片各自的播放器与降级）与体验打磨。
3. 表归属错位：netdisk_files 在 words_misc.py，维护与理解成本高。
4. 管理配置（app_key/secret、test-connection、platform-config）散在学生页弹窗与 /api/admin/netdisk，未归管理端、无鉴权（同全局 P1-5）。
5. 空态/未配置百度 app_key 时（baiduReady，Pan.jsx:295）引导可更清晰（如何申请百度开发者凭证）。

### a.4 缺失
- 百度 OAuth 完整回调（现 oob 手贴授权码，可用但体验一般；可升级标准 redirect 回调）。
- Office 文档在线预览（Word/Excel/PPT）、视频转码/流式、长 PDF 的稳定预览路线。
- 文件与知识点/教材的联动（虽有 classify/ingest 接口，前端未成体系）、资料收藏到学习计划。
- 多账号、账号健康状态、同步进度与失败提示的统一面板。

## e) 具体怎么做（文件级）

### e.1 前端
- **保留 Pan.jsx 的三态状态机与“后端 token-status 唯一真源”原则**（:179,:192,:200），不回退到本地缓存判断。
- 新增 `src/pages/pan/PreviewRouter.jsx`：根据 `/api/netdisk/preview/{id}`(:368) 返回的 mime/扩展名分流；PDF 用已装 **pdfjs-dist**；图片直接代理 URL；音频 `<audio>`；视頻 `<video>`/hls.js（MP4/ m3u8）；Office 走后端预览服务 URL（见下）；不支持给“下载/新窗口”。
- 把百度凭证配置从学生弹窗（Pan.jsx:289-315）迁到 `/admin/netdisk`，学生页只显示是否可用与去授权。
- `IngestMenu` 调 `netdiskApi.ingestFile/ingestAll/classify`（对应 :710/:726/:738/:544），把选中文件纳入 documents/knowledge_chunks，可选择挂教材/知识点（联动 03 知识树）。
- api 归并 `src/api/netdiskApi.js`（现 client.js 内 netdiskApi 可保留命名迁出）。

### e.2 后端
- 续用 `netdisk_service`：token 全程 `_encrypt_token` 加密存储、用态 `_decrypt_token`（:40/:45）；refresh 走 `/refresh-token`(:98)；files 在授权失效干净返回 401（:226,:251）。
- **预览 `/preview/{file_id}`(:368) 增强**：返回 `{provider, file_id, name, mime, size, mode, url}`，`mode∈{inline_pdf,image,audio,video,office_service,download}`；Office 文档由独立预览服务产出可访问 URL（见 e.5），内容仍经 `/content`(:473) 代理并带正确 UA（:479）。
- 标准 OAuth 回调：`/callback`(:108) 支持浏览器 redirect 带 code 自动换 token；保留 oob 手贴作为无公网回调兜底。
- 管理：app_key/secret/platform-config/test-connection 仅 /api/admin/netdisk 并加 RBAC（见00）。

- 模型整洁：把 `netdisk_files` 从 `core/models/words_misc.py:76` 迁到 `core/models/netdisk.py`（**表名保持 `netdisk_files` 不变**，用一次迁移仅改代码归属，不改物理表，避免数据迁移风险）；words_misc 仅保留 re-export 兼容或彻底更新引用。

### e.5 关键算法 / 开源 / 许可证
- **PDF**：前端 pdfjs-dist（Apache-2.0，已在依赖）。
- **Office（doc/docx/xls/ppt）**：自建 **kkFileView**（Apache-2.0，独立预览服务，URL 传后端签名地址，凭据不出主服务）；或 ONLYOFFICE Document Server（**AGPL-3.0，必须独立部署**，不并入闭源主体）。DOCX 前端可先用已装 mammoth（BSD-2-Clause）做轻量展示，复杂排版仍走 kkFileView。
- **视频**：mp4 直出 + hls.js（Apache-2.0）做 m3u8；大文件走 HTTP Range（代理需支持 Range 透传）。
- **百度**：走官方“百度网盘开放平台 / xpan”OAuth 与文件、下载（dlink）接口；UA 等坑已在 netdisk.py:427/:479 处理。**夸克无公开 Web OAuth 与文件 API（netdisk.py:514 已确认），不做 cookie/模拟登录等灰产方案**；仅保留配置化网页视图开关，待官方开放后以官方方式接入（以官方最新文档为准）。
- 安全：token/refresh_token 仅服务端加密；代理接口防 SSRF（只允许指向百度官方域名）、鉴权访问、preview_session 短期签名、操作写 netdisk_operation_logs。

## f) 数据从 0 到有（冷启动）
- 网盘资料是**用户授权后才存在的第三方数据，不预置、不可爬取**。因此本模块“冷启动”= 打通授权与首用体验，而非灌库：
  1. 管理员在 `/admin/netdisk` 配置百度 app_key/secret/redirect_uri（Pan.jsx:295 的 baiduReady 依赖），用 test-connection(:920) 验证。
  2. 用户在 `/pan` 选百度 → OAuth（oob 或标准回调）→ token-status 授权通过 → 自动加载根目录真实文件。
  3. 用户把学习资料文件夹“入库/同步”（sync:307、ingest:710-738），生成 documents/knowledge_chunks（与 03 知识树、00 §7 知识库向量化衔接，必要时跑 build_vectors 建 embedding）。
- 演示/自用：可用一个测试百度账号放少量 PDF/DOCX/MP4 验证预览与入库；无授权账号时，空态明确说明“绑定百度网盘后浏览与预览学习资料，夸克暂仅支持网页版”，不放假文件（避免重蹈 kb-import 假数据 P0-2）。
- 质量门：文件 mime/大小校验；入库文件走与 KB 相同的分块/去重/溯源（带 source=netdisk、fs_id 幂等，netdisk_files 已有 fs_id 字段）；预览会话短期有效；所有第三方访问遵循开放平台条款，仅访问用户授权范围内数据。
