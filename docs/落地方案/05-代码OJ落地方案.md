### a.3 半成品 / 坏状态
1. **P2-3a 考频文案重复 bug（根因已定位）**：`CodeBank.jsx:11`
   `const STARS = (n) => '重点'.repeat(n || 0) + '未选'.repeat(...)`，把考频等级 n 直接当“重点”重复次数；筛选按钮 `:208` 又渲染 `` `${'重点'.repeat(n)}+` `` → n=4 时显示“重点重点重点重点+”。表格 `:238/:273` 同样用 STARS 输出重复串。正确做法是星级图标（★×n）或“高频/中频/低频”标签。
2. **P2-3b 入口过深**：复试代码是独立大能力，却埋在练习下拉第 4 项，无一级入口（IA 改版见 00，提为“练习→复试上机”）。
3. **0 题导致核心链路不可达**：22 科目无 problem，题目详情、Monaco 编辑、提交判题、结果回放在 UI 上走不到。
4. **双前缀边界不清**：学生刷题在 `/api/code`，题库浏览/科目/导入在 `/api/codebank`，前端 CodeBank 同时调两套，后续易重复；且 `/api/codebank` 的导入/爬取类接口无鉴权（见 00 RBAC）。

### a.4 🔴 安全缺口（本模块最严重，提为 P0）
- 现判题器 `services/code_judge.py`：
  - `:20-21` import `subprocess/tempfile`；`:130` 写临时 `.py`；`:136-141` 用 **`subprocess.run(["python", temp_file], timeout=...)` 在后端宿主机直接执行用户提交的代码**。
  - 仅支持 Python（`:38 judge_python_code`）；**无容器/无 namespace/cgroup 隔离**；内存限制注释明确“暂未强制限制”（`:50`）、结果里“简化版不统计内存”（`:168`）；只有 `timeout` 防 TLE（`:181`）。
  - 后果：用户可借提交代码读写宿主机文件、外联、耗尽 CPU/磁盘（任意代码执行）。对一个要上线的 OJ，这是必须先于“补题/多语言”解决的 P0。

## e) 具体怎么做（文件级）

### e.1 前端
- **修 `pages/CodeBank.jsx:11`**：
  - 用星级组件替代字符串重复：`const STARS=(n)=>'★'.repeat(n||0)+'☆'.repeat(5-(n||0))`（或直接用 lucide `Star` 填充 n 个）；筛选按钮 `:208` 改为“考频≥★n”标签；表格 `:238/:273` 同步。
- **重构为目录**：`src/pages/code/CodeProblemListPage.jsx`（现列表）、`CodeProblemSolvePage.jsx`（新增答题页）、`CodeEditor.jsx`（Monaco，用 `@monaco-editor/react`，许可 MIT）、`JudgeResultPanel.jsx`。
- **新增路由（App.jsx）**：`/code`（列表，作为规范入口，/codebank 重定向到 /code 保书签）、`/code/:problemId`（答题页）。
- **api 收敛 `src/api/codeApi.js`**：学生侧一律 `/api/code`：`listProblems(params)`、`getProblem(id)`、`runSample({problem_id,language,code})`、`submit(payload)`、`getSubmission(id)`、`listSubmissions(params)`；管理侧 `/api/codebank/*` 仅在 /admin 调用。
- 提交后轮询 `/api/code/submissions/{id}`（pending→judged），或升级 WebSocket；结果逐点渲染，私有测试点只显状态不显 actual_output。

### e.2 后端
- **统一前缀边界**：学生判题 `/api/code`（code_oj.py）；题库管理/导入/爬取 `/api/codebank`（codebank.py）迁入管理端并加鉴权依赖。两者共用 `code_problems` 数据。
- **判题改为“主服务 → 独立判题服务”**（F5-01，关键架构）：
  - 主 API（FastAPI）只负责入库与排队（可先用 DB 表 status=pending + 轮询，后续换 Redis/Celery/RQ）。
  - 判题 worker **独立进程/容器**，从队列取 submission，调用沙箱执行，回写 code_submissions/code_submission_results。**绝不在 Web 主进程用 subprocess 跑用户代码**（移除/隔离 code_judge.py:136 的直跑方式）。
  - 沙箱要求：每提交一个一次性容器/exec；非 root、只读根文件系统、禁网络（`--network none`）、临时可写目录限额、`--memory`、`--cpus`、`pids-limit`、超时 kill；编译与运行分阶段（CE 提前返回）。
- 状态机：`pending → judging → judged`；逐点 `ac/wa/tle/mle/re/ce`（results 表字段已就绪，:111）；time_ms/memory_kb 回填（替换 code_judge.py 中 memory_kb=None 的简化逻辑）。

### e.5 关键算法 / 开源 / 许可证（务必独立服务隔离）
- **判题沙箱首选 [criyle/go-judge](https://github.com/criyle/go-judge)（约 500★，MIT）**：Go 实现，基于 Linux namespace+cgroup 的隔离执行，提供 HTTP/gRPC，适合作为**独立判题微服务**部署，主 Web 服务通过 HTTP 调它；MIT 许可友好，可自用与商用。
- 备选/参考：
  - [QingdaoU/OnlineJudge](https://github.com/QingdaoU/OnlineJudge)（约 6.5K★，MIT，Django+Vue+Docker）——判题沙箱与整体架构可参考。
  - [Judge0](https://github.com/judge0/judge0)（约 4.3K★，**GPL-3.0**）、[Hydro](https://github.com/hydro-dev/Hydro)（约 6.6K★，**AGPL-3.0**）、[zhblue/hustoj](https://github.com/zhblue/hustoj)（约 3.7K★，**GPL-2.0**）——**强传染许可，只能作为独立服务部署、严禁把其代码拷进本平台闭源主体**；如直接用 Judge0/Hydro，必须进程隔离 + 遵循其许可。
- 编辑器 Monaco（`@monaco-editor/react`，MIT；Monaco 核心 MIT）。
- 最小可用也可用 Docker 一次性容器 + `--network none --memory --cpus --read-only --pids-limit` 自建（本机 Windows 开发需 Docker Desktop / WSL2 后端；上线用 Linux）。但生产建议直接上 go-judge，避免自造沙箱安全漏洞。

## f) 数据从 0 到有（冷启动）
- 22 个科目骨架已在（codebank `/subjects` :57 与 school-type seed/enrich :86/:93 说明已有种子/补全脚本）。题目导入用 `POST /api/codebank/import`(:100)，题与测试点直接写 code_problems / code_problem_testcases。
- 导入格式（JSON/CSV，UTF-8）：`{subject,title,difficulty,description(md),input_format,output_format,samples:[{input,output}], private_cases:[{input,output,score_weight}],time_limit_ms,memory_limit_kb,tags[],language_scope,source}`。
- **质量门**：题面非空；每道题至少 1 个样例 + 若干私有测试点；expected_output 规范化（去行尾空白/统一换行）判 WA；time/memory 为正；同(subject,title)指纹去重；导入后用标准解与若干“错误解”在沙箱里**自验**（标准解必须 AC、常见错误必须非 AC）再上架；按 batch_id 导入可回滚。
- 冷启动范围：优先 0854 复试常用 C/C++/数据结构/数电相关，每科目先 10–20 道覆盖基础考点，再扩量。
- 次序：**先上线 F5-01 沙箱（安全前置），再批量导入与开放提交**；否则题越多、宿主机直跑风险越大。
