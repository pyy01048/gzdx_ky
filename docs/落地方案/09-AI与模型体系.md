### a.7 缺口/坏状态
1. `/model-training`、`/quality` 白屏（P0-1，根因在00），AI 运维能力“接口全、用户用不到”。
2. **向量 0 行**：知识库已分块但未跑 build_vectors，RAG 实际检索为空；reranker 有服务但无向量可重排。
3. 密钥虽加密落库（见10 secret_codec AES-GCM），但 AI/管理接口当前无鉴权（utils/auth 未启用），公网不可直接暴露。
4. 本地模型的 GPU/并发/显存边界、云调用的成本与配额、限流/熔断/降级，在前端没有统一可观测面板。
5. 电路图 VLM、AI 讲题缺“引用出处/置信度/弃答”在 UI 的一致呈现（后端 gate/confidence 有，前端未贯通）。

- 后端：
  - 在 `model_gateway` 增加 provider 健康缓存（Ollama `/api/tags` :102、云 providers `/test` ai.py:172）+ 熔断（连续失败 N 次冷却）+ 每请求 try 云→catch→本地，落实 auto 降级；超时沿用 local360/cloud60（:98-99）。
  - 把 `retrieval_gate` 从 observe 灰度到 enforce（:45）：低相关/复杂问先 HyDE/step_back 重试一轮（:162/:178），仍不达标走 `build_abstain_message`（:197）弃答；门控日志落 retrieval_gate_logs 供 /api/gate/stats。

- **选型 / 算力 / 隐私（上线口径）**：
  - 本地：Ollama + Qwen2.5/GLM 等 7B 量化（约需 6–8GB 显存，14B 需 ~12–16GB，以 model_registry.QUANT_GB_PER_B 与 detect_hardware 实测为准）；embedding bge-small-zh CPU 可跑；reranker bge-reranker-v2-m3 CPU；OCR/电路 VLM 视模型需 GPU。无 GPU 时用小模型+云端兜底。
  - 云端：豆包/DeepSeek/Qwen/GLM/OpenAI 等，按 token 计费、延迟低，适合无 GPU 或高峰；敏感学习数据上云需在隐私政策告知并允许用户“仅本地”。
  - 并发：本地推理用单/有限并发队列（避免显存 OOM），云端按配额限流；长请求异步化（讲题可 SSE/WebSocket 流式）。
- 开源/许可证：Ollama（MIT，本地推理）；BGE 系向量/重排（BAAI bge-small-zh、bge-reranker-v2-m3，MIT/Apache 类，**以模型 LICENSE 与商用条款为准**）；pgvector（PostgreSQL License）；前端可流式渲染（无特殊许可）。模型权重（Qwen/GLM 等）须分别遵循其模型许可证（部分有商用条件/月活限制），上线前逐一核对。微调训练框架（Transformers/PERL 类）遵循各自 Apache/MIT。

## f) 冷启动（让 AI“有米下锅”）
1. **先建知识库向量**：对现有 5 篇/17 分块跑 `vector_builder.build_pg_vectors`（或 embedding_service.build_all_embeddings），把 chunk_vectors 从 0 建起来；验证维度 512、HNSW 可检索。
2. **起旁路**：本地启动 backend-reranker:8140、backend-ocr-paddle:8888（各自有 启动.bat/README）；在 /data-center 确认三服务健康。
3. **配模型**：/admin/model 配置至少一个可用 provider（本地 Ollama 拉一个 7B，或一个云端 key），用 `/api/ai/providers/{id}/test` 验证；auto 路由即可工作。
4. **门控灰度**：先 observe 跑一段看 retrieval_gate_logs（相关度分布/弃答率），调阈值后再 enforce。
5. **评测门禁**：准备学科小评测集（sft_examples/eval_lora_v4），任何换模型/微调后跑 eval，关键指标（答对率/引用命中率/弃答率/延迟）达标才切流。
6. 成本与隐私默认：单机自用默认本地优先（local_first）；公网多租户默认云端+配额，并提供“仅本地”开关。
