# 【优化方案】七大平台功能拆解与私域落地 V1.0

> 生成日期：2026-10-23
> 用途：参考考研帮 / 粉笔考研 / 研途考研 / 高途考研 / 墨墨背单词 / 扇贝单词 / 调剂与笔记工具的能力拆解，形成**按平台拆解**的优化方案。
> 重点：① 每个功能的具体实现逻辑；② 在 5—6 人私域场景下，哪里可以做得**更轻、更准、更闭环**。
> 落地对象：D:\平台 现有工程（FastAPI + PostgreSQL + React + 本地 Ollama，已有院校 816 所、分数线 88,315 行、知识点 1,860、题目 386、文档 705 篇）。

---

## 〇、总纲

### 0.1 三条数据主线（所有功能最终汇入）

| 主线 | 载体 | 说明 |
|---|---|---|
| 行为数据主线 | StudySession / Task / FlashcardReview / QuizRecord | 专注分钟、刷题量、单词复习、挖空检测结果 |
| 薄弱点主线 | 卡点池（新增 StuckPoint）+ KnowledgePoint | 所有"仍未理解"的知识点汇聚、聚合、排序 |
| 决策证据主线 | 择校卡片 / 周计划草案 / 信号卡 / 复习卡片 | 每个推荐都带"为什么"（explain 字段） |

### 0.2 三个连接点（大平台做不了、私域必须做的部分）

1. **打卡不是计数器，是三条数据流的汇合点**——由「完成单词队列 / 刷完计划题量 / 番茄钟达标」自动触发，热力图按实际专注分钟点亮。
2. **AI 的产出必须回流到数据主线**——任何一次 AI 交互如果没有产生一条数据变更（卡点、批改记录、小测结果、信号卡），就不算完成。
3. **决策不是给结果，是给可争论的证据框架**——系统不替人做决定，只保证依据显性化、可被 5—6 人争论。

### 0.3 私域裁剪总原则

- **更轻**：砍掉积分商城（研豆）、C2C 问答市场、万人模考、全国调剂数据库、GraphRAG、自研视频打点。5—6 人不需要激励体系，只需要聚合与排序。
- **更准**：所有推荐逻辑从"黑盒"改为"显性规则"（if-then + 证据 + 置信度），规则本身可以被小团队质疑和修改。
- **更闭环**：每个功能的输出必须成为下一个功能的输入，用状态流转（数据表字段）保证闭环可追踪。

## 一、考研帮 → 择校风险卡片 + 共享卡点池

### 1.1 风险标签式择校卡片（把"查数据"变成"做判断"）

**借鉴点**：考研帮的院校-专业多维数据表是展示型的；我们升级为**审计型**——每张目标院校卡片直接跑风险规则，5—6 人对着同一组证据争论"它今年会不会爆"。

#### 具体实现逻辑

**数据模型（复用 + 新增）**

- 复用 `University`（已有 816 所）、`ScoreLine`（已有 88,315 行）。
- 新增 `SchoolRiskSignal` 表：
  - `id, university_id, major, year, rule_name, evidence_json, confidence, status(active/acknowledged), created_at`
  - `evidence_json` 存触发该规则的具体数据（如：近三年复试线 [310, 325, 305]）。
- 新增 `SchoolVote` 表（争论载体）：
  - `id, university_id, major, user_id, direction(看涨/看跌/中立), reason, created_at`，唯一约束 `(university_id, major, user_id)`。

**规则引擎（`services/risk_engine.py`，纯函数，可单测）**

每条规则一个函数：输入 `University + ScoreLine[]`，输出 `RiskSignal` 或 None：

| 规则名 | 触发条件（示例阈值，可配置） | 信号文案模板 |
|---|---|---|
| 洼地效应 | 去年复试线 ≤ 近三年均值 − 15 分，且报录比同比下降 | "去年分数线处于洼地，今年可能反弹爆热" |
| 推免挤压 | 推免/招生 ≥ 50%，且该比例连续两年上升 | "推免占比过高且逐年上升，统考名额实际缩水" |
| 复试线虚低 | (录取均分 − 复试线) ≥ 25 分 | "复试线是陷阱，实际录取分远高于线" |
| 大小年 | 分数线同比降幅 ≥ 10% | "去年大降，存在大小年反弹风险" |
| 数据缺失 | 关键字段缺失 ≥ 2 个 | "证据不足，本信号置信度低" |

- `confidence = 完整字段数 / 必填字段数`，缺失时明确降级，不做虚假精确。
- 规则只在**用户收藏的目标院校**（≤ 10 所）上运行，用 APScheduler 每日重算一次。

**API 与前端**

- `GET /api/universities/{id}/risk-profile`：返回基础数据 + 风险信号列表（每条含证据）+ 投票汇总。
- `POST /api/universities/{id}/vote`：投票并写一句理由（强制填写，否则不提交）。
- 前端：院校详情页改为"卡片式"——顶部数据区，中部风险信号列表（可展开证据），底部投票区（5—6 人头像 + 理由流）。

**闭环**：投票共识（看涨/看跌比例 + 理由）→ 写入 `Goal` 目标院校 → 生成专业课复习权重建议（看涨院校专业课权重 +10%）→ 周计划引用。

#### 更轻 / 更准 / 更闭环

- **更轻**：不做全国院校抓取、不做匹配度百分比算法、不做推荐。数据由 5—6 人人工认领补充（每人负责 1—2 所），总量小但证据密度高。
- **更准**：大平台给"匹配度 87%"，我们给"命中 2 条风险规则 + 证据 + 置信度"。判断依据全部显性化。
- **更闭环**：投票 → 目标确认 → 复习权重 → 周计划，择校决策直接驱动后续学习任务。

### 1.2 共享卡点池（替代研豆问答）

**借鉴点**：考研帮的研豆问答是积分驱动的 C2C 问答市场；私域 5—6 人不需要积分和市场，只需要**聚合 + 排序**：任何被标记"仍未理解"的知识点进池子，多人标记的自动成为下周共同复习议题。

#### 具体实现逻辑

**数据模型（新增）**

- `StuckPoint` 表：
  - `id, knowledge_point_id, user_id, source_type(quiz/ai/book/manual), source_id, description, status(open/topic/resolved/stubborn/archived), created_at, resolved_at`
- `StuckPointMark` 表（多人标记）：
  - `id, stuck_point_id, user_id, created_at`，唯一约束 `(stuck_point_id, user_id)`。
- `WeeklyTopic` / `WeeklyTopicItem` 表（周会议题）：
  - `WeeklyTopic: id, week_start, status(planned/ongoing/done)`
  - `WeeklyTopicItem: id, topic_id, stuck_point_id, assignee_id, verify_question_ids(json), status(pending/explained/verified/failed)`

**三条录入入口（都必须是 1 步操作）**

1. 刷题页：答错或"蒙对"时出现「仍未理解」按钮 → 自动关联 `QuizQuestion.knowledge_point_id` 创建卡点。
2. AI 解析页：回答末尾强制出现「仍未理解」按钮 → 创建卡点并自动附带 AI 回答链接。
3. 知识库阅读页：选中文本 → "标记为卡点"（source_type=book，description=选中文本）。

**聚合排序规则（每日 APScheduler 任务）**

```
权重 = 去重标记人数 × 3 + 最近48小时内新增标记数 × 2 + 距考试天数系数
```

- 规则：`distinct_user_count >= 2` 且状态为 open → 自动置为 `status=topic`，进入"待上会"清单。
- 单个用户标记超过 3 天未解决 → 进入"个人待复习"清单（不强制上会）。

**周会闭环（每周日晚 30 分钟固定流程）**

1. 系统生成本周议题清单（按权重排序，最多 5 个）。
2. 5—6 人轮流认领讲解（`assignee_id`），讲解前必须看卡点里的"不理解描述"。
3. 讲解后当场做 3 道验证题：优先从 `QuizQuestion` 按 `knowledge_point_id` 筛选；不足时由 LLM 生成并人工确认。
4. 全员通过 → `status=resolved`；仍有 ≥1 人错 → `status=stubborn`，下周自动重新上会。
5. 已解决卡点 30 天后自动生成 1 道抽查题，进入复习队列（防遗忘）。

**前端**：新增"卡点池"页面，两个视图——「池子」（按权重排序的卡点列表 + 标记按钮）和「周会议题」（本周清单 + 验证结果）。

#### 更轻 / 更准 / 更闭环

- **更轻**：砍掉研豆、积分、悬赏、学长学姐市场。5—6 人之间不需要经济激励，只需要把"谁没懂、哪些人共同没懂"聚合出来。
- **更准**：排序只看"多人标记 + 近期活跃 + 临近考试"，不靠积分权重，信号天然就是共同薄弱点。
- **更闭环**：卡点产生（刷题/AI/阅读）→ 聚合（多人标记）→ 上会（周会议题）→ 讲解验证（3 题）→ 30 天抽查，状态机全程可追踪。

## 二、粉笔考研 → 约束型 AI 批改 + 挖空背诵 + 显性信号看板

### 2.1 约束型 AI 批改（政治分析题 / 英语作文 / 专业课大题）

**借鉴点**：粉笔的"智能批改"在主观题上大概率是规则匹配；我们用**评分维度锁死的结构化批改**，让 AI 逐项给分并引用原文。

#### 具体实现逻辑

**评分模板（`services/grading_service.py`，可配置）**

每个科目一套维度模板，写入 prompt 的 JSON schema：

| 场景 | 维度（示例） |
|---|---|
| 政治分析题 | 原理正确性 40% / 材料结合度 30% / 条理结构 20% / 术语规范 10% |
| 英语作文 | 内容切题 40% / 结构逻辑 30% / 语言准确 30% |
| 专业课大题（数电/模电） | 思路正确性 40% / 步骤完整性 30% / 结果正确 20% / 表述规范 10% |

**AI 输出约束（硬性）**

- 输出必须是结构化 JSON：`[{dimension, score, max_score, deduction_reason, quoted_text, related_syllabus}]`。
- `quoted_text` 必须原文摘录（按句号切分后匹配），不允许概括性引用；Pydantic 校验不合格则重试一次。
- 语言维度错误必须分类计数：语法错误 / 搭配错误 / 中式英语。

**数据模型（新增 `GradingRecord`）**

- `id, user_id, subject, source_type(exam/homework), source_id, dimensions_json, total_score, ai_output_json, reviewer_id, reviewed_at, status(pending/reviewed)`

**人工复议（5—6 人轮值）**

- AI 批改完成后进入 `pending`，轮值人只需检查 `quoted_text` 是否准确、分数是否离谱，不重新打分。
- 复核通过 → `reviewed`，分数才生效（避免 AI 幻觉直接污染数据）。

**闭环**：批改结果按维度写入个人档案 → 触发信号规则（如"作文语言维度连续两次 < 60%"）→ 信号卡 → 下周计划自动加入 2 篇语言专项修改。

#### 更轻 / 更准 / 更闭环

- **更轻**：不追求语义级自由批改，只做维度锁死的结构化打分，Prompt + JSON Schema 校验即可，不需要微调模型。
- **更准**：每个分数都有 `quoted_text` 和扣分原因，AI 无法给"感觉分"。
- **更闭环**：批改分数直接进入信号引擎和下周计划，而不是一次性的评分消费。

### 2.2 边背边测的挖空检测（把"检测"嵌入背诵过程）

**借鉴点**：粉笔的"挖空背诵"是把检测嵌进背诵流程——不是"背完 50 个再测"，而是**在复习队列里直接插入挖空卡**。

#### 具体实现逻辑

**数据模型（改造现有 Flashcard）**

- `Flashcard` 增加 `card_type(recall/cloze)`。
- 挖空卡字段：`sentence`（含 `____`）、`blank_answer`、`hint`（中文提示）、`source_tag`（如"2018 英语一 Text 2" / "数电教材 §3.2"）。

**三种挖空卡（按科目）**

1. 单词例句挖空：`The _____ of the experiment confirmed the hypothesis.`（答案 + 释义 + 来源真题编号）
2. 政治关键词挖空：`遵义会议确立了 _____ 在全党的领导地位`（答案 + 出处页码）
3. 专业课名词/公式挖空：`D 触发器特征方程 Q* = _____`（答案 + 出处章节）

**复习队列混合规则**

- 每 5 张普通复习卡后插入 1 张挖空卡（比例可配置）。
- 交互：显示句子 → 用户先想答案（自检，不强制输入）→ 点"显示答案" → 四档评分（忘记/模糊/记得/简单）→ 评分写入 SM-2。
- "模糊/忘记"的挖空卡 10 分钟后重新出现在队列顶部一次。

**挖空卡生成**

- 首次用 LLM 批量生成（基于真题例句、讲义原文、教材定义），**人工校对一次后永久复用**，不每次调用 AI。
- 生成时要求 LLM 返回 `(sentence, answer, hint, source_tag, knowledge_point_id)` 结构化 JSON。

**闭环**：挖空自评结果 = 记忆状态数据 → 直接写 SM-2 调度 → "模糊"自动进入今晚复习队列 → 看板显示"本周模糊率最高的 10 个知识点"。

#### 更轻 / 更准 / 更闭环

- **更轻**：不做语音识别、不做手写输入。5—6 人没有作弊动机，文本自检足够。
- **更准**：检测粒度从"背完一组测一次"细化为"每条知识点边背边测"，模糊信号立即回流调度。
- **更闭环**：挖空卡的数据同时服务复习调度和卡点池（连续 2 次"模糊"自动生成卡点）。

### 2.3 显性规则信号看板（替代黑盒推荐）

**借鉴点**：粉笔的专项练习标签很细，但题目之间的推荐逻辑是隐性的；我们做**可解释、可争论的规则信号**——小团队需要的是看得见、能质疑的信号，而不是黑盒推荐。

#### 具体实现逻辑

**数据模型（新增 `Signal` 表）**

- `id, rule_name, user_id, evidence_json, suggestion, priority(P0/P1/P2), status(pending/claimed/ignored/done), claimed_by, created_at, closed_at`

**事件源与规则（写死在 `services/signal_engine.py`，每 30 分钟跑一次）**

| 规则名 | 触发事件 | 信号文案示例 |
|---|---|---|
| 连续错题 | 某人在同一知识点连续错 3 题 | "XX 在『数电-时序逻辑』连续错 3 题，正确率 42%，建议下周专项优先级 P1" |
| 正确率下滑 | 某科正确率连续 2 次周环比下降 | "XX 英语阅读正确率连续 2 次下降，建议复盘最近 10 道错题的生词" |
| 计划过载 | 周完成率 < 60% 且专注时长达标 | "任务量可能过载，建议下周减量 20%" |
| 挖空预警 | 某知识点挖空模糊率 > 50% | "『模电-反馈组态』挖空模糊率 60%，建议转为周会议题" |

**信号卡操作（前端看板）**

- 认领：某人负责下周带练（`claimed_by` 记录，自动生成专项任务）。
- 忽略：必须写原因（防静默放弃）。
- 转议题：一键把信号转成 `StuckPoint` 进卡点池。

**闭环**：信号触发 → 认领 → 生成专项练习任务 → 一周后自动复查该知识点正确率 → 达标则 `done`，未达标则升级 `P0` 重新触发。

#### 更轻 / 更准 / 更闭环

- **更轻**：不做协同过滤、不做用户画像模型，规则就是几条写死的 if-then，用现有事件表就能算。
- **更准**：规则可解释，5—6 人可以直接争论"这条规则阈值合不合理"，而不是猜算法。
- **更闭环**：信号卡有明确的"认领 → 执行 → 复查"生命周期，避免推荐完就消失。

## 三、研途考研 → 规则化周计划引擎 + 小样本相对排名

### 3.1 规则生成 + 人工微调的周计划引擎（把"人工定制"变成"规则生成 + 人工微调"）

**借鉴点**：研途卖的是顾问时间；我们把 1V1 定制计划流程规则化，成本从顾问时间变成一次性规则设计。5—6 人每周花 10 分钟互相 review。

#### 具体实现逻辑

**输入（每周日自动汇总）**

- 每人上周任务完成率（按任务类型聚合）
- 各科刷题量与正确率（QuizRecord）
- 挖空自评模糊率（按科目）
- 卡点池未解决数
- 距考试天数

**计划生成规则（`services/plan_engine.py`）**

```
周总时长 = 基础时长(如 35h) + 上周任务缺口(h) × 0.5，随距考试天数线性递减调整
科目时间分配 = Σ(各科薄弱权重) → 薄弱权重 = 1 + (1 - 该科正确率) × 2
任务生成来源：
  - 单词：Flashcard 到期量（取前 N 个）
  - 错题复习：ErrorRecord 中到期未复习的题
  - 专项练习：本周 pending 的信号卡对应知识点
  - 专业课：Plan 模板中该阶段章节任务（按完成率偏差调整）
  - 作文/主观题：每周固定 1 篇
每个任务必须带 explain 字段（生成依据），如 "源于信号卡 S-102：辩证法正确率 42%"
```

**周日晚 review 会议（10 分钟，前端"周计划 review"页）**

1. 每人看自己的草案 + 他人标注意见。
2. 重点检查两处：任务量是否合理（结合上周完成率）、薄弱科目时间是否够。
3. 直接改，改完确认；系统记录每次手动调整（新增 `TaskAdjustment` 表：`task_id, user_id, action(删除/减量/加量), reason`）。
4. **规则自优化**：某类任务连续 3 周被删 → 引擎自动降低该类任务默认权重（写日志，可在设置页查看）。

**闭环**：周计划 → 每日执行（打卡自动统计）→ 下周草案带上完成率偏差 → 手动调整记录反向优化规则权重。计划越用越准。

#### 更轻 / 更准 / 更闭环

- **更轻**：不要顾问、不要 AI 规划对话，规则一次性写死；10 分钟人工微调远便宜于任何"智能规划"。
- **更准**：每个任务都带"生成依据"，被删的任务会反哺规则，计划随使用越来越贴合。
- **更闭环**：计划引擎是打卡、信号卡、卡点池、复习队列的共同出口，也是唯一入口。

---

### 3.2 小样本模考相对排名（把"万人排名"换成"5—6 人相对位置"）

**借鉴点**：万人模考对私域没有意义，但模考后的**排名分析逻辑**可以保留——5—6 人本身就是一个有效小样本，相对位置比全国排名更有诊断价值。

#### 具体实现逻辑

**数据**：复用现有模考记录（或新增 `ExamResult`：`id, user_id, exam_id, subject_scores_json, total_score, created_at`）。

**模考报告页（前端改造）**

- 每科得分率雷达图，每人叠加"上周雷达"虚线 → 升降一眼可见。
- 小样本横向对比：每科显示"第 N/6 名"和"与最高分差 X 分"。
- 专业课进度对比：显示每人当前章节进度，落后于最强者 ≥ 2 章 → 触发信号卡。

**诊断规则（写入 signal_engine）**

- `某科排名连续两次下降` → 信号卡"建议下周该科加时 2h"。
- `专业课进度落后最强者 ≥ 2 章` → 信号卡"建议下周专业课加时并优先补章节 X"。

#### 更轻 / 更准 / 更闭环

- **更轻**：不需要全国成绩分布，雷达图 + 排名几行代码。
- **更准**：全国排名无法行动，小样本排名直接指向"谁、哪科、差多少"。
- **更闭环**：排名诊断直接触发信号卡 → 下周计划调整 → 下次模考验证。

## 四、高途考研 → 三场景约束 AI 答疑 + 手工课程索引表

### 4.1 三场景约束型 AI 答疑（不做自由对话）

**借鉴点**：高途的 GraphRAG 技术栈太重，但它的**场景约束思路**值得直接借用——AI 的输入输出都锁在场景里，对私域比"什么都能问"的对话框有用得多。

#### 具体实现逻辑

**三个固定场景（`services/ai_scene.py`，每个场景 = 预设 prompt + 输出 schema）**

| 场景 | 输入约束 | 输出结构 | 禁止 |
|---|---|---|---|
| `question` 题目级解析 | 题干、选项、正确答案、所属知识点（从题库直接带入） | 正确项解析 / 每个错误项逐一排除原因 / 关联知识点 / 类似题推荐 | 输出与本题无关内容 |
| `grading` 主观题批改 | 评分维度表（见 2.1） | 分维度得分 + 引用 + 扣分原因 | 自由点评 |
| `knowledge` 知识点追问 | 当前知识点名称 + 卡点描述 | 只在该知识点范围内回答；越界返回"这属于 XX 知识点，建议先解决当前卡点" | 跨知识点自由发挥 |

- **追问深度限制**：`knowledge` 场景最多追问 3 轮，之后提示"建议去周会讲"（防止无限对话消耗资源）。
- **强制回流**：每个场景回答末尾必须有「仍未理解」按钮 → 点击创建 `StuckPoint`（自动附带 AI 回答链接）。

**前端**：不做一个全局对话框，而是三个场景入口——刷题页内嵌解析、批改页、卡点详情页。

**闭环**：AI 回答 → "仍未理解" → 卡点池 → 周会议题。AI 的产出必须回流到数据主线，而不是一次性消费。

#### 更轻 / 更准 / 更闭环

- **更轻**：不要图数据库、不要实体关系抽取、不要自由对话记忆。三套 prompt 模板 + JSON 校验，现有 ai_router 即可承载。
- **更准**：输入输出全部锁死，AI 无法跑题，幻觉空间被压缩到最小。
- **更闭环**：每个场景的终点都是"数据变更"（卡点/批改/信号），这是高途都没做透的部分。

### 4.2 手工"课程—知识点"索引表（替代视频 AI 打点切片）

**借鉴点**：高途用 AI 给视频做知识点打点；私域 5—6 人课程量有限，**手工维护索引表的成本远低于自研算法**。

#### 具体实现逻辑

**数据模型（新增 `CourseIndex` 表）**

- `id, course_name, source(b站/网盘/本地), url, start_time, end_time, knowledge_point_id, note, creator_id, created_at`

**录入规则**

- 看课时随手记：每节课 ≤ 30 秒录入（课程名 + 链接 + 时间点 + 知识点标签）。
- 总量预估：5—6 人共享的课程可能就几套，索引总量 ≤ 几百条，完全可维护。

**联动使用**

- 卡点池详情页：按 `knowledge_point_id` 检索关联视频片段，直接跳转对应时间点。
- 看完片段回来 → 标记"已解决"或"仍未理解"（闭环回到卡点池）。

**闭环**：索引片段被点击次数统计 → 高频片段对应的知识点标记为薄弱候选 → 进信号引擎复核。

#### 更轻 / 更准 / 更闭环

- **更轻**：不碰视频解析、不碰 AI 打点，一个共享表格就能承载。
- **更准**：索引直接挂在知识点 ID 上，和卡点池、信号引擎天然打通。
- **更闭环**：从"做题卡住 → 找视频片段 → 回来确认"形成完整链路。

## 五、墨墨背单词 → 可解释 SM-2 复习队列 + 真题生词溯源

### 5.1 可解释复习队列（把 SM-2 中间字段暴露出来）

**借鉴点**：不需要复现墨墨的 MM 算法精度，但可以借用它的**可解释性**——每张卡片显示"为什么今天复习它"，而不是只弹出一个词。

#### 具体实现逻辑

**SM-2 字段全暴露（现有 Flashcard / review_scheduler 已有基础）**

每张复习卡显示：

```
上次评分：3（模糊）
当前间隔：3 天
到期日：今天
EF 值：2.3
距离遗忘临界点：0 天（已超过 1 天）→ 这就是今天必须复习的原因
```

- "距离遗忘临界点天数" 用自定义近似规则：`临界点 = 当前间隔 × 0.3`，超过则提示"已超过临界点"。

**每日队列规则（写死）**

- 到期词 = 今天必须复习的词（按 due_date 排序）。
- 新词上限 = 用户设定；若到期词 > 200，自动把新词上限减半（规则可配置）。

**前端**：单词复习页卡片底部显示复习原因文本，让用户看到调度依据。

**闭环**：复习评分 → SM-2 间隔更新 → 看板显示"下周到期量"预警（到期量突然放大时，提前提示降低新词）。

#### 更轻 / 更准 / 更闭环

- **更轻**：SM-2 是公开算法，几十行代码，不训练模型。
- **更准**：暴露中间字段后，用户能验证调度合理性，误判"怎么又复习这个"的抱怨会消失。
- **更闭环**：复习数据直接驱动"新词上限自适应"和"下周到期量预警"。

---

### 5.2 真题生词自动入库 + 来源标签（单词从真题里长出来）

**借鉴点**：墨墨最大的短板是词库和真题脱节；我们做**源头追溯**——刷题时标记的生词自动进词库，带上来源标签。

#### 具体实现逻辑

**数据模型（改造现有 Word / Flashcard）**

- 增加字段：`source_quiz_id, source_tag("2018 英语一 Text 2" / "834 真题 2023 第 4 题"), source_sentence(原文句子)`。

**生词入库流程**

1. 刷题页遇到生词 → 点选单词 → 弹出"加入复习队列"（自动带上原文句子和来源标签）。
2. 复习时默认先显示**原文句子**（语境回忆优先），再显示单词和释义。
3. 记住后打"已消化"标签 → 看板统计"这次阅读错题里标记的生词，已消化 X / Y，占比 Z%"。

**看板联动查询（按来源标签聚合）**

- `GET /api/words/source-stats?source_tag=...`：返回该来源生词的入库数、到期数、已消化数。
- 结果驱动阅读专项：错题生词未消化的文章优先重做。

**闭环**：生词（真题）→ 复习队列（带语境）→ 已消化 → 回流到阅读正确率统计。

#### 更轻 / 更准 / 更闭环

- **更轻**：不需要 15 万词库，词从 5—6 人实际刷的题里长出来，每人几百个就够用。
- **更准**：每个词都有真实来源句，记忆的是"题里那个意思"，不是孤立释义。
- **更闭环**：单词模块第一次和刷题、错题、阅读正确率形成数据回路。

## 六、扇贝单词 → 词汇量前置测试 + LLM 即时小测

### 6.1 10 分钟词汇量前置测试（筛掉已掌握的，只背不认识的）

**借鉴点**：扇贝的"筛除已掌握词"专利逻辑，让 5—6 人不需要从大纲第一个词开始背，启动成本大幅降低。

#### 具体实现逻辑

**分层抽样测试（`services/vocab_test.py`）**

1. 词频分层：高频 1—1000 / 中频 1000—3000 / 低频 3000—6000（现有 Word 表需增加 `freq_level` 字段，可先用公开词频表导入）。
2. 每层随机抽 10 词，4 选 1 中文释义，共 30 题，限时 10 分钟。
3. 估算词汇量 = Σ(各层正确率 × 层词数)。
4. 分档输出：已掌握（高频全对）/ 模糊（中层有错）/ 不认识（低频错）。

**入队规则**

- 已掌握词 → 直接标记（不进入复习队列）。
- 模糊 + 不认识 → 进入 SM-2 复习队列（约等于从零开始量的 1/3）。
- 初始复习计划从"模糊"词开始，间隔按 SM-2 设定。

**闭环**：测试结果 → 初始复习队列 → 首周计划自动生成（复习量 = 模糊词数 / 7 天）。

#### 更轻 / 更准 / 更闭环

- **更轻**：30 题 + 规则估算，不需要机器学习。
- **更准**：5—6 人词汇基础差异大，前置测试让每个人从自己的真实起点开始。
- **更闭环**：测试结果直接决定初始队列和首周计划。

---

### 6.2 LLM 即时小测（背和考在同一个动作里完成）

**借鉴点**：扇贝"从会背到会考"——基于已学词汇自动生成高频考试题型；我们让复习和检测合并。

#### 具体实现逻辑

**触发与生成**

- 每复习完一组（10 词）后，自动请求 LLM 生成 3—5 题：
  - 题型：选词填空（4 个备选只含本组词）+ 首字母填空（给首字母 + 中文提示）。
  - 生成约束：题目语境必须使用该词在真题中的常见搭配（`source_sentence` 提供上下文）。
  - 输出 JSON：`[{type, sentence, blank_answer, options[]}]`，Pydantic 校验。

**结果回流**

- 小测正确率 → 该组词掌握度评分 → 写入 SM-2。
- 全对 → 该组词延长间隔；错题词 → 立即回到队列顶部，10 分钟后重测。

**闭环**：复习 → 即时小测 → 掌握度更新 → SM-2 间隔调整 → 错词重测。

#### 更轻 / 更准 / 更闭环

- **更轻**：不维护题库，LLM 生成 + 5—6 人轮值校对一次即可复用。
- **更准**：题目只基于本组词和真实来源句，不会超纲。
- **更闭环**：小测结果直接修改记忆调度，而不是"测完就完"。

## 七、周边域 → 调剂关注列表 + Obsidian 笔记打通

### 7.1 调剂关注列表（不做全国数据库，做看板 + 筛选 + 提醒）

**实现逻辑**

- 数据模型（新增 `AdjustSchool` 表）：`id, university_id, major, previous_min_score, quota_status, source_url, user_id, apply_deadline, status(关注中/已申请/已放弃/已录取)`。
- 录入：手动 + 半自动（粘贴网页文本 → 正则提取院校/专业/分数，预览确认后入库）。
- 筛选规则：`我的分数 ≥ 往年调剂最低分 + 5` 显示"建议申请"；支持按专业、地区过滤。
- 提醒：`apply_deadline` 前 3 天 / 1 天各提醒一次（复用现有提醒机制）。
- 闭环：录入 → 筛选 → 状态流转 → 每周复盘"哪些判断错了"，复盘结果写入卡点池（决策类卡点）。

### 7.2 笔记模板化 + Obsidian 双向链接（平台管任务题库，Obsidian 管深度笔记）

**实现逻辑**

- 平台内约定笔记模板：`题干 / 我的错误答案 / 正确答案 / 解析 / 知识点标签 / 来源链接(真题/视频片段/课程)`。
- 题目详情页增加"导出 Markdown"按钮 → 一键生成模板化笔记 → 放入共享 Obsidian 仓库。
- Obsidian 内用标签 + 双向链接做知识点聚合；反向汇总：定期把 Obsidian 笔记的标签统计导入平台，与卡点池交叉校验——"这个知识点你有 3 篇笔记还标了卡点，建议复习"。
- 闭环：题目 → 笔记模板 → Obsidian 聚合 → 标签统计回灌 → 卡点校验。

## 八、三个共性连接点的落地设计

### 8.1 打卡 = 数据流汇合点

- **规则**：打卡不再单独存在，由以下任一事件自动触发：
  1. 完成当日单词复习队列（到期词 100% 复习）
  2. 完成当日计划刷题量（QuizRecord 计数达标）
  3. 番茄钟专注达标（StudySession 累计 ≥ 设定分钟）
- **热力图亮度 = 实际专注分钟数**（不是"打开 App"）。悬停显示构成："单词 20min + 刷题 45min + 番茄 60min"。
- 前端：仪表盘周视图改为 GitHub 风格热力图，5—6 人同屏可见，格子亮度就是最诚实的进度信号。

### 8.2 AI 产出必须回流数据主线

- 在 `ai_router` 增加统一后处理钩子（after_response）：
  - 解析场景 → "仍未理解" → `StuckPoint`
  - 批改场景 → 低分维度 → `Signal`
  - 小测场景 → 正确率 → SM-2
  - 追问超 3 轮 → 引导去周会
- **验收标准**：任何一次 AI 交互如果没有产生一条数据变更，视为未完成。

### 8.3 决策证据显性化

- 所有推荐/计划/信号统一带 `explain` 字段：
  - 择校卡片：每条风险信号带证据 + 置信度
  - 周计划：每个任务带生成依据
  - 复习卡片：显示复习原因（5.1）
  - 信号卡：规则名 + 证据 + 可质疑
- 前端统一渲染"为什么"组件（可折叠），5—6 人可以直接在证据上争论。

### 落地约束提醒（遵循项目硬性规范）

1. 所有新表走版本化迁移脚本，禁止手改已有表结构；`Flashcard`、`Word` 加字段必须新建迁移。
2. 共享数据（卡点池、择校投票、信号卡）按现有权限模型：读接口默认登录，写接口按 `user_id` 隔离，共享写接口收管理员权限（沿用 `scoped()` 与 `GUEST_READ_PREFIXES` 约定）。
3. 规则引擎全部为纯函数，配套 pytest 单测（阈值边界用例必须覆盖）。
4. AI 场景输出统一走 Pydantic 校验，失败重试一次，再失败降级为本地小模型输出并标记"低置信度"。
