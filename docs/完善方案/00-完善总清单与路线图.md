## 一、总体结论

这个项目**不是"半成品"，而是一个功能完成度相当高、但工程治理欠账明显的系统**。先说已经做得好的（不要动）：

| 已达标项 | 证据 |
|---|---|
| 路由按 6 域收敛，注册中心单一挂载点 | `routers/registry.py` + `main.py` 唯一 `iter_routers()` 循环 |
| 测试库硬隔离（铁律 + 硬断言） | `tests/conftest.py`：PG_DATABASE 改写 kaoyan_test，import 前断言生产库名即退出 |
| 认证体系完整 | PBKDF2 24 万轮 + JWT 双 httpOnly cookie + 首登强改密 + 登录失败锁定 + app 级默认拒绝 |
| 行级数据隔离有统一机制 | `utils/scope.py`（scoped/owner_id + USER_ISOLATION 回退开关）+ core/sql/108 |
| 凭据落库加密 | `utils/secret_codec.py` AES-256-GCM |
| 知识库体检-自愈闭环 | `services/kb_pipeline.py` 体检 + --heal |
| 部署有预检/备份/健康验证 | `deploy/push_update.py` |
| 每日备份加密 + 本地滚动 7 份 | `deploy/backup.sh` |
| 前端构建直出后端 static，消除双产物漂移 | `frontend/vite.config.js` outDir |
| 决策留痕习惯 | docs/decisions/ADR-001~003 |

**真正的短板集中在 5 个面**：① 敏感信息与仓库内容治理（最急）；② 公网安全与依赖漏洞；③ 质量门禁（CI 假绿 + 测试基线带伤）；④ 数据库迁移与运维回滚链路的"最后一公里"；⑤ 文档/数据口径漂移。

## 四、执行铁律（沿用项目既有约定，所有文档通用）

1. **任何数据写操作前先备份**：走 `services.backup_service` / `pg_dump`，备份文件落 `database/backups/`（该目录已 gitignore）。
2. **测试绝不碰生产库**：conftest.py 的 kaoyan_test 隔离是红线；新增脚本一律从环境变量取连接串，禁止再写死口令。
3. **每个变更可回滚**：数据变更留备份表 + 回滚 SQL；代码变更走分支 + PR；部署留 pre-<ts>.tar.gz。
4. **改完必回归**：后端 `python -m pytest tests -q`（真 PG），前端 `npm test` + `npm run build`；P0/P1 修复后全量跑一轮。
5. **文档与代码同 PR 更新**：修复报告写进 docs/，README 口径用 `scripts/diagnostics/readme_counts.py` 刷新，禁止手填数字。
