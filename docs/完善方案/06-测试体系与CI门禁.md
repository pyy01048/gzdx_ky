# 06 · 测试体系与 CI 门禁

> 覆盖问题：R05（CI 假绿）、R06（27 failed + 15 errors 基线）、R18（CI 缺 build/lint/coverage/e2e）
> 优先级：R05 = P0，R06/R18 = P1 ｜ 预计工作量：CI 修复 S；基线清零 M；e2e 扩展 M

---

## 1. 现状与证据

### 1.1 CI 门禁失效点（.github/workflows/ci.yml）

```yaml
# 后端 job 第 50 行：
pip install -r requirements.txt 2>/dev/null || true
```
**依赖装失败被静默吞掉**：后面 pytest 若因缺依赖收集失败会红，但若恰好"缺的依赖只影响部分用例"，就出现**假绿**——CI 过了，生产缺功能。requirements 注释里自己写过：缺 six/PyYAML/urllib3 会让 OCR 引擎初始化失败被吞成"0 字"、向量加载失败静默跳过——这类静默降级正是 `|| true` 会放过的。

```yaml
# 前端 job 第 74 行：
run: python ../backend-main-fastapi/scripts/design_guard.py
```
前端 job **没有 setup-python**，依赖 runner 镜像自带的 python 别名——镜像更新即可能断；且 design_guard 若需要后端依赖则根本没装。

其它缺口：
- 无 `npm run build` job → 构建破坏（如 vite 配置/依赖升级）到部署才暴露
- 无 lint（04/07 文档补齐后接入）、无覆盖率、无 pip-audit/gitleaks
- e2e（4 个 Playwright smoke）不在 CI，本地也少跑
- 后端 job 无超时上限控制（pytest --timeout=300 有，但 job 级 timeout-minutes 缺）

### 1.2 测试基线带伤（docs/QA回归测试报告-20261028.md）

1525 用例：**1468 passed / 27 failed / 15 errors / 14 skipped / 1 xfailed**。失败全部是存量，五类：

| 类 | 根因 | 消解方式 |
|---|---|---|
| 旧扁平路由导入 | V3.1 重构后测试仍 `from routers import documents/kb/formula…` | 批量改为 `from routers.<domain> import <module>` |
| test_quiz_gate_ast 白名单失效 | AST 网关白名单按旧导入路径写 | 白名单更新为域路径 |
| test_local_clock_guard 允许点失效 | 时钟守卫允许清单未随重构更新 | 同上 |
| test_words_* 返回 403 | 测试种子/权限准备缺失 | conftest 补词库种子 + 认证夹具 |
| MemoryError | 大文件/OCR 用例吃内存 | 标记 + 资源门槛 skipif |

**带伤基线的危害**：每次跑测试都要人工分辨"这 42 个红是不是老问题"，真回归混在里面看不见；CI 若按现状跑全量必红，于是只能不跑或放水——门禁形同虚设。

做得对的（保持）：conftest 测试库硬隔离铁律、pytest.ini testpaths 防收集污染、真 PG 测试（不用 SQLite 掩盖方言缺陷）、前端 vitest 52 文件 + jsdom 超时/origin 已调优。

## 2. 完善标准

1. **CI 可信**：依赖安装失败即红；每个 job 显式声明运行时；job 级超时；CI 红 = 禁止合并/部署。
2. **基线零红**：全量 pytest 0 failed / 0 errors；确需豁免的用 `@pytest.mark.xfail(reason=..., strict=True)` 显式登记（strict：意外通过也报），**禁止用跳过/删测试消红**。
3. 覆盖率可见：后端核心域（services/kb_pipeline、ai_router、search、scope/security）行覆盖 ≥80%，全仓 ≥60% 起步只升不降（ratchet）。
4. CI 五 job 齐备：backend-test / frontend-test+build / lint / security-audit / e2e-smoke。
5. e2e 从 4 个 smoke 扩到覆盖核心闭环（登录→刷题→交卷→错题→复习队列→AI 问答），PR 跑 smoke、nightly 跑全量。
6. 测试数据契约：关键接口（words/quiz/kb/taxonomy）有响应字段契约测试，前后端字段漂移在 CI 暴露（项目已有 test_words_list_status_contract 先例，推广）。

## 3. 落地步骤

### 3.1 CI 修复（P0，半天）——可直接替换的 ci.yml

```yaml
name: CI
on:
  push: { branches: [main] }
  pull_request: { branches: [main] }

jobs:
  backend:
    name: 后端 pytest（真 PG）
    runs-on: ubuntu-latest
    timeout-minutes: 40
    defaults: { run: { working-directory: backend-main-fastapi } }
    services:
      postgres:
        image: postgres:16
        env: { POSTGRES_USER: postgres, POSTGRES_PASSWORD: postgres, POSTGRES_DB: kaoyan }
        ports: ["5432:5432"]
        options: >-
          --health-cmd "pg_isready -U postgres" --health-interval 10s
          --health-timeout 5s --health-retries 5
    env:
      PG_HOST: 127.0.0.1
      PG_PORT: "5432"
      PG_USER: postgres
      PG_PASSWORD: postgres
      PG_DATABASE: kaoyan_test
      DATABASE_BACKEND: postgresql
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.13", cache: pip, cache-dependency-path: backend-main-fastapi/requirements*.txt }
      - name: 安装依赖（失败即红，绝不吞）
        run: |
          python -m pip install --upgrade pip
          pip install -r requirements.txt -r requirements-dev.txt
      - run: python scripts/project_healthcheck.py
      - name: pytest + 覆盖率
        run: python -m pytest tests -q --timeout=300 --cov=. --cov-report=xml --cov-fail-under=60
      - uses: actions/upload-artifact@v4
        with: { name: coverage, path: backend-main-fastapi/coverage.xml }

  frontend:
    name: 前端 vitest + build
    runs-on: ubuntu-latest
    timeout-minutes: 20
    defaults: { run: { working-directory: frontend } }
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: "22", cache: npm, cache-dependency-path: frontend/package-lock.json }
      - uses: actions/setup-python@v5          # design_guard 显式声明运行时
        with: { python-version: "3.13" }
      - run: npm ci
      - run: python ../backend-main-fastapi/scripts/design_guard.py
      - run: npm test
      - run: npm run build                      # 构建破坏在 CI 暴露
      - uses: actions/upload-artifact@v4
        with: { name: static-dist, path: backend-main-fastapi/static }

  lint:
    runs-on: ubuntu-latest
    timeout-minutes: 10
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.13" }
      - run: pip install ruff
      - run: ruff check backend-main-fastapi
      - run: ruff format --check backend-main-fastapi
      # 前端 eslint 落地后（07 文档）追加 npm run lint

  security:
    runs-on: ubuntu-latest
    timeout-minutes: 10
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - uses: gitleaks/gitleaks-action@v2
      - uses: actions/setup-python@v5
        with: { python-version: "3.13" }
      - run: pip install pip-audit && pip-audit -r backend-main-fastapi/requirements.txt --strict

  e2e-smoke:
    name: Playwright smoke（真后端 + 真 PG）
    runs-on: ubuntu-latest
    timeout-minutes: 30
    needs: [backend, frontend]
    services:
      postgres:
        image: postgres:16
        env: { POSTGRES_USER: postgres, POSTGRES_PASSWORD: postgres, POSTGRES_DB: kaoyan }
        ports: ["5432:5432"]
        options: >-
          --health-cmd "pg_isready -U postgres" --health-interval 10s
          --health-timeout 5s --health-retries 5
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.13" }
      - uses: actions/setup-node@v4
        with: { node-version: "22" }
      - uses: actions/download-artifact@v4
        with: { name: static-dist, path: backend-main-fastapi/static }
      - name: 起后端（测试种子库）
        working-directory: backend-main-fastapi
        env:
          PG_HOST: 127.0.0.1
          PG_PORT: "5432"
          PG_USER: postgres
          PG_PASSWORD: postgres
          PG_DATABASE: kaoyan_e2e
          DATABASE_BACKEND: postgresql
          ADMIN_USERNAME: e2e_admin
          ADMIN_INITIAL_PASSWORD: ${{ secrets.E2E_ADMIN_PASSWORD || 'E2ePass!2026' }}
        run: |
          pip install -r requirements.txt
          python scripts/seed_e2e_minimal.py     # 新增：最小种子（科目/章节/20题/10词/1文档）
          nohup python -m uvicorn main:app --host 127.0.0.1 --port 8000 &
          for i in $(seq 1 30); do curl -sf 127.0.0.1:8000/api/health && break || sleep 2; done
      - name: Playwright
        working-directory: frontend
        run: |
          npm ci
          npx playwright install --with-deps chromium
          npm run e2e
        env:
          BASE_URL: http://127.0.0.1:8000
```
> 要点：`|| true` 删除；requirements-dev.txt（03 文档）承载 pytest/pytest-timeout/pytest-cov；e2e 用独立 kaoyan_e2e 库 + 最小种子脚本（新增 `scripts/seed_e2e_minimal.py`，幂等，不碰生产）。

### 3.2 基线清零（M，按类批量）

```powershell
cd D:\研途\gzdx_ky\backend-main-fastapi
# 1) 拿到当前精确失败清单（真 PG 测试库）
python -m pytest tests -q --tb=line 2>&1 | Tee-Object ..\..\docs\reports\pytest-baseline-$(Get-Date -Format yyyyMMdd).txt
```
逐类消解：
1. **旧导入**（预计占大头）：
   ```powershell
   Select-String -Path tests\*.py -Pattern 'from routers import (documents|kb|formula|quiz|words|tasks|plan|planner|errors|flashcards|goals|review|favorites|stats_export|papers|exam|codebank|insight|analytics|growth|dashboard|blind_spot|answers|quality|qa_tools|analysis)' -List
   # 按 registry.py 的 DOMAIN_ROUTERS 映射批量替换为 from routers.<domain> import <module>
   ```
2. **AST 白名单**：test_quiz_gate_ast / test_local_clock_guard 的允许清单改为从 `routers.registry.DOMAIN_ROUTERS` 动态生成（重构不再需要同步维护白名单——这是根治）。
3. **words 403**：conftest 增加认证夹具（登录 e2e 用户拿 cookie）+ 词库种子；参照 docx/60 的"新用户懒加载克隆"逻辑准备内置词书。
4. **MemoryError**：`@pytest.mark.skipif(psutil.virtual_memory().available < 4*1024**3, reason="内存不足")` 或拆小 fixture；CI runner 7GB 内存一般够，本地低内存才跳。
5. 每消一类跑一次全量，**最终 0F/0E**；实在无法短期修的业务缺陷 → strict xfail + 登记到 docs/reports/xfail-ledger.md（问题/责任人/预计修复版本），每迭代清一条。

### 3.3 覆盖率 ratchet（S）

- pytest-cov 进 requirements-dev；`--cov-fail-under=60` 起步，每月把阈值提到当前实际值（只升不降）。
- 核心域单独看：`--cov=services/kb_pipeline --cov=services/ai_router --cov=utils/scope --cov=utils/security` 目标 ≥80%。
- 不追数字游戏：新增业务代码必须带测试写进 CONTRIBUTING。

### 3.4 e2e 扩展（M）

现有 4 smoke（assistant/guest-public/quiz/schools）→ 增加核心闭环 spec：
```
e2e/
  auth.spec.js            # 登录/强改密/401 刷新/登出清 localStorage
  quiz-loop.spec.js       # 选知识点→答题→交卷→结果页→错题入本
  review-loop.spec.js     # 错题→复习队列→评分→下次到期变化
  kb-search.spec.js       # 上传文档→体检面板→检索命中→AI 引用来源
  isolation.spec.js       # 双账号：A 的错题/任务 B 不可见（B4 回归）
```
isolation.spec 是**行级隔离的永久回归闸**——scope.py 的 USER_ISOLATION 开关、108 迁移、路由接线任何一处回退都会被它抓住。
