# 04 · 后端架构与代码质量

> 覆盖问题：R10（无 lint/type 工具链）、R11（模型单体 + 兼容层债）、R12（scripts 失控）、R25（弃用 API/日志卫生）
> 优先级：R10/R11/R12 = P1，R25 = P2 ｜ 预计工作量：lint 落地 1 天；架构收敛 L（可分 4–6 个迭代）

## 1. 现状与证据

### 1.1 规模盘点（commit a7f92ea）

| 层 | 规模 | 评价 |
|---|---|---|
| routers | 53 个模块 / 6 域（study 24、knowledge 10、ai 6、kaoyan 6、platform 6、auth 1），485 条路由 | ✅ registry 收口良好，保持 |
| services | 144 个 .py | 🟡 数量偏多但职责尚清；缺依赖方向约束 |
| models | **models.py 1628 行单体** + `core/pg_models.py` 161 行 + `orm_aliases.py` 260 行兼容 shim | 🔴 三处定义/适配并存 |
| scripts | **494 个文件** | 🔴 一次性导入/回填/诊断/可复用工具/临时 JSON 混放 |
| main.py | 658 行，30 处 `print()` | 🟡 入口承担了中间件装配+启动种子+静态挂载+SPA fallback |
| 测试 | 118 个 test 文件 / 1525 用例 | ✅ 规模可观（基线问题见 06 文档） |

### 1.2 具体债务

1. **ORM 三轨**：`models.py`（59 类单体）与 `core/pg_models.py` 并存；ADR-002/003 canonical 改名（source→source_label、file_type→source_format、interval→interval_days…）后，业务代码仍用旧属性名，靠 `orm_aliases.install()` 在启动时打 synonym 补丁（main.py:33-43）。**兼容层没有退场计划 = 永久债**：新人读代码看到 `q.source`，库里列叫 `source_label`，grep 两头对不上。
2. **scripts/ 494 文件无生命周期**：`import_*`（一次性导入）、`fill_*`/`backfill_*`（一次性回填）、`fix_all_tests.py`（写死测试库 DSN）、`tmp_repo/`（抓取临时物）、`diagnostics/`（可复用）全在一层。无法回答"哪些脚本还能跑、哪些已完成历史使命"。
3. **弃用 API**：`@app.on_event("startup")`（main.py:316）在 FastAPI 0.104 已弃用，0.115 仍兼容但告警；升级窗口（03 文档）正是迁 lifespan 的时机。
4. **日志双轨**：已有 `utils/logger.py` 统一日志系统，但 main.py 启动段 30 处 `print()`——print 不进日志文件、无级别、无时间戳，服务器 journalctl 里格式混杂。
5. **零静态检查**：全仓无 pyproject.toml / ruff / mypy / .editorconfig / pre-commit。BOM 问题（10-28 报告提及 planner.py/review.py）现已修复，但**没有机制防止再犯**。
6. 死代码：10-28 报告 P3-2 指出 `_ensure_missing_platform_configs` 疑似未调用——**现已在 startup 调用（main.py:335），该条关闭**；但类似的"定义未调用"需要工具化排查而非人工审计。

## 2. 完善标准

1. **ruff（lint+format）+ mypy（渐进类型）进 CI 与 pre-commit**，新增代码 0 error；存量按目录分批清零。
2. ORM 单一真相源：`models/` 包按域拆分，`core/pg_models.py` 收编或明确分工；**orm_aliases 有退场路线图**（每迭代消灭一批旧属性名引用，最终删除 shim）。
3. scripts 分区 + 生命周期标注：`tools/`（可复用）/ `diagnostics/`（体检）/ `oneoff/`（一次性，带完成标记）/ `migrations/`（数据迁移），每个 oneoff 脚本头部注明状态与执行日期。
4. main.py ≤ 300 行：中间件装配、启动逻辑、静态挂载各自成模块；lifespan 替代 on_event；print 全部换 logger。
5. 依赖方向约束：routers → services → models/utils，禁止 services 反向 import routers（用 AST 检查脚本固化，项目已有 test_quiz_gate_ast 类似实践）。
6. 所有 .py 无 BOM、UTF-8、LF（.editorconfig + pre-commit 固化）。

## 3. 落地步骤

### 3.1 ruff + pre-commit（第一天）

仓库根 `pyproject.toml`（先宽后紧，避免一次性几千条告警淹没人）：
```toml
[tool.ruff]
target-version = "py313"
line-length = 120
extend-exclude = ["_archive", "scripts/oneoff", "training"]

[tool.ruff.lint]
select = ["E", "F", "W", "B", "I", "UP"]   # 错误/ flakes / bugbear / import 排序 / 升级建议
ignore = ["E501"]                          # 行长先交给 format

[tool.ruff.lint.per-file-ignores]
"tests/*" = ["B011"]
"scripts/*" = ["E402"]                     # 脚本常见 sys.path 前置

[tool.ruff.format]
quote-style = "double"
```
```powershell
pip install ruff
ruff check backend-main-fastapi --statistics   # 先看告警分布，留档
ruff check backend-main-fastapi --fix          # 自动修安全项（import 排序等）
ruff format backend-main-fastapi               # 格式化单独一个 commit，便于 blame 跳过
```
`.git-blame-ignore-revs` 登记格式化 commit。pre-commit（02 文档已建文件）追加：
```yaml
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.8.4
    hooks: [{ id: ruff, args: [--fix] }, { id: ruff-format }]
```
`.editorconfig`：
```ini
root = true
[*]
charset = utf-8
end_of_line = lf
insert_final_newline = true
[*.py]
indent_style = space
indent_size = 4
[*.bat]
end_of_line = crlf
```
> ⚠️ .bat 必须 CRLF 且无 BOM（项目已有 make_bats.py 校验），.editorconfig 与 pre-commit 的 mixed-line-ending 钩子要对 bat 豁免。

4. **orm_aliases 退场**：`orm_aliases.py` 里每个 synonym 就是一条待办。每迭代挑 1–2 个域，把业务代码旧属性名批量改为 canonical 名（ruff/grep 辅助），改完删对应 synonym。全部删完时移除 main.py 的 install() 段与 database.py 的懒初始化兜底。

### 3.5 main.py 瘦身 + lifespan + 日志（S，与 03 升级同批）

```python

from contextlib import asynccontextmanager

@asynccontextmanager

    # 原 on_startup 内容整体迁入，print → logger.info
    ...

    # 原 on_shutdown（如有）迁入
```

- `middleware_stack.py`：CORS/Token/GZip/StaticCache/TimeoutGuard 装配函数 `install_middlewares(app)`。

- 30 处 print 全换 `logger.info/warning`（启动横幅保留 logger 输出）。
