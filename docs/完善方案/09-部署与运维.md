## 2. 完善标准

1. 发布 = CI 产物 + 一键部署 + 自动健康验证 + **一条命令可回滚（前端/后端/数据库三层都真实可用）**。
2. 线上版本可追溯：/api/health 返回 git SHA + 构建时间；部署包名含 SHA。
3. 备份 3-2-1：至少 3 份副本、2 种介质、1 份异地；加密密钥异地单独保管；每季度恢复演练（05 文档）。
4. 四类告警必达手机：服务存活、磁盘水位、备份成败、证书续期（TLS 方案 A/C 时）。
5. 日志轮转生效，磁盘占用有上限。
6. 部署文档（DEPLOY.md）与脚本行为一致，回滚章节实测过。

## 3. 落地步骤

### 3.1 修复回滚链 + 版本标识（半天）

push_update.py 解包前插入：
```python
# ---- 前端回滚点：当前 static → static.prev（rollback.sh 的约定）----
remote(cli, f"cd {BACKEND_REMOTE} && "
            "if [ -d static ]; then rm -rf static.prev && mv static static.prev; fi",
       check=True)
```
> 注意顺序：备份 pre-<ts>.tar.gz 之后、解包之前。后端回滚靠 pre 包（已有）；数据库回滚靠 pg_restore（DEPLOY.md §10 + 05 文档演练）。

版本标识：构建时生成 `backend-main-fastapi/_version.py`：
```python
# scripts/gen_version.py（打包前调用）
import subprocess, datetime, pathlib
sha = subprocess.check_output(["git", "rev-parse", "--short", "HEAD"], text=True).strip()
dirty = subprocess.call(["git", "diff", "--quiet"]) != 0
pathlib.Path("_version.py").write_text(
    f'GIT_SHA = "{sha}{"-dirty" if dirty else ""}"\n'
    f'BUILT_AT = "{datetime.datetime.now(datetime.timezone.utc).isoformat()}"\n',
    encoding="utf-8")
```
main.py health 端点：
```python
from _version import GIT_SHA, BUILT_AT   # 缺失时兜底 "dev"
return {..., "version": "3.0.0", "git_sha": GIT_SHA, "built_at": BUILT_AT, ...}
```
push_update.py 的 package() 前调用 gen_version；部署包名改 `kaoyan-deploy-{TS}-{sha}.tar.gz`；本地包输出到 `deploy/artifacts/`（gitignore）并只保留最近 5 份。

### 3.2 异地备份接通（半天）

```bash
# 服务器装 rclone，配置对象存储（阿里云 OSS / 腾讯 COS / Backblaze B2 任选，个人量级月费 ≈ 0）
sudo apt install rclone
rclone config   # 新建 remote: kaoyan-backup（OSS/COS/S3 兼容）
```
backup.sh 启用并加固：
```bash
# 异地同步（替换占位行）
rclone copy "$BK" kaoyan-backup:kaoyan-backups --include "*.enc" --min-age 1m
# 异地也滚动：保留最近 30 份
rclone lsf kaoyan-backup:kaoyan-backups --files-only | sort -r | tail -n +31 | \
  while read f; do rclone deletefile "kaoyan-backup:kaoyan-backups/$f"; done
# 备份成败心跳（见 3.3）：成功才 ping
curl -fsS -m 10 https://hc-ping.com/<backup-uuid> || true
```
**密钥异地**：KAOYAN_SECRET_KEY、/etc/kaoyan/backend.env、.secrets 用密码管理器（Bitwarden/1Password）或打印纸质离线保存——**绝不与备份密文放同一存储**。backup.sh 注释已提醒，落实它。
cron 确认：`crontab -l` 有 `0 3 * * * /opt/kaoyan/deploy/backup.sh >> /var/log/kaoyan-backup.log 2>&1`。
恢复演练按 05 文档 §3.5，首次在本周做。

### 3.3 监控告警四件套（半天，全免费方案）

| 监控项 | 方案 | 配置 |
|---|---|---|
| 服务存活 | UptimeRobot / 自建 Uptime Kuma（家庭节点） | 每 5 分钟 GET `https://<入口>/api/health`，关键字 `"status":"ok"`；down 推送微信/Telegram/邮件 |
| 备份心跳 | healthchecks.io（免费 20 个） | 3.2 的 hc-ping；cron 超时 26h 未 ping 即告警（备份静默失败克星） |
| 磁盘/内存 | 服务器 cron 自检脚本 | 见下 |
| 证书续期 | certbot 自带 cron + UptimeRobot 证书过期监控（方案 A/C） | 到期前 14 天告警 |

```bash
# /opt/kaoyan/deploy/watchdog.sh（cron */30 * * * *）
#!/usr/bin/env bash
USE=$(df / | awk 'NR==2{print int($5)}')
[ "$USE" -ge 85 ] && curl -fsS -m 10 "https://hc-ping.com/<disk-uuid>/fail" -d "disk ${USE}%"
systemctl is-active --quiet kaoyan || curl -fsS -m 10 "https://hc-ping.com/<svc-uuid>/fail"
# 家庭算力节点连通（Tailscale）
ping -c1 -W3 100.92.154.42 >/dev/null || curl -fsS -m 10 "https://hc-ping.com/<node-uuid>/fail"
```
> 项目已有 utils/server_watchdog.py（进程内），系统级 watchdog 与之互补：进程内的管请求质量，系统级的管"进程/机器还活着吗"。

### 3.4 日志轮转（1 小时）

```
# /etc/logrotate.d/kaoyan
/opt/kaoyan/backend-main-fastapi/logs/*.log {
    daily
    rotate 14
    compress
    delaycompress
    missingok
    notifempty
    copytruncate
}
```
journald 限额：`/etc/systemd/journald.conf` → `SystemMaxUse=200M`，`systemctl restart systemd-journald`。
uvicorn 日志确认走 utils/logger.py 的文件 handler（04 文档 print 清理后统一）。

### 3.5 CI/CD 半自动化（1 天，可选但推荐）

GitHub Actions 增加手动触发 deploy job（repository secrets 存 SSH 私钥/主机指纹）：
```yaml
  deploy:
    if: github.ref == 'refs/heads/main'
    needs: [backend, frontend, lint, security]
    runs-on: ubuntu-latest
    environment: production          # 手动 approval 闸
    steps:
      - uses: actions/checkout@v4
      - uses: actions/download-artifact@v4
        with: { name: static-dist, path: backend-main-fastapi/static }
      - name: 部署（复用 push_update.py 的服务器段）
        env:
          SSH_KEY_B64: ${{ secrets.DEPLOY_SSH_KEY }}
          SSH_HOST: ${{ secrets.DEPLOY_HOST }}
          SSH_USER: deploy
        run: |
          mkdir -p ~/.ssh && echo "$SSH_KEY_B64" | base64 -d > ~/.ssh/id_ed25519 && chmod 600 ~/.ssh/id_ed25519
          ssh-keyscan -t ed25519 "$SSH_HOST" >> ~/.ssh/known_hosts
          python deploy/push_update.py --ci   # 新增 --ci：跳过本地打包，直接用 artifact
```
过渡期保留本地 push_update.py 双通道；CI 通道稳定后本地仅作应急。
DEPLOY.md 同步更新：static.prev 回滚实测记录、版本端点说明、异地备份与密钥保管、监控清单。
