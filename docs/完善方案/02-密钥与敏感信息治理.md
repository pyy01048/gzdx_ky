**风险判定**：这是本机开发库口令，但 ① 仓库曾公开，口令已进过公网与 git 历史；② 同一口令若被复用到服务器 PG（deploy 模板要求强密码，但无机制阻止复用），等于服务器库口令泄露；③ 40 个脚本各自写死连接，换口令要改 40 处，必然漏改 → 脚本集体失效。

### 1.2 数据库 dump 入库

`deploy/datasync_20261019.dump`（33.7MB，PG 自定义格式）被 git 跟踪。按文件名与部署链路推断含业务数据同步内容，**可能包含 users 表（密码哈希）、platform_configs（加密后的网盘/AI 凭据）、个人学习数据**。即使凭据有 AES-256-GCM 加密，主密钥若曾出现在任何 commit/日志，密文等同明文。

### 1.3 做得对的（保持）

## 2. 完善标准

1. **任何源码/文档/ notebook / SQL 中不出现真实口令、token、API key**；连接参数唯一来源是环境变量（`.env` / `/etc/kaoyan/backend.env`）。
2. 数据脚本与主应用**共用同一套连接解析**（`database.py` 的 `build_database_url()`），不再各写各的。
3. 已泄露口令**全部轮换**（本机 PG、服务器 PG、以及任何复用该口令的服务）。
4. git 历史中的口令与 dump 被清除（filter-repo），且清除前仓库已私有。
5. 提交链路上有**自动密钥扫描**（pre-commit + CI 双闸），再犯在提交时就被拦下。
6. 文档中的连接串一律脱敏写法：`postgresql+psycopg://kaoyan:***@127.0.0.1:5432/kaoyan`。

### 3.2 建立脚本统一连接入口（一次性基建）

新建 `backend-main-fastapi/scripts/_conn.py`：

```python
"""数据脚本统一连接入口：与主应用同源解析 .env，禁止硬编码口令。

用法（任何 scripts/ 下的脚本）：
    from scripts._conn import pg_connect, dsn
    conn = pg_connect()                # psycopg3 连接，参数全部来自环境变量
    # 或需要 DSN 字符串时：
    psycopg.connect(dsn())
"""
from __future__ import annotations
import os
from pathlib import Path
from dotenv import load_dotenv

# 与 main.py 相同口径加载后端 .env
load_dotenv(Path(__file__).resolve().parent.parent / ".env")

def dsn() -> str:
    return (
        f"host={os.getenv('PG_HOST', '127.0.0.1')} "
        f"port={os.getenv('PG_PORT', '5432')} "
        f"dbname={os.getenv('PG_DATABASE', 'kaoyan')} "
        f"user={os.getenv('PG_USER', 'kaoyan')} "
        f"password={os.environ['PG_PASSWORD']}"   # 缺失直接 KeyError，绝不静默用默认口令
    )

def pg_connect():
    import psycopg
    return psycopg.connect(dsn())
```

然后批量改造 40 个脚本（可半自动）：

```powershell
cd D:\研途\gzdx_ky\backend-main-fastapi
# 1) 列出所有命中文件
Select-String -Path scripts\*.py -Pattern 'kaoyan_dev_2026' -List | Select-Object -ExpandProperty Path
# 2) 逐文件把 DB=dict(...)/DB_DSN="..." 替换为：
#    from scripts._conn import pg_connect / dsn
#    conn = pg_connect()
# 3) 改完全仓复查，必须 0 命中：
Select-String -Path scripts\*.py,docs\*.md -Pattern 'kaoyan_dev_2026'
```

改造规则：
- `DB = dict(...)` → 删除，`psycopg.connect(**DB)` → `pg_connect()`
- `DB_DSN = "host=... password=..."` → `from scripts._conn import dsn`，`psycopg.connect(dsn())`
- `fix_all_tests.py` 的测试库 DSN → 读 `PG_DATABASE_TEST`（默认 kaoyan_test），口令同样走 env
- 两份报告里的 DSN → 手工脱敏为 `kaoyan:***@`
- 顺带把 `scripts/` 里其它写死 `127.0.0.1:5432` 但口令走 env 的脚本也统一到 `_conn.py`（消灭连接参数漂移）

### 3.3 提交链路密钥扫描（双闸）

```powershell

```
仓库根 `.pre-commit-config.yaml`：
```yaml

  - repo: https://github.com/gitleaks/gitleaks
    rev: v8.21.2
    hooks: [{ id: gitleaks }]
  - repo: https://github.com/pre-commit/pre-commit-hooks

      - id: check-merge-conflict
```


### 3.4 git 历史清除（与 01 文档 §3.3 同一轮执行）

```powershell
# 在已补全历史的克隆上，先写替换清单
@"
kaoyan_dev_2026==>***REMOVED***
"@ | Set-Content -Encoding UTF8 replacements.txt
# 与 01 文档的路径删除合并为一次 filter-repo：
git filter-repo --invert-paths `
  --path deploy/datasync_20261019.dump `
  --path-glob 'deploy/kaoyan-deploy-*.tar.gz' `
  --path data/backups/kaoyan_school_domain_20261021.sql `
  --replace-text replacements.txt --force
```
> 注意：`--replace-text` 会改写所有含该字符串的历史文件内容；当前工作区的脚本必须先完成 §3.2 改造并提交，否则重写后工作区与历史不一致。清理后 `git log -S 'kaoyan_dev_2026' --all` 必须为空。

### 3.5 dump 与备份的长期存放

- dump/备份**只放** `database/backups/`（gitignore）或服务器 `/opt/kaoyan/backups/`，加密后异地（09 文档 §3）。
- 需要"数据同步包"走部署链路（push_update.py 或 rclone 点对点），**永远不进 git**。
- 每季度跑一次 `gitleaks detect` 全量复查 + `git ls-files | Where-Object Length -gt 500KB` 大文件审计。
