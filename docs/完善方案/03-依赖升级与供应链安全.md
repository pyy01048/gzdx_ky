# 03 · 依赖升级与供应链安全

> 覆盖问题：R04（已知漏洞依赖暴露在公网上传入口）
> 优先级：🔴 P0 ｜ 预计工作量：1–2 天（含回归）

---

## 1. 现状与证据

`backend-main-fastapi/requirements.txt` 关键锁定：

| 依赖 | 当前版本 | 问题 |
|---|---|---|
| `fastapi` | **0.104.1**（2023-11） | 强制 starlette `>=0.27.0,<0.28.0`，被钉死在 0.27.x |
| `starlette`（传递） | 0.27.0 | **CVE-2024-47874**：multipart/form-data DoS（解析大量表单字段耗尽资源），0.40.0 修复；另有 CVE-2025-54121（FileResponse 大文件阻塞事件循环，0.47.2 修复） |
| `python-multipart` | **0.0.6** | **CVE-2024-53981**（高危 DoS：畸形 boundary 导致 CPU 空转），0.0.18 修复；CVE-2024-24762（ReDoS），0.0.7 修复 |
| `pydantic` | 2.5.2 / ≥2.8.2,<2.9 按 Python 版本分流 | 与 fastapi 0.104 兼容性"未验证先封顶"（注释自述） |
| `pypdf` | 4.2.0 | 后续版本修复多个解析死循环/资源耗尽问题（扫描件解析入口直接吃用户上传 PDF） |
| `Pillow` | 10.3.0 / ≥10.4.0 分流 | 10.x 后续有安全修复版本 |

**为什么是 P0**：平台已公网开放（60.204.223.140:80），`/api/documents` 上传、错题拍照 OCR 等入口直接接收外部 multipart 请求与 PDF——上述 DoS 漏洞的攻击面是真实暴露的，且 2C2G 服务器资源极小，一个畸形请求就能打满。

其它供应链问题：
- **无 Python 锁文件**：requirements 里大量 `>=` 浮动（httpx、trafilatura、lxml、onnxruntime、urllib3…），不同时间安装得到不同版本，"本机实测可用组合"不可复现。
- **无 dev 依赖清单**：pytest/pytest-timeout/httpx 测试依赖靠 CI 临时 `pip install`，本地与 CI 不一致。
- **无漏洞扫描**：没有 pip-audit / dependabot（01 文档已补 dependabot 配置）。
- 双 Python 版本分流（<3.13 / ≥3.13）是历史包袱：本机 3.13、服务器 <3.13，同一份代码两套依赖行为。

做得对的：注释里写清了每个锁定的原因与降级行为（jieba 缺失退化为 2-gram、rapidocr 传递依赖缺失被吞成"0 字"等）——升级时这些注释是宝贵的回归检查单。

## 2. 完善标准

1. 公网暴露组件（fastapi/starlette/python-multipart/pypdf/Pillow）**无已知高危 CVE**（pip-audit 0 high/critical）。
2. 依赖**两层管理**：`requirements.in`（意图 + 约束注释）→ `requirements.txt`（pip-compile 全量锁定含哈希），可复现安装。
3. 测试/开发依赖独立 `requirements-dev.txt`，CI 与本地同源。
4. 本机与服务器 **Python 主次版本统一**（建议 3.12 或 3.13 二选一），消除 marker 分流。
5. 每次升级有回归记录：全量 pytest + 前端 build + 关键链路 smoke（上传/OCR/检索/AI 流式）。
6. dependabot 每周提 PR + CI pip-audit job 常态红绿。

## 3. 落地步骤

### 3.1 最小安全升级（P0，先做，不动架构）

目标：只升漏洞组件及其连带，保持其余锁定不变。

```powershell
cd D:\研途\gzdx_ky\backend-main-fastapi
# 1) 现状漏洞扫描留档
pip install pip-audit
pip-audit -r requirements.txt --format json -o ..\..\docs\reports\pip-audit-before.json
```

分两档执行（按风险承受选）：

**档位 A · 保守（半天）**：fastapi 升到 0.115.x 线（starlette ≥0.40 修复 CVE-2024-47874），pydantic 随之放宽到 2.9+：
```text
fastapi==0.115.12          # starlette>=0.40,<0.47；修复 multipart DoS
python-multipart==0.0.20   # 修复 CVE-2024-53981 / CVE-2024-24762
pydantic>=2.9,<3           # fastapi 0.115 兼容线；去掉 <2.9 封顶
pypdf==5.4.0               # 解析安全修复累积
Pillow>=10.4,<12           # 统一分流，取安全修复版
```
⚠️ fastapi 0.104 → 0.115 的行为差异需重点回归：
- `@app.on_event` 仍可用但告警（04 文档迁 lifespan）
- pydantic 2.9 的序列化/校验细节（schemas.py 全量过一遍测试）
- starlette 0.40+ 的 multipart 解析更严格（上传接口回归）
- `UtcZJSONResponse` / 中间件链（main.py 的裸 ASGI TimeoutGuard）在 new starlette 下跑一遍 SSE 流式

**档位 B · 彻底（1–2 天）**：fastapi 最新稳定线 + starlette ≥0.47.2（连 FileResponse 阻塞问题一起修），其余同 A。个人项目建议直接 B，回归成本差不多。

```powershell
# 2) 升级后全量回归（铁律：真 PG 测试库）
python -m pytest tests -q --timeout=300
# 3) 关键链路 smoke（起服务后）
#    上传一个 PDF → OCR → 入库 → 检索 → AI 流式问答 → 拍照错题
# 4) 复扫
pip-audit -r requirements.txt   # 目标：0 high/critical
# 5) 前端构建 + vitest
cd ..\frontend; npm ci; npm test; npm run build
```

服务器同步：push_update.py 部署后在服务器 `.venv` 内 `pip install -r requirements.txt` 并重启（DEPLOY.md 流程），**先本机验证通过再推服务器**。

### 3.2 锁定体系（pip-tools）

```powershell
pip install pip-tools
```
把现有 requirements.txt 改造为 `requirements.in`（保留全部中文注释——那是降级行为说明书），浮动版本收紧为兼容区间：
```text
# requirements.in（意图层，注释原样保留）
fastapi==0.115.12
uvicorn==0.30.6
sqlalchemy>=2.0.36,<2.1
psycopg[binary]==3.2.10
httpx>=0.27,<0.29
...
```
```powershell
pip-compile requirements.in -o requirements.txt --generate-hashes --resolver=backtracking
pip-compile requirements-dev.in -o requirements-dev.txt --generate-hashes
# requirements-dev.in：
#   -c requirements.txt
#   pytest>=8,<10
#   pytest-timeout
#   pytest-cov
#   httpx
#   pip-audit
#   ruff
#   pre-commit
```
CI 与本地统一 `pip install -r requirements.txt -r requirements-dev.txt`（CI 改造见 06 文档）。
> 哈希锁定在 Windows/Linux 双平台都可用；服务器部署同样用锁文件，消除"服务器行为不变"靠注释祈祷的现状。

### 3.3 Python 版本统一

- 建议统一到 **3.13**（本机已是 3.13.9；requirements 注释里 3.13 的 wheel 问题在 2026 年已基本消失）。
- 服务器：`python3.13 -m venv /opt/kaoyan/backend-main-fastapi/.venv-new` → 装锁文件 → 全量 smoke → 切换 systemd 指向 → 保留旧 venv 一周可回退。
- 统一后删除 requirements 里全部 `; python_version < "3.13"` 分流行，注释归档到 docs/reports/。

### 3.4 常态化

- CI 增加 `pip-audit -r requirements.txt --strict` job（06 文档）。
- dependabot 每周 PR：小版本自动合（CI 绿即合），fastapi/pydantic/sqlalchemy 大版本人工评审 + 全量回归。
- 每次升级在 CHANGELOG 记一行：`deps: fastapi 0.104.1→0.115.12（CVE-2024-47874）`。
