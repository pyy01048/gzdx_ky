## 2. 完善标准

1. **单一文档树** `docs/`，docx/ 编号体系收编为 docs/reports/ 子目录；README 只做"门面 + 索引"，不承载会过期的细节数字。
2. README 所有链接指向仓库内真实存在的文件（CI link-check 守卫）；所有数据数字来自 readme_counts.py 自动生成块。
3. 决策登记册真实反映状态：已落地的 OPEN 项关闭并写 Resolution；ADR 状态同步。
4. 文档分层清晰：现行指南（guides）/ 架构决策（decisions）/ 历史报告（reports，只增不改）/ 数据台账（data）。
5. 每份现行指南有"最后核对日期 + 对应 commit"头；超过 90 天未核对的在索引中标 stale。

### 3.2 README 重写（半天）

原则：**门面薄、数字自动、链接真实**。骨架：
```markdown
# 考研学习平台（gzdx_ky）
一句话定位 + 截图 1 张 +  badges（CI 状态）
## 快速开始（≤10 行，指向 docs/guides/quickstart.md）
## 功能总览（模块表，不写具体数字）
## 数据实况（自动生成块，见下）
## 技术栈（表）
## 文档索引（只列 docs/README.md 一个入口 + 3 个最常用指南）
## 已知短板（诚实清单，每项指向对应完善文档/issue）
## 版权与使用边界（11 文档声明）
```
数字自动化：readme_counts.py 增加 `--write-readme` 模式，把查询结果写进 README 的标记块：
```markdown
<!-- COUNTS:BEGIN（自动生成，勿手改；刷新：python scripts/diagnostics/readme_counts.py --write-readme）-->
| 指标 | 数值 | 口径日期 |
...
<!-- COUNTS:END -->
```
发布流程（CONTRIBUTING）：每次数据批量变更/部署后跑一次刷新；CI 增加检查——COUNTS 块日期距今 >30 天则 warning。

### 3.4 链接与时效守卫（S）

CI 增加 doc-check job：
```yaml
  docs:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: lycheeverse/lychee-action@v2
        with:
          args: --offline --no-progress README.md docs/**/*.md   # 只查仓库内相对链接
          fail: true
```
指南头部模板：
```markdown
> 最后核对：2026-11-20 · commit a7f92ea · 维护人：pyy
```
docs/README.md 索引脚本扫描头部日期，>90 天标 `⚠️ stale`。
