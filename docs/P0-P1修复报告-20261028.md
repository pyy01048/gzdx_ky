## 详细修复说明

### P0-1 路由重构收尾（main.py）

**问题**：V3.1 路由重构将 51 个 router 移入 `routers/{ai,auth,kaoyan,knowledge,platform,study}/` 子目录，但 `main.py` 仍使用旧的扁平导入 `from routers import stats_export, ...`，而 `routers/__init__.py` 是空包，导致 `ImportError: cannot import name 'stats_export' from 'routers'`，服务无法启动。

**修复**：
- `main.py` 改用 `routers/registry.py` 的 `iter_routers()` 循环挂载全部路由。
- 保留 startup 事件、静态文件挂载、异常处理器等必要逻辑。

**验证**：
```
from main import app
APP_OK 485
```

### P0-2 修正 registry.py future 拼写

**问题**：`routers/registry.py:15` 写为 `from __future import annotations`（少一个下划线），导致 `ModuleNotFoundError: No module named '__future'`。

**修复**：改为 `from __future__ import annotations`。

**验证**：registry 正常导入，`iter_routers()` 可调用。

### P0-3 补齐 memory 三表与枚举

**问题**：`models.py` 定义了 `MemoryTrace`/`MemoryFact`/`MemorySynthesis`，但 PG 中表与枚举类型完全不存在，`/api/memory/*` 8 个端点必 500。

**修复**：在 PostgreSQL 中创建：
- 表：`memory_traces`、`memory_facts`、`memory_synthesis`
- 枚举：`memory_trace_type`、`memory_source_layer`

**验证**：
```sql
SELECT tablename FROM pg_tables WHERE schemaname='public' AND tablename IN ('memory_traces','memory_facts','memory_synthesis');
-- memory_facts / memory_synthesis / memory_traces ✅
```

**备份**：`database/backups/kaoyan_schema_backup_before_memory_20261028_142528.sql`

### P1-1 66 篇 failed 文档补 parse_error 与重试入口

**问题**：66 篇文档 `index_status='failed'` 但 `parse_error` 为空、`parse_progress=1`；kb_pipeline 体检口径不把 failed 当缺口。

**修复**：
- 为 failed 文档补写 `parse_error` 失败原因。
- kb_pipeline 体检口径增加 failed 状态统计。
- 提供重试入口（kb_pipeline --heal 可重试 failed 文档）。

**验证**：
```sql
SELECT index_status, COUNT(*), COUNT(*) FILTER (WHERE parse_error IS NOT NULL AND parse_error <> '') AS with_error
FROM documents GROUP BY index_status;
-- indexed 2600 (with_error 0) / failed 66 (with_error 66) ✅
```

**备份**：`database/backups/documents_backup_before_parse_error_20261028_143141.sql`

### P1-2 清理/回填 scorelines major_id

**问题**：`kaoyan_scorelines` 182,748 行中 164,829 行 `major_id` 为 NULL（多来源导入导致专业关联缺失）；最初诊断口径误判为"孤儿"。

**修复**（方案 B1 修正口径）：
- 只回填 `major_id IS NULL` 且 `major_name` 非空、`school_id + major_name` 在 `kaoyan_majors` 唯一命中的行。
- 排除已存在同键行 `(school_id, major_id, year, line_type)`。
- 同一组内保留 `source_id` 排序最小的一条，其余跳过（避免 uq_scoreline 冲突）。
- **未删除任何数据**。

**验证**：
```sql
SELECT COUNT(*) total, 
       COUNT(*) FILTER (WHERE major_id IS NOT NULL) with_major,
       COUNT(*) FILTER (WHERE major_id IS NULL) null_major,
       COUNT(*) FILTER (WHERE major_id IS NOT NULL AND NOT EXISTS (SELECT 1 FROM kaoyan_majors m WHERE m.id = kaoyan_scorelines.major_id)) orphan
FROM kaoyan_scorelines;
-- total=182748 / with_major=30371 / null_major=152377 / orphan=0 ✅

-- 重复键检查
SELECT COUNT(*) FROM (
  SELECT school_id, major_id, year, line_type, COUNT(*)
  FROM kaoyan_scorelines WHERE major_id IS NOT NULL
  GROUP BY school_id, major_id, year, line_type HAVING COUNT(*) > 1
) dup;
-- 0 ✅
```

**结果**：
- 成功回填 **12,452 行**（17,919 → 30,371 非空）
- 重复键 **0**
- 孤儿 **0**
- 剩余 152,377 行 NULL 保持原样（源数据重复导致无法安全关联，属合法原始数据）

**备份**：`database/backups/kaoyan_scorelines_backup_20261028_143740.sql`（31MB 全表）

**回填 SQL 脚本**：`backend-main-fastapi/scripts/backfill_scorelines_major_id_a1.sql`（A1 版，B1 修正版由主理人执行）
