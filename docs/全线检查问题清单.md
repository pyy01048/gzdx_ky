> **根因（脚本 bug，非真实故障）**：`scripts/diagnostics/check_env.py` 第 30-31 行只读取 `DATABASE_PATH` 或回退到 `backend/data/kaoyan.db`，用 **sqlite3** 连接。但 `.env` 已配置 `DATABASE_BACKEND=postgresql` 且真实库是 PostgreSQL，脚本**完全没有解析 PG 连接**，于是连到不存在的 sqlite 文件（或 0 字节诱饵库）误报。见问题 #B-4。

### 3.3 main.py app 加载

- **❌ `from main import app` 失败**：
  ```
  ImportError: cannot import name 'stats_export' from 'routers'
  ```
- **根因（P0）**：git 工作区正处于 **V3.1 路由重构中途**（`git status` 显示 51 个 `routers/*.py` 全部 `R` 重命名到 `routers/{ai,auth,kaoyan,knowledge,platform,study}/` 子目录，且 `routers/registry.py` 为未跟踪新文件），但 `main.py` 仍用旧的扁平导入 `from routers import stats_export, ...`，而 `routers/__init__.py` 是空包，不导出子模块 → 导入失败。
- **叠加问题（P0）**：新架构的 `routers/registry.py` 第 15 行 `from __future import annotations` **拼写错误**（少了结尾下划线，写成 `from __future`），导致即使 main.py 改用 registry 也会 `ModuleNotFoundError: No module named '__future'`。
- **修复方向**（二选一）：
  1. 让 `main.py` 改用 `from routers.registry import iter_routers` 循环挂载（符合新架构），并修正 `registry.py` 拼写；
  2. 或在 `routers/__init__.py` 中从子目录 re-export 全部 51 个模块（兼容旧 main.py）。
- 经验证：registry 的 `DOMAIN_ROUTERS` 覆盖了 main.py 需要的全部 51 个模块名，无遗漏。→ 方案 1 是正解。
