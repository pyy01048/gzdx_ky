## 一、掌上考研取证

### 1.1 身份纠偏（先修前提）

「掌上考研」**不是研招网官方 App**，是**中国教育在线（EOL）**旗下产品：

- 开发者/运营者为「中教智网(北京)信息技术有限公司」（EOL 体系）。【B】App Store：<https://apps.apple.com/cn/app/id1478224092>（"开发者 中教智网(北京)信息技术有限公司"，版本 6.7.8，2026-10-17 更新）；应用宝 <https://sj.qq.com/appdetail/cn.eol.kaoyan>（同开发商，V 6.7.8）。
- 百度百科：中国教育在线推出，2014 年推出轻量化访问模式，2020 年上线为考研信息服务平台。【C】<https://baike.baidu.com/item/掌上考研/24264540>
- 研招网官方平台是 yz.chsi.com.cn（教育部，导航为 院校库/专业库/硕士目录/统考网报等），与掌上考研是两个体系。【B】<https://yz.chsi.com.cn/>
- 对本任务的含义：掌上考研的价值在「第三方聚合站的成熟 IA」，其数据的权威性仍应以研招网/院校官网为准（与 07 落地方案的口径一致）。

### 1.2 院校模块信息架构

**整体形态**（商店文案 + 百科 + 网页实测）：以「查学校/查专业」双检索为骨架，院校数据、真题资料、调剂、直播/研招会、AI 问答挂在同一首页。应用宝简介：研招信息查询覆盖 900 余所高校及科研院所——招生简章、招生计划、录取分数线、报录比、调剂信息、复试信息。【B】应用宝页"简介"节。

**网页版实测**（2026-10-11 实测记录，`docx/_analysis/reference-sites-notes.md`，kaoyan.cn 当时可抓）【A·实测转档】：

- **院校列表** `kaoyan.cn/school-list/0-0-0`（§站2，:50-72）：
  - 三维筛选：**院校位置（含 A/B 区）× 院校类型（13 类）× 院校层次**；
  - 结果计数（"共找到 1109 条结果"）；
  - **卡片流（非表格）**：每卡 = 校名 + 省份 + 层次标签（可叠加 985/211/双一流/自划线）+ **快捷入口按钮（招生简章/招生计划/复试分数/历年真题/调剂查询）** + 关注按钮。
- **院校详情** `kaoyan.cn/school/198`（贵州大学）（§站3，:79-110）：
  1. **院校档案头部**：校名 + 标签（211 双一流）+ 分区/省份/类型（B区·贵州·综合类）+ **一排关键指标卡**：129 专业招生数 / 4177 招生人数（不含推免）/ 软科综合 85 / 校友会综合 78 / US世界 888；
  2. 院校简介（长文折叠）+ 联系方式块；
  3. 办学规模指标（建校时间/占地面积/国家重点学科/重点实验室/博士点/硕士点）；
  4. 开设学科（学科 + 评估等级 + 博/硕士点）；
  5. 招生计划（折叠区）+ 招生公告列表 + 招生简章列表（标题 + 日期，时间倒序，"全部"下钻）。
  - **结论：分数线、报录比、招生简章、复试信息不设独立页面，全部收进院校详情的下钻结构里。**
- **招生计划** `…/plan/1434937`（§站4，:110-120）【D·结构推断，正文当时为空】：学院/专业下拉筛选；**专业 → 方向 → 人数 → 考试科目 四段式**；拟招/推免区分；科目带代码+名称。
- **历年分数** `…/score#year=2026`（§站5，:130-143）【D·结构推断】：**年份切换器用 URL hash（可分享的状态）**；分专业分数表（复试线总分/单科、最低/最高/平均、国家线、录取人数）；同比批注。
- **公告页** `…/zsgg`（§站6，:149-163）【A·实测】：**双分类 Tab（招生公告 / 招生简章）**，标题 + 日期时间倒序的长列表，详情 `/news/{id}`。

**App 侧演进信号**（App Store 版本历史，6.6.4→6.7.8）【B】：

- 6.7.0 与 6.7.8 两次「首页全新改版，功能布局更清晰」→ 首页被当作**查找效率**的核心不断打磨；
- 6.7.7「首页新增消息通知栏」「招生计划页面增加**数据来源说明**，计划数据有依据」→ 通知入口上浮到首页；数据可信度写进产品；
- 6.7.6「院校详情页优化，院校数据更清晰」；
- 6.6.8「复试/加试资料上线」「考研难度系数（大数据分析复试录取数据）」「招生计划大数据分析升级」；
- 6.6.5「考研小智 AI 问答（DeepSeek）」。

**App 内部页面级 IA：本次未实测**（无运行环境）。以上 App 侧结论基于商店文案/百科/版本史【B/C】，具体控件布局为【D】推断，不写进结论。

### 1.3 通知类信息呈现与提醒

- **院校维度**：公告与简章是详情页内的**双分类列表**（标题+日期倒序，回链详情）【A】；不做独立跨校页。
- **首页维度**：6.7.7 起**消息通知栏**进首页【B】；百科列出「考研资讯」模块做全站资讯推送【C】。
- **提醒机制**：商店证据只能证明「消息通知栏 + 资讯推送」存在；**报名/初试/复试节点级提醒（日历、push）在公开资料中未见细节**——标注【D】待证。标杆能力可参考仓库《标杆报告》§3.6 的节点提醒清单（预报名/正式报名/网上确认/准考证/初试/查分/国家线/复试，`docs/【标杆报告】优秀考研学习平台应具备的特征V1.0.md`，§3.6）。

## 二、txkyer.cn（天行考研）取证

### 2.1 可达性事实（多点交叉）

- 2026-10-11 侦察：❌ 无法访问，两次 WebFetch 均失败，搜索无有效收录，推断已下线或被阻断（`docx/_analysis/reference-sites-notes.md:19,41`）。
- 2026-10-17 落地方案：「txkyer 仅 **http** 可访问（https 不可用）」（`docs/落地方案/07-院校落地方案.md:166`）。
- 本次实测（2026-10-19）：本机 `Resolve-DnsName txkyer.cn` 无解析；`curl` http/https 及 www 变体均 000；`fetch_content` 两次 invalid_response；Web Archive 亦不可达（本机网络受限）。
- **结论：站点当前不可达【A·实测】；其信息架构只能以一手代码 + 实访转述为据，页面级结构标【C/D】。**

### 2.2 数据架构（一手代码，等级最高）

仓库的种子导入脚本直接记录了它的形态（`backend-main-fastapi/services/kaoyan/seed_txkyer.py`）：

- 整站院校数据是一个静态 JS 文件：`http://www.txkyer.cn/data/kaoyan_data.js`（:9）；
- 结构：`window.KAOYAN_DATA = {"records": [[省份, 校名, 学院, 专业代码, 专业名, …, 院校级别], …]}`（:31-36 注释，222 校通信电子类种子）；
- 字段即数组位置，级别四档 985/211/双一流/双非。
- **含义：txkyer 是「单页数据看板」型站点——没有逐校服务端页面，数据整包下发、前端渲染**。这解释了本平台借鉴它的方式：紧凑表格 + 数组口径，而非内容页。

### 2.3 字段口径与展示模式（实访转述，【C】，原始 recon 文件缺失）

`docs/落地方案/07-院校落地方案.md` 引用的实访记录 `research/txkyer-recon.md` **不在本工作区**（00 方案注明它在上级目录 `..\research\`，未随仓库入库）——已如实标注为缺失证据。经 07 转述的可信口径（:56、:79、:166）：

- 院校详情分数图表：**进复试/拟录取人数、均分/最低分、按「专业+学院+初试科目」分组的总分/专业课分布**；
- 首页数据层：**倒计时 + 热度榜 TOP10 + 今日待办**（`docx/_analysis/pm-reading-notes.md:263`「对标 txkyer」）。

### 2.4 本平台已吸收的 txkyer 模式（一手代码注释，`frontend/src/pages/KaoyanSchoolDetail.jsx`）

- :186-190 分数表「参考站模式：红色分数 = 院线与国家线的差值」；
- :206-208 公告 tab「采集到数据才显示（无数据不摆空壳）」；
- :211 Hero「校名 + 徽章 + 位置 + 关注（参考站院校卡模式）」；

## 三、推荐信息架构：简洁版院校模块

### 3.1 结论：学生端 3 页 + 管理端 1 页（可选 +1 对比）

```
学生端（3 页）                                管理端（1 页）
┌──────────────────────────────┐            ┌────────────────────┐
│ P1 院校库（=择校唯一入口）      │            │ P4 收集管理         │
│  搜索 + 筛选(A/B区×类型×层次)   │            │  数据源启停/采集运行 │
│  院校卡：校名+省+层次标签       │            │  导入/质量/采集源    │
│   +核心指标条(3项可信指标)      │            └────────────────────┘
│   +快捷入口(计划/分数/公告)+关注 │
└──────────────┬───────────────┘
               │ 点卡片
┌──────────────▼─────────────────────────────────┐
│ P2 院校详情（单页 4 Tab）                        │
│  Hero：校徽/校名/层次标签/地区/官网/设为目标       │
│        + 指标条（≤6，全部挂来源徽标）             │
│  Tab1 概况      简介 + 联系方式（有数据才显）      │
│  Tab2 招生计划   年份切换 + 专业→方向→拟招/推免    │
│                 →考试科目 四段式表；行展开:参考书目 │

│        红色差值=院线-国家线；DataQualityNote 折叠  │

│  统计卡：初试 n / 复试 n / 报名 n / 招生简章 n     │
```

### 3.2 依据（为什么收成这样）

- **对标掌上考研**：分数线/报录比/简章/复试信息全部收进院校详情的下钻结构，独立子页只服务跨校任务（调剂/真题）；列表页只做「筛+卡」【A】。年份切换用可分享的 URL 状态【D】。
- **对标 txkyer**：单页数据看板 + 「无数据不摆空壳」+ 红色差值批注 + 均分/人数分布口径【A/C】。
- **贴合本平台数据现实**：
  - 字段可信度审计（`frontend/src/utils/kaoyanFields.js` §UNTRUSTED_FIELDS）：national_line 全库 0/811 有值、politics/english_line 0% 命中、math_line 3.3% 命中、admit_count 为伪造列——**分数线页独立存在只会展示大面积空态**；可信的只有 total_line（进面最低分）、major_line、人数类（进线/录取）、复录比（93.8% 命中）。
  - 2026-10-19 晨报：816 所院校 level/intro/official_url 全空——**院校库卡片不能依赖官方简介/星级，只能依赖筛选+标签**。
  - 公告数据 518 条但仅覆盖 8 校、publish_date 125/518（`docx/_analysis/pm-reading-notes.md` D10）——**复试方案/名单/拟录取名单独立成页必然长期空置**，且 07 方案合规红线：拟录取名单中考生姓名/考号不入库，只聚合人数/分布（`docs/落地方案/07-院校落地方案.md:160`）。
  - 考试科目已有结构化归一入口（`kaoyanFields.js` §examSubjects，`kaoyan_majors.exam_subjects`），天然是招生计划表的一列，不需要独立页。

## 四、减法清单（11 子页 → 学生端 3 + 管理端 1）

## 五、通知收集与统计（初试/复试/报名/招生简章四类）展示建议

1. **类型口径固定为四类**：招生简章（简章/专业目录类）、初试（初试科目/大纲/参考书变更）、复试（复试方案/名单/拟录取）、报名（网报公告/考点公告）。采集入库时打标，四个 chips 贯穿「通知中心列表 ↔ 院校详情 Tab4」两处，口径一致。
2. **统计卡 = 首屏**：每类一张卡（计数 + 未读数），顶部再给「覆盖院校数 / 最近更新时间」。未读与已读/星标沿用现平台通知中心已有能力（navConfig.js:46「公告已读/置顶·改考雷达」）。
3. **列表规则**：时间倒序、当日更新高亮、跨校聚合；每条 = 标题 + 院校名 + 类型徽标 + 发布日期 + 来源徽标（官方/聚合/未验证，`kaoyanFields.js` §SOURCE_TYPES）+「阅读原文」回链。只存元数据不转正文（07:160 合规标准）。
4. **提醒三层**（对齐掌上考研「消息通知栏」+ 仓库标杆报告节点清单）：
   - 全局**固定节点日历**（预报名/正式报名/网上确认/准考证/初试/查分/国家线/复试）——不依赖院校采集，永不为空；
   - **关注校新公告**进仪表盘消息栏（对应掌上考研 6.7.7 的首页消息通知栏）；
   - **改考雷达**：初试科目字段 diff（exam_subjects 变更）触发提示——数据已结构化，成本最低、价值最高。
5. **四类聚合统计的诚实性**：发布日期缺失时显示「日期未采集」而非压制该条；每类计数卡附覆盖率（如「复试类：覆盖 8 校」），避免把 816 校的空态误读为「无公告」。
